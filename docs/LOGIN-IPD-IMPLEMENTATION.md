# Login และรายการผู้ป่วย IPD แบบดูข้อมูล — เฟสแรก

อัปเดต 18 ตุลาคม 2026 ตามคำขอล่าสุด: ใช้โครงหน้าเดิม เลือกเฉพาะห้องยาที่ login และเลือกวอร์ดในหน้าทำงาน

## การใช้งาน

`/login` ใช้พื้นหลังเดิม กรอบสีขาว และปุ่มเข้าสู่ระบบสีเขียว กรอกบัญชีเดิมและเลือกห้องยาจาก `ms_room` ไม่แสดงตัวเลือกวอร์ด ไม่เปิดสมัครบัญชีใน viewer

หลัง login เข้า `/ipd` คืนเมนูด้านบนเดิม (ห้องยา IPD, Pharmcare, ข้อมูลการจ่าย, Nurse Station, Report, คลังย่อย, คืนยา, Med Reconcile, Setting) พร้อม dropdown เดิมและแถวคำสั่งงาน ปุ่มเปลี่ยนข้อมูลปิดไว้ เมนูหน้าที่ยังไม่เชื่อมใน viewer จะแจ้งสถานะและคงหน้าปัจจุบัน ไม่เรียก API งานเขียน

ใช้สี/โครงเดิม ตัวกรองด้านบน วอร์ดทางซ้าย ผู้ป่วยทางขวา เอาบล็อกหัวข้อ “เลือกหอผู้ป่วย / วอร์ด” และช่องค้นวอร์ดแยกออก กดวอร์ดเพื่อดูผู้ป่วยและเปลี่ยนวอร์ดได้โดยไม่ต้อง login ใหม่

- ห้องยาเฟสนี้รองรับ `001` และ `010` ชื่ออ่านจากฐานข้อมูล
- วอร์ดอ่านจาก `ms_ward` ที่ `wardstatus='Y'` ไม่รวมรหัสว่าง/000/1420 แสดงเฉพาะที่มีผู้ป่วยตรงเงื่อนไข พบ 89 วอร์ดในวันที่ 2026-10-18 สถานะ all (จาก active master 170 วอร์ด) ไม่แสดงวอร์ดจำนวนศูนย์
- จำนวนด้านซ้ายเป็น distinct AN ตามวันที่/สถานะ/AN/มีหรือไม่มีใบสั่งยา ใช้เงื่อนไขร่วมกับตารางผู้ป่วย
- ห้องยาเป็นบริบทงาน ผู้ป่วยกรองตามวอร์ดตาม `ucDispense` ไม่เติมเงื่อนไขห้องยาให้จำนวนเปลี่ยนโดยไม่มี reference
- ค้น AN ตรงตัวจากทุกวอร์ดโดยไม่ติดวอร์ดที่เคยเลือก แสดงเฉพาะวอร์ดที่พบและเลือกวอร์ดแรกของผลลัพธ์ให้อัตโนมัติ ตารางผู้ป่วยแสดงเฉพาะ AN นั้น วันที่และสถานะยังเป็นตัวกรองร่วม ค้นไม่พบจะไม่มีวอร์ดและไม่มีข้อมูลผู้ป่วยค้าง ล้างค้นหาแล้วคืนรายการตามตัวกรองอื่น
- ดับเบิลคลิกเปิดหน้ารายละเอียดผู้ป่วยหลักได้แล้ว ดู [รายละเอียดและผลทดสอบ](IPD-PATIENT-DETAIL.md); Screening ยังไม่ได้เชื่อมใน viewer

## Session และ API

JWT HS256 อายุ 12 ชั่วโมง มีผู้ใช้/ตำแหน่ง/ห้องยา `access=ipd-readonly`, version 2 ไม่ผูกวอร์ดตั้งแต่ login และไม่ส่ง password กลับ Token รุ่นก่อนต้อง login ใหม่

เก็บ token ใน sessionStorage แยกแต่ละแท็บ Refresh คงการ login และห้องยา แต่กลับไปให้เลือกวอร์ดภายในหน้า IPD การออกจากระบบล้าง token และถอดหน้าข้อมูลออก

| Method | Path | การทำงาน |
|---|---|---|
| GET | `/api/login-options` | รายการห้องยา IPD เท่านั้น |
| POST | `/api/login` | username/password/roomCode; ไม่ต้องส่ง wardCode |
| GET | `/api/auth` | ตรวจ token คืนบริบทห้องยา |
| GET | `/api/ipd/wards` | ต้อง login; รายการวอร์ดที่มีข้อมูลตาม orderdate/ptstatus/search/prescription ไม่กรองวอร์ดเดิม |
| GET | `/api/ipd/patients` | ต้อง login; รับ wardCode และตัวกรองเดียวกัน; ตรวจวอร์ดยังเปิดใช้งานก่อนอ่านผู้ป่วย |

ห้องยาใช้ค่าจาก JWT เท่านั้น ไม่รับ override ห้องผ่าน query ส่วนวอร์ดตรวจจากฐานข้อมูลทุกครั้งที่ขอผู้ป่วย การเลือกจากวอร์ดที่เปิดใช้งานไม่ใช่ ACL รายบัญชีใหม่ ไม่สมมติว่า `ms_users.wardcode` คือตารางสิทธิ์

Legacy routers งานเขียน/ฮาร์ดแวร์ไม่ถูก mount; API อื่นใน `/api` และ `/dose` ถูกปฏิเสธ ไม่มีการสร้างใบสั่งยา แก้รายการ สั่งพิมพ์ หรือสแกน

## การอ่านข้อมูล

ใช้ shared pool และ SQL parameters วอร์ด/วันที่/AN การนับวอร์ดไม่ join prescriptionheader ให้เกิดแถวซ้ำ ใช้ EXISTS/NOT EXISTS เฉพาะเมื่อกรองใบสั่งยา การอ่านผู้ป่วยไม่เรียก API นับทุกวอร์ดซ้ำ ใช้ `COUNT(DISTINCT prescriptionno)` ใน query ผู้ป่วย

คงนิยามเดิม: ordercreatedate เท่ากับวันที่เลือก และ Discharged ถึง 23:59:59 ไม่แก้ schema/index หรือข้อมูลธุรกิจ ใช้ JS เรียงรหัสวอร์ดแบบ numeric-aware เพราะฐานข้อมูลไม่รองรับ TRY_CONVERT

ยกเลิก request เก่าเมื่อเปลี่ยนวอร์ด/วัน/สถานะ ไม่แสดงผลผู้ป่วยค้างจากบริบทก่อนหน้า แยก loading/error/empty และมีลองใหม่

## ผลตรวจรอบล่าสุด

- Backend `npm test` ผ่าน 16 กรณี เพิ่มการค้นหาข้ามวอร์ดและตัวกรองร่วม พร้อมตรวจ prescription ผิด/array ถูกปฏิเสธ
- Frontend `npm run build` และ ESLint ไฟล์ที่แก้ผ่าน ไม่มี dependency เพิ่ม
- API ฐานข้อมูลจริง: พบ 89 วอร์ดที่มีข้อมูล ไม่มีจำนวนศูนย์; AN ตัวอย่างที่ผู้ใช้ให้พบวอร์ด 1 เพียงวอร์ดเดียว จำนวน 1 คน และผู้ป่วยตรง AN ทุกแถว; ค้นไม่พบคืนวอร์ดว่าง
- Browser: เริ่มเลือกวอร์ด 3 ได้ 27 ราย แล้วค้น AN ตัวอย่างที่อยู่วอร์ด 1 เหลือวอร์ด 1 เพียงแถวเดียวและผู้ป่วย 1 รายอัตโนมัติ ค้นไม่พบไม่แสดงวอร์ด/ผู้ป่วย ล้างค้นหาคืน 89 วอร์ด ตัวกรองมีใบสั่งยาซ่อนวอร์ดที่ไม่มีผล เปิด dropdown เมนูเดิมได้และปุ่มสร้างยังปิดอยู่

หลักฐาน parity จากรอบก่อนเมื่อไม่กรองใบสั่งยา: เทียบทุก field กับ query เดิมใน `back/services/first.js` วอร์ด 1 วันที่ 2026-10-18 all 24 แถว, วอร์ด 3 วันเดียวกัน admit 24 แถว, วอร์ด 1 วันที่ 2025-06-06 discharged 7 แถว ตรงกัน ไม่ใช่การรับรอง parity ทุกหน้า Windows

ไม่บันทึกชื่อผู้ป่วย HN/AN หรือ token ลงเอกสารหรือภาพประกอบ

## รันในเครื่อง

ที่ `back` ใช้ `npm start` (.env เดิม port 3000) ที่ `front` ใช้ `npm run dev` เปิด `http://localhost:3001/login` การ deploy Nginx/HTTPS เป็นขั้นแยก
