# Report > ใบเบิก > ห้องยา ER

พัฒนา 22 ตุลาคม 2026 เปิดที่ `/ipd/reports/requisition-er` เป็นรายงานดูข้อมูลอย่างเดียวผ่าน session เดิม ไม่บันทึกใบเบิก ไม่ตัดสต็อก ไม่ส่งเครื่องพิมพ์หรือ Robot

## เส้นทาง Windows ที่ใช้จริง

- `frmMain.vb:tsER_IPD_Click` (เมนูชื่อ “ห้องยา ER”) กำหนด StatusBT=`btnER`
- `ctx/Requisition/ucUD.vb:btnOK_Click` เรียก **ER()** โดยตรง ไม่เรียก branch `btnER` ที่อยู่ภายใน IPD() ซึ่งเป็นคนละเงื่อนไข
- ฟอร์ม `ucUD.Designer.vb` และรายงานหลัก `Report/Sendmix/crpRequisitionNew.rpt` เหมือน IPD/D/C
- วันที่เริ่ม/สิ้นสุดเริ่มวันนี้ รพ.ผลิตเอง / ยาฆ่าเชื้อ อยู่ใต้ส่งใบเบิกชั้น 3 มีตัวเลือกส่งใบเบิกชั้น 4 (ค่าเริ่มต้น) / ยาเสพติด และปุ่ม OK
- โหลดเมื่อกด OK เท่านั้น เปลี่ยนเงื่อนไขยกเลิกคำขอ/ซ่อน PDF เก่า สลับห้องยาแล้วเริ่มฟอร์มใหม่

## แหล่งข้อมูลและการรวม

1. MSSQL: `getUsageDrug` จาก prescriptiondetail LEFT JOIN ms_drug โดย departmentcode=`004`, printstatus=`1` ไม่มีตัวกรอง ordertype, sendmachine, unused, void หรือ hold
2. ช่วง IPD ตามนาฬิกา Asia/Bangkok: ก่อน 08:00 ใช้วันก่อนวันที่เริ่ม 08:00 ถึงวันที่สิ้นสุด 07:59:00; ตั้งแต่ 08:00 ใช้วันที่เริ่ม 08:00 ถึงวันถัดจากวันที่สิ้นสุด 07:59:00
3. MySQL ที่เขียนเตรียม: `getDrugOPD` จาก view_pharmacy_opd_drug_item, location=`ER`, inv_type != `9`, Date BETWEEN วันที่เริ่มและสิ้นสุดตามปฏิทิน ไม่ใช้รอบ 08:00 รวม `SUM(CAST(no AS DEC(10,2)))` GROUP BY drugcode ตาม native
4. นำแถว IPD มาก่อนแล้ว append OPD ตาม dt.Merge ไม่มี primary key จึงไม่ตัดซ้ำก่อนแปลงรหัส
5. แปลงรหัสตาม drugname.mc_id โดยเลือกแถวแรก ถ้า Sum_MCID ไม่ว่างใช้ค่านั้น ถ้าว่างหรือไม่พบใช้รหัสเดิม (changordercode)
6. หาแถวแรกใน master ms_drug ของรหัสที่แปลงแล้วและประเภทใบเบิกที่เลือก ใช้ชื่อ orderitemENname, drugform, orderunitcode, Inventorycode, ISNULL(pack,0) จาก master ไม่ใช้ชื่อในใบสั่งยา
7. รวมรหัสเดียวกัน โดย CInt จำนวนแต่ละแถวก่อนบวก (ครึ่งปัดเข้าจำนวนคู่และตรวจ Int32) ไม่บวกรวมทศนิยมก่อนปัด
8. คำนวณ `Ceiling(qty / CInt(pack)) x pack` หลังรวมแต่ละครั้ง ตาม native กรณี pack=0 คง Infinity/NaN ไม่เดาจำนวนใหม่ กรณี pack ว่างบน branch รวมซ้ำเป็นข้อผิดพลาดตาม native
9. เรียงชื่อยา จัดกลุ่ม drugform ตาม Crystal และเลขลำดับต่อเนื่อง เลขใบเบิก ER + ddMMyyyy ของวันพิมพ์ ห้อง “ห้องยา ER”

| ตัวเลือก | sendStore | sendF3F4 |
| --- | --- | --- |
| รพ.ผลิตเอง | 1 | 0 |
| ยาฆ่าเชื้อ | 1 | 2 |
| ส่งใบเบิกชั้น 4 | 1 | 1 |
| ยาเสพติด | 2 | ไม่กรอง |

กรองประเภทหลังแปลงรหัส ไม่กรองประเภทใน SQL ดิบ IPD/OPD เพราะอาจมีรหัส alias ที่ master ของรหัสปลายทางอยู่คนละประเภท

อ่าน MSSQL 3 คำสั่งอิสระพร้อมกันต่อการค้นหา (รายการ, master, mapping) แล้วใช้ Map ในหน่วยความจำแทน DataTable.Select ซ้ำทุกแถว ไม่ทำ SQL รายตัวยา ไม่ cache ยอดใบเบิกข้ามคำขอ

## สถานะ MySQL

- ตามขอบเขตที่ตกลงไว้ เขียนเส้นทาง MySQL ไว้แล้วแต่ **ไม่ได้ทดสอบเชื่อมต่อหรือ query MySQL จริง**
- ค่าเริ่มต้น `REPORT_REQUISITION_ER_OPD_ENABLED=false` หรือไม่กำหนด จะไม่สร้าง MySQL pool และไม่ probe เครือข่าย
- เมื่อต้องการเปิดภายหลัง ตั้งเป็น `true` ใน back/.env และใช้ SERVER/USER/PASSWORD/DATABASE_HOSPITALKKH เดิม แล้วรีสตาร์ต backend มีตัวอย่างชื่อค่าใน back/.env.example ไม่มี secret อยู่ใน frontend
- ระหว่างปิดหรืออ่าน MySQL ไม่ได้ หน้าเว็บและ **PDF ทุกหน้า** แสดงชัดว่าเป็นข้อมูลเฉพาะ IPD และยอด ER ยังไม่ครบ ไม่ตีความ OPD ที่ยังไม่อ่านว่าไม่มีข้อมูล
- เมื่อเปิดและอ่าน OPD สำเร็จ รวมข้อมูลทั้งสองฝั่งและไม่แสดงข้อความเตือนข้อมูลไม่ครบ

## รายการรหัสยาที่ไม่มีใน Unitdose

- ตรวจ master ของรหัสหลังแปลงโดยไม่จำกัดประเภท แถวที่อยู่ประเภทอื่นไม่ถือว่ารหัสหาย
- กรณีไม่มี master แสดง dialog “ระบบแจ้งเตือนรหัสยา OPD ที่ไม่มีใน Unitdose” ตาม frmMessageDrug มีคอลัมน์รหัสยา/ชื่อยาและจำนวนรายการ เก็บแถวซ้ำตาม native
- ปุ่ม PDF รายการยาแทน Print เดิม ใช้ `crpRequisitionDrug.rpt` / `frmPreviewDrugUse.ShowDrug` เป็นแบบอ้างอิง: Drug Report, โลโก้และที่อยู่เดิม, เลขลำดับ/รหัสยา/ชื่อยา, วันที่พิมพ์และเลขหน้า เรียงชื่อยา
- แบบพิมพ์ยาที่ขาดใช้ **US Letter 612 × 792 pt** ขอบ 18 pt ตาม RPT ส่วนใบเบิกหลักใช้ A4 595 × 842 pt
- จัดเตรียม layout/header จาก Crystal ด้วย DataTable จำลองเท่านั้น ไม่มีข้อมูลจริงหรือการเชื่อมฐาน/เครื่องพิมพ์ในไฟล์ assets
- รายการแจ้งเตือนและ PDF สร้างจาก snapshot การค้นหาเดียวกับใบเบิกหลัก ไม่อ่านฐานใหม่เมื่อกดดาวน์โหลด

## พฤติกรรมไม่มีข้อมูลและ PDF หลัก

- ถ้าไม่มีแถวต้นทางทั้ง IPD และ OPD: native แสดง “ไม่พบข้อมูลใบสั่งยา” แล้ว Exit Sub เว็บจึงไม่สร้าง PDF กรณี OPD ยังไม่เปิดมีข้อความข้อมูลไม่ครบกำกับ
- ถ้ามีแถวต้นทาง แต่กรองประเภทแล้วไม่เหลือ: native ยังแสดงแบบใบเบิกว่างโดยไม่แจ้ง “ไม่พบข้อมูล” เว็บทำเช่นเดียวกัน
- PDF หลักใช้ renderer/โลโก้/ช่องลงชื่อร่วมกับ IPD และ D/C คอลัมน์เลขลำดับ, INV_Code, รหัสยา, รายการยา, min Stock (ว่าง), ใช้ไป, Rate/วัน (ว่าง), ขอเบิก, หน่วย
- คงยอดรวมจำนวนแถวและช่องลงชื่อผู้ขอเบิก/ผู้อนุมัติ/ผู้จ่าย/ผู้รับ ไม่มีข้อมูลสต็อกหรืออัตราการใช้ที่สร้างเพิ่ม
- ชื่อยา/รหัสยาวขึ้นบรรทัดและแบ่งหน้าตามความสูง มีหัวกระดาษและเลขหน้า ไม่มีการส่งเครื่องพิมพ์จริง
