# Note บันทึกเภสัชกรแบบอ่าน — ปรับคอลัมน์ 19 ตุลาคม 2026

คงกรอบรายละเอียดผู้ป่วย เมนูหลัก และโครงหน้า Note เดิม: ตารางประวัติด้านบน ช่องอ่านปัญหา/เพิ่มเติมด้านล่าง ไม่มีเพิ่ม แก้ไข บันทึก ลบ พิมพ์ หรือคำสั่งฮาร์ดแวร์

## เทียบกับ Windows

- จุดเปิด: Dispense/ucAddOrderdispense.btnNote_Click → PharmaNote/frmNote
- อ้างอิง frmNote.Designer.vb, Getdata, dgvnote_CellClick และ PharmaNote/Class/clsnote.GetData_note
- แสดง 4 คอลัมน์ตามลำดับเดิม: **วันที่บันทึก, ปัญหา, เพิ่มเติม, บันทึกโดย** ไม่เพิ่ม AN หรือเวลาลงตาราง ซ่อน id ในตาราง แต่ยังแสดงเลขบันทึกเมื่อเลือกตาม txtid เดิม
- วันที่บันทึกมาจาก **Lastupdatedatetime** รูปแบบ **dd-MM-yyyy** ตาม SQL ของ Windows ไม่ใช้ ordercreatedatetime แทน จัดรูปแบบจาก datetime ดิบใน frontend เพื่อไม่รัน SQL FORMAT ต่อแถว
- อ่าน Problem/Note เต็มตามต้นฉบับ เลิก LEFT(...,200) และไม่ใช้ field preview อีก ตารางห่อข้อความในแถวสูงประมาณ 100px ตาม RowTemplate.Height เดิม เลือกแล้วอ่านข้อความเต็มในช่อง readOnly ด้านล่างได้ทันที
- รักษาข้อความไทย ช่องว่าง หลายบรรทัด และค่าศูนย์ตามที่บันทึก Null/ข้อความว่างแสดงว่าง ไม่ใส่ขีดหรือข้อความสมมติ ชื่อผู้บันทึกใช้ ms_users.fullname ตามต้นฉบับ ไม่ fallback username
- ใช้ประวัติ HN ทุก AN รวมครั้งก่อนและบันทึกที่ไม่มี AN เรียง Lastupdatedatetime DESC และใช้ id DESC ตัดสินลำดับเมื่อ timestamp เท่ากัน ไม่มีการรวม/ตัดรายการประวัติ
- ตัดข้อมูลวันที่สร้าง เวลาแก้ไข และผู้บันทึกที่เคยเพิ่มในส่วนรายละเอียดออก คงเลขบันทึกและข้อความสองช่องในโครงเว็บเดิม

Note หน้านี้มาจาก **ms_note** แยกจาก ms_drpdetail.PharmacistNote/PlanNote และแท็บ Note DRP ไม่ดึงข้อความ DRP มาเติมแทน

## API และการโหลด

| API อ่าน | ผลลัพธ์ |
|---|---|
| GET /api/ipd/patients/:an/pharmacist-notes | ประวัติของ HN พร้อม Problem/Note เต็ม วันที่และชื่อผู้บันทึก |
| GET /api/ipd/patients/:an/pharmacist-notes/:noteId | ยังคง API ข้อความเต็มสำหรับอ่านรายบันทึก ตรวจ HN เจ้าของก่อนเสมอ |

หน้า Note ใช้รายการที่โหลดแล้วเปิดรายละเอียดจากแถวในหน่วยความจำ เช่นเดียวกับ dgvnote_CellClick ไม่เรียก API รายละเอียดซ้ำเมื่อเลือกแถว จึงลดคำขอเครือข่ายและรอบ query ขณะเปลี่ยนบันทึก ข้อแลกเปลี่ยนคือคำขอประวัติครั้งแรกส่งข้อความเต็มเช่นเดียวกับ Windows ไม่อ้างว่าเร็วขึ้นทุกชุดประวัติ

ใช้ OUTER APPLY TOP 1 หา author เพื่อไม่ให้รหัส master ซ้ำเพิ่มแถวบันทึก ไม่มี query ต่อรายการ ไม่แก้ schema/index ข้อมูล AN/createdAt ยังอยู่ใน API เดิมเพื่อคงบริบท แต่ไม่แสดงเป็นคอลัมน์เพิ่มใน viewer

ทุกคำขอตรวจ JWT และ current AN/active ward ผ่าน resolver เดิม ใช้ HN ที่ backend resolve ไม่รับ HN override ใช้ parameterized SQL ในรายละเอียด n.HN=@hn AND n.id=@noteId ตรวจรูปแบบ ID และความยาวไม่เกิน 20 ตัวอักษร ปิด POST/PUT/PATCH/DELETE

จำ pnId ใน URL คงบันทึกที่เลือกเมื่อสลับหน้าในกรอบผู้ป่วย เปลี่ยนรายการ/โหลดใหม่แล้วไม่แสดงข้อความเก่าที่ไม่ตรงผลลัพธ์ ถ้า ID ไม่อยู่ในประวัติใหม่ให้เลือกใหม่ ไม่เปิด ID ของผู้อื่น ไม่เลือกรายการอื่นแทนอัตโนมัติ แยกกำลังโหลด/ประวัติว่าง/บันทึกที่ข้อความว่าง/error และมีปุ่มลองใหม่

## MSSQL และ MySQL

เส้นทาง frmNote/clsnote นี้ใช้ **MSSQL เท่านั้น** ไม่มี MySQL ที่ต้องเพิ่มในหน้า Note โค้ด MySQL ในส่วนอื่นยังคงเตรียมไว้ตามเดิมสำหรับเครือข่ายโรงพยาบาล ตาม [DATABASE-CONNECTIVITY.md](DATABASE-CONNECTIVITY.md) ไม่เรียก MySQL เพื่อสร้างหรือเติมบันทึกสมมติ

## ผลตรวจรอบนี้

- Tests backend **144 กรณีผ่าน** รวม auth/current ward/AN/HN override/บันทึกของคนอื่น/ID ผิดรูปแบบ/ปิด mutation/บันทึกว่าง/DB outage เดิม เพิ่มยืนยันรายการส่งข้อความเต็มเกิน 200 ตัวอักษร และทดสอบ 4 header, dd-MM-yyyy, ขอบวัน/leap day, null และข้อความยาวหลายบรรทัดพร้อมช่องว่าง
- Production build และ ESLint ไฟล์ที่แก้ผ่าน
- ฐาน MSSQL จริง: ตัวอย่าง 1 บันทึกเทียบกับ query ของ Windows แล้ว **ข้อความปัญหาและเพิ่มเติมตรงทุกตัวอักษร วันที่ตรง และชื่อผู้บันทึกตรง** จำนวนแถวเท่ากัน API รายละเอียดคืนข้อความตรงรายการ และ HN อื่นเปิด ID เดียวกันไม่ได้
- ตัวอย่างเวลาอ่านรายการ 55ms และ API รายละเอียด 54ms; หน้าใหม่ไม่เรียก API รายละเอียดเมื่อเลือกแถว เป็นเวลาตัวอย่าง ไม่ใช่ SLA
- Browser ข้อมูลสมมติ 3 บันทึก: header ครบ 4 ช่อง ไม่มี AN/เวลาพิเศษ วันที่ถูกต้องทั้งขอบวันและวันที่ว่าง คงประวัติที่มี AN ครั้งก่อนและไม่มี AN
- บันทึกยาว 425 ตัวอักษรมีส่วนท้ายครบทั้งข้อมูลตารางและ textarea แบบ readOnly เปลี่ยนบันทึกว่างล้างข้อความทั้งคู่ และจำนวนคำขอยังเป็น 1 หลังเลือกหลายรายการ
- จำลองฐานขัดข้องแล้วโหลดใหม่: ล้างรายละเอียดเก่า แสดง error ไม่แสดงเป็นไม่มีประวัติ ยอดเป็นขีด กดลองใหม่กลับมาอ่านบันทึกเต็มได้

ภาพหลักฐานใช้ข้อมูลสมมติทั้งหมด การตรวจฐานจริงเป็นตัวอย่างหนึ่งชุด ไม่ใช่การเปิด Windows เทียบภาพสดทุกบันทึก ไม่มีการเขียนข้อมูลธุรกิจหรือ commit/push
