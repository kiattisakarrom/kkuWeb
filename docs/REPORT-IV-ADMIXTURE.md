# Report > IV Admixture

เพิ่ม `/ipd/reports/iv-admixture` ในเมนู Report ของโครง IPD เดิม ใช้ session เดิม
และเปิดดูข้อมูลได้ 4 หน้า:

| หน้า | mode | ตาราง |
| --- | --- | --- |
| แยกหอผู้ป่วย | ward-wait | หอผู้ป่วย, ใบสั่งยา, รายการยา |
| รวมหอผู้ป่วย | total-wait | ใบสั่งยา, รายการยา, รายการรวมใบสั่งยา |
| ส่งหอผู้ป่วยแล้ว | ward-sent | หอผู้ป่วย, ใบสั่งยา |
| ส่งรวมหอผู้ป่วยแล้ว | total-sent | ใบสั่งยา, รายการรวมใบสั่งยา |

## อ้างอิง Windows

เทียบ `ctx/IV/ucIVmain.vb`, `ucReportSendmix.vb`, `ucReportSendmixTotal.vb`,
`ucReportSendmixComp.vb`, `ucReportSendmaxTotalComp.vb` และ Designer แต่ละหน้า,
`ctx/class/clsreportsendmix.vb`, `ctx/IV/frmPreview.vb`, `Dispense/cls/clsAllow.vb`
รวมถึง metadata ของ `Report/Sendmix/crpSendmix.rpt` และ `crpSendmixTotalward.rpt`.

เส้นทางรายงานทั้งสี่ในต้นฉบับใช้ **MSSQL Interface** ไม่พบ MySQL ในเส้นทางนี้
จึงไม่มีการเพิ่มหรือทดสอบ query MySQL.

## เงื่อนไขและคอลัมน์

- เลือก IV Admixture หรือยาเตรียมเฉพาะรายได้ทุกหน้า ค่าเริ่มต้นเป็น IV Admixture.
  แยกด้วยรหัสยาใน `ms_drug_approvetype.approvetypecode='7'` ตาม native.
- ค่าเริ่มต้นช่วงวันปัจจุบัน เวลา 00:00–23:59; กรอง `ordercreatedate`
  ด้วย BETWEEN รวมขอบเขตถึงวินาที 00 ของนาทีสุดท้ายตาม Windows.
- เฉพาะ `sendmix='Y'`; หน้ารอใช้ `IVStatus IS NULL`, หน้าส่งแล้วใช้ `IS NOT NULL`.
  ไม่กรองห้องยา, active ward, Off/Hold หรือจำนวนยามากกว่าศูนย์เพิ่มจากต้นฉบับ.
- หอผู้ป่วยแสดง `[รหัส] ชื่อ`, จำนวนใบสั่งยาไม่ซ้ำ และเรียงรหัสแบบตัวเลข.
- ใบสั่งยา: checkbox สำหรับ PDF, ใบสั่งยา, ประเภทใบสั่งยา, HN, AN,
  ชื่อ - นามสกุล, สถานะ. หน้า `ward-sent` ใช้หัวคอลัมน์ `Ordertype`
  ตาม Designer; สองหน้ารวมมีคอลัมน์หอผู้ป่วยเพิ่ม.
- สถานะ Admit/ผู้ป่วยจำหน่ายพิจารณา `ms_patientadmit.DCdatetime` เหมือนต้นฉบับ.
- รายการยามีเฉพาะสองหน้ารอ: รหัสยา, ชื่อยา, Dose, QTY, รหัสวิธีใช้ (`timecode`),
  คำอธิบายวิธีใช้ (`freetext2`). อ่านทั้งใบสั่งยาโดยไม่บีบวันที่ซ้ำ.
  ชื่อยามี `[OFF]` ก่อน `[HOLD]` ตามข้อมูลบันทึก.
- สองหน้ารวมดับเบิลคลิกใบสั่งยาเพิ่มในรายการรวมทางขวา และกด X เพื่อนำออกได้.
  เพิ่มใบเดิมซ้ำได้ตาม native, ลบทีละแถว และรวมเลขใบสั่งยาซ้ำตอนออก PDF.
  การติ๊กเลือกและรายการรวมเป็น state บนเว็บเท่านั้น.
- ลำดับปุ่มตาม `ucIVmain.Designer`: แยกหอผู้ป่วย, ส่งหอผู้ป่วยแล้ว,
  รวมหอผู้ป่วย, ส่งรวมหอผู้ป่วยแล้ว. กดเปิดปุ่มเดิมซ้ำจะเริ่มฟอร์มใหม่ด้วย.
- ฟอร์มแยกวอร์ดวางวันที่/เวลา/ประเภท/ค้นหา/ยอดวอร์ดไว้ในกล่องซ้าย;
  PrintByOrderNo, ข้อมูลวอร์ดและยอดใบอยู่เหนือใบสั่งยาฝั่งขวา.
- ฟอร์มรวมวอร์ดวางประเภททางซ้ายของวันที่/เวลา/ค้นหา/Print เหนือใบสั่งยา;
  แถบขวามี PrintByOrderNo และยอดรายการรวมอยู่เหนือตาราง.
- ใช้ช่องเลือกชั่วโมงและนาทีแยกแบบ 24 ชั่วโมงตาม Windows.
  ข้อมูล HN/AN/ชื่ออยู่เหนือรายการยา; เฉพาะหน้ารวมรอมีข้อมูลวอร์ดในส่วนนี้ด้วย.
  หน้าส่งรวมแล้วไม่มีช่องข้อมูลวอร์ดหรือรายละเอียดผู้ป่วยเพิ่มจากต้นฉบับ.
  ยอดนับอยู่ด้านบนของแต่ละตารางตาม Designer และคลิกหัวคอลัมน์เรียงข้อมูลได้.

## PDF และการอ่านอย่างเดียว

- GET `/api/reports/iv-admixture/wards`, `/prescriptions`, `/items`
  และ POST `/pdf` อยู่หลัง authentication เดิม.
- รับเฉพาะตัวกรองและ header id ที่เลือก ไม่รับชื่อผู้ป่วย/ข้อมูลยาจาก browser.
  Header id เป็น SHA-256 ของกลุ่มข้อมูลที่อ่าน; resolve ใบสั่งยา/HN/AN/วอร์ดบน server.
  ถ้าเลือกไม่ตรงกับข้อมูลปัจจุบัน หรือใบสั่งยามีบริบทผู้ป่วยต่างกัน ตอบ 409 ให้ค้นหาใหม่.
- PDF เลือกได้ไม่เกิน 200 แถวใบสั่งยาต่อครั้ง; เลขใบสั่งยาซ้ำจะอ่านครั้งเดียว.
  ใช้พารามิเตอร์ `@rx0...` โดยตรงเพื่อใช้ index ได้ ไม่ต่อเลขใบสั่งยาลง SQL.
- ปุ่ม Print/PrintByOrderNo ดาวน์โหลด A4 PDF พร้อมฟอนต์ไทยฝังในไฟล์.
  ใช้หัวรายงาน IV Admixture Report, ข้อมูลโรงพยาบาล, กลุ่ม AN/ใบสั่งยา,
  ชื่อผู้ป่วย, หอผู้ป่วย, สถานะ, ชื่อยา/ขนาดยา, วิธีใช้, freetext3 และผู้บันทึกเดิม.
  หัวกระดาษพร้อมโลโก้โรงพยาบาลมาจาก ReportHeader ของ RPT เดิมแยกสองแบบ:
  `crpSendmix.rpt` สำหรับหน้าแยกวอร์ด และ `crpSendmixTotalward.rpt` สำหรับหน้ารวม.
  ใช้ระยะขอบและพิกัดส่วนรายงานของแต่ละไฟล์; หัวกรอบ/ผู้บันทึก/เวลา/คอลัมน์ซ้ำทุกหน้า,
  กลุ่มผู้ป่วยและยาใช้เส้นแบ่งตามต้นฉบับ ไม่มีตารางสีแบบรุ่นแรก.
  ข้อความไทยฝัง Sarabun และตัดบรรทัดสำหรับข้อความยาวเพื่อไม่ให้ข้อมูลหาย.
  สร้าง static assets ครั้งเดียวจาก Crystal ด้วยตารางว่าง ไม่มีข้อมูลคนไข้;
  web server ไม่ต้องติดตั้ง Windows/Crystal runtime. ดู `tools/export-iv-templates.ps1`.
- ตาม preview เดิม PDF อ่านรายการ sendmix ทั้งใบที่เลือก รวม IVStatus ทุกค่า/ทุกวัน
  ภายในประเภท IV หรือยาเตรียมเฉพาะรายที่เลือก แล้วตรวจบริบทผู้ป่วยอีกครั้ง.
- ใช้ชื่อ generic สำหรับ IV ถ้ามี, ชื่อ withoutVolname สำหรับ diluent ตาม native;
  ผู้บันทึกมาจาก `pharmacyitemdesc` ไม่ใช่ผู้ใช้ที่กำลังล็อกอิน.
- อ่าน Hold/diluent พร้อมยาแบบ batch ไม่ query ต่อรายการ. เงื่อนไข Hold คงตาม native:
  EndDate ถึงวันปัจจุบันแล้ว และเวลาประเทศไทยเกิน 08:00 น. (เทียบ HHmm).
- IV รวมส่วนผสมตาม groupdrug ภายในใบสั่งยา/ผู้ป่วย/วอร์ดเดียวกัน เก็บทุกส่วนผสม.
  แก้บั๊ก native ที่อาจใช้ group ข้ามใบ หรือทำส่วนผสมลำดับที่สามขึ้นไปหาย.
  ยาเตรียมเฉพาะรายไม่รวม groupdrug.
- PDF สร้างในหน่วยความจำ, attachment และ no-store จาก middleware เดิม.
  **ไม่มีการ UPDATE IVStatus, INSERT/DELETE, ส่ง PDF ไป share, OCS/Robot หรือพิมพ์จริง.**
- เปลี่ยนตัวกรองจะซ่อนผลเดิมและยกเลิกการอ่าน/ส่งออกที่ยังค้าง.

## ผลตรวจ 21 ตุลาคม 2026

- Backend regression ผ่าน 216/216 tests รวม IV ใหม่ 13 tests; frontend targeted lint
  และ production build ผ่าน.
- MSSQL จริง: IV หน้ารอพบ 17 วอร์ด, หน้ารวมรอ 38–40 ใบระหว่างทดสอบ;
  หน้าส่งแล้ว 60 วอร์ด/รวม 658 ใบ. ยาเตรียมเฉพาะรายรอ 4 วอร์ด/6 ใบ,
  ส่งแล้ว 5 วอร์ด/7 ใบ. จำนวนเปลี่ยนได้ตามข้อมูลระหว่างวัน.
- Local API ดาวน์โหลด PDF สำเร็จ 200 application/pdf ทั้ง 4 mode x 2 ประเภท.
  ตัวอย่างเลือกครั้งละ 2 ใบใช้ประมาณ 0.3–2.2 วินาที ไม่เก็บ PDF คนไข้ลงดิสก์.
- Browser ตรวจตำแหน่งตัวกรองทั้ง 4 โหมด, ติ๊กใบสั่งยาเปิดรายการยาและปุ่ม PDF,
  เพิ่มใบเดิมซ้ำ 2 แถวแล้วลบเหลือ 1, เปลี่ยนประเภทล้างรายการรวม,
  เปิดหน้าเดิมซ้ำกลับค่าเริ่มต้น, เปลี่ยนวันที่ด้วยแป้นพิมพ์ซ่อนผลเก่า,
  คอลัมน์เฉพาะแต่ละโหมด และหน้าส่งแล้วไม่มีตารางรายการยา.
- PDF ข้อมูลสมมติ: ตรวจภาพ A4 ภาษาไทยและรายงานหลายหน้า;
  สองแบบใหม่มีโลโก้จาก RPT; 100 รายการ/9 หน้า พร้อมบันทึกยาวต่อข้ามหน้า
  สกัดข้อความได้ครบ ไม่มีรายการซ้ำหรืออักษรนอกขอบกระดาษ และมีหัวตารางทุกหน้า.
- รอบนี้ทำในเครื่อง local ยังไม่ได้ deploy เซิร์ฟเวอร์โรงพยาบาล.
