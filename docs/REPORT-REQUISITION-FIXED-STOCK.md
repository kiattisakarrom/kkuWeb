# Report > ใบเบิก > ห้องยาเสพติดและ Fixed Stock

พัฒนา 23 ตุลาคม 2026 เปิดที่ `/ipd/reports/requisition-fixed-stock` ผ่าน session เดิม เป็นรายงานดูข้อมูล ไม่สร้างใบเบิก ไม่ตัดสต็อก ไม่ส่งเครื่องพิมพ์หรือ Robot

## ชื่อและเส้นทาง Windows

- ชื่อเมนูใช้ “ห้องยาเสพติดและ Fixed Stock” ตาม `frmMain.Designer.vb:tsRAddict.Text` วางหลังห้องเตรียมยาอาคารเภสัชกรรมตามลำดับ Windows
- ชื่อห้องใน PDF ใช้ “ห้องจ่ายยาเสพติด และ Fixed Stock” ตาม `ucUD.IPD()` ซึ่งต่างจากข้อความเมนูอยู่แล้ว เว็บแยก label เมนูกับ Room รายงานเพื่อคงทั้งสองจุด
- `frmMain.vb:tsRAddict_Click` กำหนด StatusBT=`btnAddict` แล้ว `ucUD.btnOK_Click` เรียก **IPD()** ไม่ใช่รายงานยาเสพติดกลุ่ม Warehouse ตัวอื่น
- ใช้ ucUD.Designer และ `Report/Sendmix/crpRequisitionNew.rpt` เดิม
- ฟอร์มวันที่เริ่ม/สิ้นสุดเริ่มวันนี้ มีส่งใบเบิกชั้น 3 (รพ.ผลิตเอง / ยาฆ่าเชื้อ), ส่งใบเบิกชั้น 4 (ค่าเริ่มต้น) และยาเสพติด ครบ 4 ตัวเลือก ไม่บังคับเลือกยาเสพติดเพียงอย่างเดียว
- กด OK จึงค้นหา เปลี่ยนเงื่อนไขซ่อน PDF เก่าและยกเลิกคำขอ ไม่โหลดอัตโนมัติ สลับห้องยาเริ่มฟอร์มใหม่

## แหล่งข้อมูลและเงื่อนไข

หน้านี้ใช้ **MSSQL เท่านั้น** ตาม getUsageDrug ใน native ไม่มีส่วน MySQL จึงไม่เพิ่มการเชื่อมต่อหรือค่า MySQL ใหม่

- `prescriptiondetail pt LEFT JOIN ms_drug mdr ON orderitemcode`
- departmentcode=`018` และ `(sendmachine='Y' OR printstatus='1')` และ ordertype IN (`0`,`3`)
- ไม่เปลี่ยนเป็นห้อง 001/ห้องจาก session ไม่เพิ่มเงื่อนไข unused, void, hold, IVStatus หรือกรองเฉพาะ printstatus
- ช่วงเวลาตามนาฬิกา Asia/Bangkok: ก่อน 08:00 ใช้วันก่อนวันที่เริ่ม 08:00 ถึงวันที่สิ้นสุด 07:59:00; ตั้งแต่ 08:00 ใช้วันที่เริ่ม 08:00 ถึงวันถัดจากวันที่สิ้นสุด 07:59:00 คงวินาที :00 ตาม native

| ตัวเลือก | sendStore | sendF3F4 |
| --- | --- | --- |
| รพ.ผลิตเอง | 1 | 0 |
| ยาฆ่าเชื้อ | 1 | 2 |
| ส่งใบเบิกชั้น 4 | 1 | 1 |
| ยาเสพติด | 2 | ไม่กรอง |

- รวม `SUM(CAST(pt.orderqty AS DEC(10,2)))` GROUP BY รหัส/ชื่อยาในรายการเดิม และ drugform, orderunitcode, Inventorycode, pack ของ master เรียงชื่อรายการยาตาม SQL
- ไม่เปลี่ยนชื่อยาเป็นชื่อ master และไม่ลดแถว master ซ้ำก่อน join เพราะจะเปลี่ยนผลจาก Windows
- จำนวนใช้ไปใช้ VB CInt ปัดครึ่งเข้าจำนวนคู่พร้อมตรวจ Int32 ก่อนคำนวณ `Ceiling(CInt(qty)/CInt(pack)) x pack` ถ้า pack ว่างใช้จำนวนเต็ม ถ้า pack=0 คง Infinity/NaN ตาม native ไม่เดาจำนวนหรือแก้ฐาน
- drugform ว่างเป็น “อื่นๆ” จัดกลุ่มตาม Crystal เลขลำดับต่อเนื่อง ยอดรวมเป็นจำนวนแถว
- เลขใบเบิก **AD** + ddMMyyyy ของวันพิมพ์ปัจจุบัน ไม่ใช้ FS หรือวันที่ค้นหา
- อ่าน query เดียวพร้อม bound parameters ต่อการค้นหา ไม่โหลด master/drugname ทั้งตารางที่ฟังก์ชันรายงานไม่ได้ใช้

## คอลัมน์และ PDF

- A4 แนวตั้ง 595 × 842 pt ขอบ 18 pt ใช้ renderer/assets ร่วมกับใบเบิกเดิมตาม RPT เดียวกัน
- โลโก้/ชื่อโรงพยาบาล/ที่อยู่หน้าแรก กล่องเลขใบเบิก/ชื่อห้องเต็ม/วันที่พิมพ์และหัวคอลัมน์ซ้ำทุกหน้า
- คอลัมน์เลขลำดับ, INV_Code, รหัสยา, รายการยา, min Stock (ว่าง), ใช้ไป, Rate/วัน (ว่าง), ขอเบิก, หน่วย ตาม RPT ซึ่งไม่มีชื่อหัวเลขลำดับและรหัสยาแยก
- ขอเบิกจาก Pack หน่วยจาก master.orderunitcode ไม่สร้างข้อมูลสต็อกหรืออัตราการใช้เพิ่ม
- ช่องลงชื่อผู้ขอเบิก/ผู้อนุมัติ/ผู้จ่าย/ผู้รับเดิม มีเลขหน้าและยอดรวมจำนวนแถว ฝังฟอนต์ไทย วัดข้อความก่อนแบ่งหน้า
- ไม่พบข้อมูลแจ้ง “ระบบแจ้งเตือน / ไม่พบข้อมูล” แล้วแสดงแบบพิมพ์ว่างต่อ ตาม IPD() ของ Windows
- ดาวน์โหลด `Fixed-Stock-Requisition-Report.pdf` จาก Blob เดียวกับตัวอย่าง ไม่อ่านฐานซ้ำ และ runtime ไม่ต้องติดตั้ง Crystal

## API และผลตรวจ

- POST `/api/reports/requisition-fixed-stock/pdf` รับเฉพาะ `{from,to,kind}` ต้องมี session/no-store ใช้ bound parameters ไม่รับ rows/override department จาก client คืน X-Report-Rows/X-Report-Pages รวมกรณีไม่มีข้อมูล rows=0 / PDF 1 หน้า
- Backend regression **278/278 ผ่าน** รวม Fixed Stock 5 tests; targeted frontend ESLint และ production build ผ่าน
- เทียบคำสั่งกับ SQL StringBuilder ของ getUsageDrug จาก native โดย `tools/check-requisition-ipd-native.cjs` โหมด `fixed-stock` วันที่ 2026-10-21 กำหนดเวลาค้นหาเป็นหลัง 08:00 ผลทั้ง 4 ประเภทตรงกัน โดยไม่มีรายการห้องยา 018 ทั้งคำสั่ง native และเว็บในรอบนี้
- ตรวจเพิ่มวันที่ 2026-10-23 ด้วยนาฬิกาปัจจุบัน พบชั้น 4 จำนวน **2 แถว** และอีก 3 ประเภทไม่มีรายการ ผล SQL ของ native และเว็บตรงกันครบทุกฟิลด์ทั้ง 4 ประเภท จึงยืนยันได้ทั้งกรณีที่มีแถวจริงและกรณีว่าง (ยอดจริงอาจเปลี่ยนตามเวลา/ข้อมูล)
- ทดสอบแถวที่มีข้อมูล ชื่อ/หน่วย/แพ็ก สูตร CInt เลข AD และการรวมยอดด้วยข้อมูลจำลอง
- PDF จำลอง 6 แถว 1 หน้า ตรวจชื่อห้องเต็มว่าไม่ทับวันที่หรือหัวคอลัมน์ พร้อมโลโก้และช่องลงชื่อแล้ว
- PDF จำลอง 120 แถว 5 หน้า ชื่อครบ 120 และปลายชื่อยาวครบ 4 จุด เลข AD ทุกหน้า ไม่มีอักขระนอกกระดาษ ตรวจภาพหน้าแรก/กลาง/ท้ายแล้ว
- Browser เปิดจากเมนูตามชื่อ/ลำดับ Windows ได้ ค่าเริ่มต้นวันนี้/ชั้น 4 ถูกต้อง แสดง PDF ข้อมูลจริง 2 รายการพร้อมชื่อห้องเต็ม เลข AD23102026 และช่องลงชื่อ
- Browser เปลี่ยนไปประเภทยาเสพติดในวันที่ตรวจ ขึ้น “ไม่พบข้อมูล” ปิดแล้วแสดงแบบพิมพ์ว่าง 1 หน้าได้ตาม native เปลี่ยนกลับชั้น 4 โหลดข้อมูลจริงใหม่ได้ และการเปลี่ยนประเภทซ่อนผล/ปิดดาวน์โหลดเดิมจนกด OK
- ระหว่าง QA พบข้อความกำลังโหลดซึ่งอยู่ใน normal flow ทำให้ fit-page canvas ล้น viewport เกิด scrollbar เปิด/ปิดและ ResizeObserver สั่งเรนเดอร์ซ้ำ แก้ตัวแสดง PDF ร่วมให้ข้อความสถานะ/error เป็น overlay และกันพื้นที่ scrollbar คงที่ ตรวจภาพโหมดพอดีหน้าแสดงค้างได้แล้ว ไฟล์ PDF และสูตรข้อมูลไม่เปลี่ยน
- ทดสอบสลับพอดีความกว้าง → พอดีหน้าแล้ว canvas เรนเดอร์เสร็จและแสดงค้างได้ ตรวจ lint/build หลังแก้ตัวแสดง PDF ผ่าน
