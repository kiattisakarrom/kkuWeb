# Medical Reconcile แบบอ่าน — 18 ตุลาคม 2026

อัปเดต 20 ต.ค.: เปลี่ยนเป็น 4 คอลัมน์ประวัติ/11 คอลัมน์ยา และ mapping หน่วยจ่าย/ผู้สั่งตาม native แล้ว ดู [สถานะล่าสุด](IPD-READONLY-STATUS-2026-10-20.md); ไม่เรียก MySQL จริงตามคำขอ ข้อความบรรยายคอลัมน์ชุดเก่าด้านล่างเป็นประวัติการพัฒนา

เปิดผ่านปุ่ม Medical Reconcile ในรายละเอียดผู้ป่วย คงกรอบข้อมูลผู้ป่วย เมนูด้านบน LAB/DRP และปุ่มกลับเดิม ส่วนล่างเป็นประวัติทางซ้ายและรายการยาทางขวา เลือกได้ทั้งแถวหรือปุ่มวันที่ มีตัวกรองแหล่งข้อมูล และปุ่มโหลดใหม่ ไม่มี transfer/copy/สร้างรายการ/แก้ไข/Off/Hold/พิมพ์

## ข้อมูลที่แสดง

| แหล่ง | Source ในโปรแกรมเดิม | รายการยาที่เปิด |
|---|---|---|
| OPD | `clsms_medicationreconcile.GetdataDrugitem_opd` → MySQL `view_pharmacy_opd_drug_item` | ประวัติวันที่/VN ของ HN เดียวกัน เปิดยาทั้ง VN ตาม `showdatadetailopd` ไม่ตัดเฉพาะวันที่ใน VN |
| IPD · ยากลับบ้าน Unitdose | `GetDatadrugitemipd` → `prescriptionheader` + `prescriptiondetail` | `ordertype = 1`, ไม่รวมรหัส `DC`, เลือก AN และวันปฏิทินบน header; รวม AN ปัจจุบันเมื่อมีข้อมูลตาม native |
| MRC · AN ครั้งอื่น | `GetDataMedreconcile` → `ms_medicationrecconcile` | HN เดียวกันและ AN ต่างจากปัจจุบัน เปิดทั้ง AN ตาม `showdatadetailipd` |

แสดงรหัส/ชื่อยา ขนาด หน่วย วิธีใช้ ความถี่ เวลา จำนวนจ่าย ข้อความและหมายเหตุ แพทย์ ใบยา วันเริ่ม/สิ้นสุด และ Off/Hold ที่บันทึก ไม่ตีความว่าเป็นยาที่ผู้ป่วยกำลังใช้อยู่ ส่วน OPD แสดงเฉพาะข้อมูลที่ source มี ไม่เติมราคา/สถานะ/วันสิ้นสุดสมมติ

วันที่ IPD ใช้ช่วงเที่ยงคืนถึงก่อนวันถัดไป ไม่ใช่รอบ 08:00 ของ Medication Profile/รายการสั่งยา ตามการเลือกวันที่ใน `ucMedReconcile` ยา OPD และ MRC เปิดทั้ง VN/AN ตาม native แม้มีหลายวัน จำนวนยา OPD รวมทั้ง VN ให้ตรงกับ detail

MRC เดินผลลัพธ์เรียง Off/priority/date แล้วเพิ่มวันที่เมื่อ AN เปลี่ยน ตัดคู่ AN/วันที่ซ้ำตาม `showorderdetail` เดิม จึงอาจมี AN เดิมหลายวันที่เมื่อข้อมูลสลับกัน การเลือกแต่ละวันที่ของ AN นั้นยังเปิดชุดยาทั้ง AN ตาม native ไม่ตัดตามวันโดยพลการ

## API และการจำกัดข้อมูล

ใต้ `/api/ipd/patients/:an`:

- `GET /reconcile/:source` คืนประวัติ; source รับเฉพาะ OPD/IPD/MRC
- `GET /reconcile/:source/items?historyId=...&historyDate=YYYY-MM-DD` คืนยาในประวัติ; 404 ถ้าไม่พบภายใต้ HN/แหล่ง/วันที่ที่เลือก

ตรวจ JWT และ current AN/active ward ผ่าน resolver เดิมทุกครั้ง ใช้ HN จาก backend ไม่รับ HN ฝั่ง client ทุก SQL ใช้ parameters และตรวจ HN ใน detail ด้วย จึงไม่เปิดประวัติคนอื่นด้วยเลข AN/VN เพียงอย่างเดียว MRC ห้าม AN ปัจจุบัน ส่วน header/detail Unitdose ตรวจ HN และ AN ให้ตรงกันด้วย

ใช้ pool เดิมของ MSSQL และ pool MySQL แยก (สูงสุด 3 connections, connect timeout 8 วินาที, query timeout 10 วินาที) จาก environment `*_HOSPITALKKH` ที่มีอยู่ ไม่มีการเพิ่ม dependency หรือบันทึก credential ใน source

ผู้ใช้ยืนยันว่า MySQL ทุกส่วนต้องใช้เครือข่ายภายในโรงพยาบาล ให้เตรียมโค้ดไว้ก่อนตาม [ข้อกำหนดการเชื่อมต่อฐานข้อมูล](DATABASE-CONNECTIVITY.md) โดยเครื่อง backend ต้องเข้าถึงเครือข่ายนั้น โค้ด OPD เปิดใช้อยู่แล้ว เมื่อเชื่อมต่อได้ให้กดโหลดประวัติใหม่เพื่ออ่านข้อมูลจริง

แยก request ทั้ง 3 แหล่ง ทำให้ประวัติ SQL ใช้งานได้ขณะ OPD กำลังโหลดหรือเชื่อมต่อไม่ได้ แยก error กับข้อมูลว่างและมีปุ่มลองใหม่ เก็บตัวกรอง/แหล่ง/รหัส/วันที่ใน URL (`mrFilter`, `mrSource`, `mrId`, `mrDate`) เพื่อ refresh และสลับหน้าแล้วกลับมาได้ เปลี่ยนประวัติหรือตัวกรองล้างยารายการเก่าทันที ยกเลิก request เก่า ไม่แสดง response ผิดรายการ กลับหน้ารายการผู้ป่วยล้างเฉพาะ key ของหน้ารายละเอียดและคงตัวกรองเดิม

## ผลตรวจและข้อจำกัดปัจจุบัน

- Tests รวม 37 กรณีผ่าน เพิ่ม source/selection validation, auth, HN override, ผิดวอร์ด/ผิดผู้ป่วย/ผิดวันที่, mutation, กรณี OPD ล่มแต่ IPD ยังอ่านได้ และการจัดกลุ่มวันที่ MRC แบบ native เมื่อ AN สลับกัน
- Frontend build และ ESLint ไฟล์ที่แก้ผ่าน
- ฐานข้อมูลจริง: ตัวอย่าง Unitdose 1 ประวัติ/1 รายการ ชุด itemindex ตรง SQL เดิม การส่งวันที่ผิดหรือ HN อื่นคืน null; อ่าน list+detail+ตรวจ parity รอบแรกประมาณ 431 ms แต่รอบตรวจซ้ำชุดเดียวกันใช้รวมประมาณ 20.5 วินาที และพบ MSSQL timeout เป็นช่วง ๆ จึงยังไม่อ้างว่าเวลาเข้าถึงฐานจริงคงที่ ตัวเลขนี้รวมหลาย query ในสคริปต์ตรวจ ไม่ใช่เวลา endpoint เดียวหรือ SLA
- แยกวัดซ้ำเฉพาะ query ปกติของ Unitdose: list 123 ms และ detail 52 ms โดยไม่มีการเพิ่ม index หรือแก้ฐานข้อมูล
- MRC ตัวอย่างอีกผู้ป่วยมี 1 ประวัติ/1 รายการ ชุด meditemindex ตรง SQL เดิมและตัด AN ปัจจุบันถูกต้อง
- Browser จริง: เปิด Unitdose ได้ 1 รายการ, refresh คงประวัติ, เปลี่ยน source แล้วล้างยาเก่า และยังอ่าน Unitdose ได้ขณะ OPD error
- Browser ข้อมูลสมมติ: เลือก OPD 2 รายการ, Unitdose AN เก่า 2 รายการ, MRC 1 รายการ และกรอง source ได้ ภาพตัวอย่างไม่มีข้อมูลผู้ป่วยจริง
- **OPD เตรียมโค้ดพร้อมแล้ว รอทดสอบข้อมูลจริงภายในเครือข่ายโรงพยาบาล** ตามที่ผู้ใช้แจ้งเรื่อง MySQL ทุกส่วน รอบก่อนพบ `ETIMEDOUT` จึงยังไม่ยืนยัน schema/ผลลัพธ์จากฐานจริง และไม่ถือ timeout จากนอกเครือข่ายเป็นหลักฐานว่า query มีบัค การทดสอบ OPD ที่ไม่ว่างบนหน้าจอรอบนี้ใช้ fixture เท่านั้น

ไม่เขียนข้อมูลธุรกิจ ไม่เปลี่ยน schema/index และไม่ได้ commit/push
