# Screening — ยา Screen และส่งจัดยาแล้ว (Continue จัดแล้ว)

อัปเดต 19 ตุลาคม 2026: แก้รายชื่อหอและยอดฝั่งซ้ายให้รวมทุกห้องยาตรง Windows แล้ว ใบสั่งยาและรายการยายังกรองตามห้องยาที่เลือก

ตรวจวันที่ 18 ตุลาคม 2026 จาก Windows `Screenning/ucScreenning.vb` กิ่ง `btnContinueFinished` ใน `Showward` (~324), `ShowPrescriptionHeader` (~559), `ShowPrescriptiondetail` (~1046), `clsPrescription.getgroupWard/getPresHeader` และ `clspackagemaster.getForgenorder`

## การใช้งาน

เมนู ห้องยา IPD → Screening → **ยา Screen และส่งจัดยาแล้ว** ใช้ `mode=continue-finished` ในกรอบเดิม วอร์ดซ้าย → ใบบน → ยาล่าง ใช้ตัวเลือกห้องจริงทุกห้องจาก `ms_room` ร่วมกับ Stat/Continue รอจัด เริ่มห้อง login แต่เลือกห้องอื่นใน Screening ได้โดยไม่เปลี่ยน session ห้องหลัก

เลือกวันที่/วอร์ด/ใบ ค้น AN/HN/เลขใบแบบตรงกันข้ามทุกวอร์ดและทุกห้องในยอดฝั่งซ้าย ส่วนใบ/ยากรองห้องที่เลือก แสดงเฉพาะวอร์ดที่มีรายการ เมื่อเปลี่ยนห้อง/วัน/โหมด/ค้นหา ล้างใบและยาเดิมพร้อมยกเลิกคำขอเก่า แสดง loading/error/empty ต่างกันและลองใหม่ได้

แสดงยาที่บันทึก ขนาด จำนวน หน่วย เวลา วิธีใช้ ข้อความ หมายเหตุ แพทย์/ผู้บันทึก สถานะ Off/Hold/พิมพ์/ส่งจัด/เครื่อง รวมวัน Screen ในหัวใบและเวลา `genorderdatetime` ในยา คงค่าศูนย์และข้อมูลว่างต่างกัน ใช้สี Off แดง/Hold เหลืองเดิม

ดับเบิลคลิกใบเปิด AN ของใบนั้นผ่านวอร์ดปัจจุบันที่ backend ตรวจ แล้วกลับคงห้อง/โหมด/วัน/รอบ/คำค้น/วอร์ดของใบ/เลขใบเดิม ปุ่ม Screen/ส่งจัด/พิมพ์/ส่งเครื่อง/ยกเลิกยังปิด และ server ไม่เปิด mutation/hardware route

## เงื่อนไขและความต่างที่ระบุไว้

- `genorderdatetime IS NOT NULL` และ `ISNULL(frequencycode,'') NOT IN ('S','E','STAT')` รวมความถี่ null/ว่างตาม native; `ordertype <> '1'` แยกกลับบ้าน
- **ไม่มี priority exclusion `%C%`** ของ Stat จัดแล้ว และไม่บังคับ priority เป็น C ไม่ตัด Off/Hold ออก เพราะต้นฉบับคอมเมนต์เงื่อนไข void ไว้
- วอร์ดนับ distinct เลขใบและไม่บังคับ active ward เช่น native ส่วนหัวใบต้องเป็น active ward รายละเอียดยาตรวจห้อง/วอร์ด/non-home/active ward และ HN/AN จากหัวใบฝั่ง server เพิ่มเพื่อไม่ปนข้ามบริบท
- ห้องยาตรวจ master ฝั่ง server และใช้ parameter กรอง `fromlocationname=roomname+'['+roomcode+']'` ไม่รับชื่อห้องหรือ HN override จาก client
- **ห้องยาตาม Windows:** กิ่ง `Showward.btnContinueFinished` ไม่กรอง fromlocationname เว็บจึงรวมทุกห้องเฉพาะยอดวอร์ดของโหมดนี้ รวมรายการที่ห้องว่าง/ไม่อยู่ใน master ส่วนหัวใบและยายังคงเงื่อนไขห้องอย่างเคร่งครัด หอที่มีแต่ใบของห้องอื่นจะแสดงฝั่งซ้ายได้ และเมื่อเลือกจะแจ้งว่าไม่มีใบในห้องที่เลือก ไม่แจ้งให้โหลดซ้ำเสมือนเป็นข้อผิดพลาด มีข้อความอธิบายสั้นใต้ตัวเลือกห้อง การเปลี่ยนนี้ไม่ขยายตัวกรองของ Stat หรือ Continue รอจัด
- รอบยาเหมือน [Stat](IPD-SCREENING-STAT.md): 08:00 ถึงวันถัดไป 07:59:00 สำหรับยอดวอร์ด และ 07:59:59 สำหรับใบ/ยา ก่อน 08:00 กรุงเทพฯ ถอยวันที่เลือกหนึ่งวันรวมการดูย้อนหลัง ใช้ workdate จาก backend คงรอบระหว่างเลือก
- `Screen แล้ว` แปลจาก gen ไม่ว่างตามระบบเดิม ไม่รับรองว่าบริหารยาแก่ผู้ป่วยแล้ว แสดงแถว prescription/ปริมาณ/ข้อความที่บันทึกจริงตามขอบเขตเฟสก่อน ไม่รันส่วนแตกซองหรือสร้างรายการสำหรับเครื่อง/พิมพ์ จึงไม่อ้างว่าจำนวนแถว/จำนวนต่อซองตรงกับตาราง native หลังแตกซอง
- เส้นทางนี้ใช้ **MSSQL** ตาม Windows ไม่มี MySQL เพิ่ม ส่วน MySQL ของหน้าอื่นยังเตรียมไว้ตาม [ข้อกำหนดการเชื่อมต่อ](DATABASE-CONNECTIVITY.md)

ใช้ GET `/api/ipd/screening/options`, `/wards`, `/prescriptions`, `/prescriptions/:prescriptionno` เดิม เพิ่ม enum ทั้ง backend/frontend และ patient return ผ่าน config โหมดร่วม คง pool ร่วม/SQL parameter/EXISTS/OUTER APPLY ไม่มี query หรือ HTTP ต่อแถวยาจาก browser
