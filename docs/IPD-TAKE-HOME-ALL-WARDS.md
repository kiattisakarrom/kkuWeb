# ยากลับบ้านรอจัด/จัดแล้ว — แสดงทุกหอเหมือน Windows

แก้ 18 ตุลาคม 2026 ตามข้อทักท้วงเรื่องหอผู้ป่วยฝั่งซ้ายแสดงไม่ครบ

## สาเหตุและพฤติกรรมล่าสุด

Windows `ucScreenTakeHome.Showward` ไม่กรองห้องยา ทั้งรอจัดและจัดแล้วรวมทุกหอที่มีรายการตามสถานะ/ประเภท/ความถี่/ช่วงวันที่ แต่เว็บเฟสแรกเพิ่มตัวกรองห้องแล้วเริ่มจากห้อง login จึงแสดงน้อยกว่าต้นฉบับ

แก้ทั้ง `take-home-wait` และ `take-home-finished` ให้:

- ค่าเริ่มต้น **ทุกห้องยา** (`roomCode=all`) ทั้ง UI และ API แสดงทุกหอที่มีรายการ รวมรายการจากห้องอื่นและ fromlocationname ที่ไม่ผูก master/เป็น null ไม่เอาหอว่างทั้ง master มาเติม
- กดเมนูรอจัดหรือจัดแล้ว รวมการกดเมนูเดิมซ้ำ ล้างห้องเฉพาะ/คำค้น/วอร์ด/ใบ/รอบที่ค้าง และเริ่มทุกห้องยา โดยคงวันที่ปฏิทินที่เลือก
- ยังเลือกห้องเฉพาะได้เพื่อกรอง เมื่อกรองห้องหรือค้นหา มีปุ่ม **แสดงทุกหอที่มีรายการ** เพื่อกลับทุกห้อง/ล้างคำค้น
- ทุกห้องไม่ใส่ fromlocationname filter ที่ยอด/หัวใบ/ยา ส่วนห้องเฉพาะยังตรวจ master และเทียบชื่อพร้อมรหัสห้องแบบ exact ทุกระดับ ยาแต่ละแถวในโหมดทุกห้อง lookup ที่เก็บจากห้องต้นทางของแถวนั้น
- เลือกหอแล้วยังแสดงใบของหอนั้น และเลือกใบเพื่ออ่านยาด้วยขอบเขตวอร์ด/ใบ/ตัวตนที่ server ตรวจ กลับจากผู้ป่วยคง room=all หรือห้องเฉพาะที่เลือก ไม่เปลี่ยนห้อง login ของ IPD
- กติกา type1/gen null หรือไม่ null/non-Stat/Off/Hold/active ward และช่วงเวลาสามระดับเหมือนเฟสก่อน ไม่มีคำสั่งเขียน จัดยา พิมพ์ หรือส่งเครื่องเพิ่ม

ห้อง all ใช้ได้เฉพาะ Robot และ Take-home สองโหมดนี้ Stat/Continue/Screen All ยังคงเงื่อนไขห้องเดิม

## ผลตรวจล่าสุด

- **119 backend tests ผ่าน**, frontend production build/ESLint ผ่าน ครอบคลุม default all/explicit all/ห้องเฉพาะ, หอจากห้องอื่นและแหล่งส่งไม่ผูก master, หัวใบ/ยา, reset ตัวกรองเก่า, ตัวตนและบริบทผู้ป่วย, โหมดอื่นไม่รับ all และ login room ไม่เปลี่ยน
- เทียบ SQL native ที่ **ไม่ใส่เงื่อนไขห้องยา** กับชุดยอดรายหอจริงครบทั้งสองสถานะและสองรอบ: วันที่ 18 ต.ค. 2026 รอบหลัง 08:00 รอจัด 0 หอ, จัดแล้ว **36 หอ**; รอบก่อน 08:00 รอจัด **1 หอ**, จัดแล้ว **44 หอ** ทุกชุดตรงกัน ไม่บันทึกชื่อ/รหัสผู้ป่วยลงผลตรวจ
- กรองห้อง001ในรอบเดียวกัน: จัดแล้วเหลือ **6 หอ / 13 หอ** ตามลำดับ และรอจัด 0 หอทั้งสองรอบ อธิบายหอที่หายไปในเว็บเฟสก่อน
- สุ่มเทียบ fields หัวใบกับ native หลังตัดตัวกรองห้องผ่าน: รอบรอจัดที่มีข้อมูล 1 หอ/1 แถว; จัดแล้ว 3 หอ/9 แถวในรอบหลัง 08:00 และ 3 หอ/8 แถวในรอบก่อน 08:00
- API จริงหลัง restart: ไม่ส่งห้องและส่ง all ได้ทุกหอ กรองห้อง001ยังได้เฉพาะห้องนั้น ทั้งสองหน้า 200; รอจัดรอบก่อน 08:00 อ่านหัวใบ/ยาในหอจากห้องอื่นได้ 200; session IPD ยังเป็นห้อง001
- Browser ข้อมูลสมมติ: ค่าเริ่มต้นเห็น 3 หอจากห้อง001/002/แหล่งส่งไม่ผูกห้อง, กรองห้อง001เหลือหอเดียว, กดแสดงทุกหอกลับครบ, กดจัดแล้วจากห้อง/คำค้นค้างกลับทุกห้อง, เลือกยาในห้องอื่นและกลับจากผู้ป่วยคง all/ใบ ผ่าน เว็บจริงแสดงจัดแล้วครบ **36 หอ**
- ภาพ `ipd-home-wait-all-wards-demo.png` และ `ipd-home-finished-all-wards-demo.png` ใช้ข้อมูลสมมติทั้งหมด

ผลเฟสก่อนในเอกสารรอจัด/จัดแล้วที่ระบุห้อง001หรือ002เป็นหลักฐานของการกรองห้องเฉพาะ ส่วนค่าเริ่มต้นล่าสุดให้ยึดเอกสารนี้ ยังต้องตรวจรับวัน/ห้องอื่นและโหลดหลายผู้ใช้เพิ่มเติม
