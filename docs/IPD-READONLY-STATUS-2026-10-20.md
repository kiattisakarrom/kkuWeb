# สถานะ IPD viewer หลังแก้รายการตรวจ 6 จุด — 20 ตุลาคม 2026

เอกสารนี้บันทึกผลของคำขอแก้เฉพาะกลุ่ม “ต้องแก้จริง” จากการตรวจโค้ดล่าสุด ไม่ใช้ checkbox เก่าเป็นหลักฐานว่ายังไม่ได้เขียนหน้า ไม่รวมหน้าใบสั่งยาที่มีภาพใน Screening การสร้าง/แก้ไขข้อมูล และฮาร์ดแวร์

คำขอถัดมาเพิ่ม [ป๊อปอัปเมื่อเปิดโปรไฟล์](IPD-PROFILE-ENTRY-ALERTS.md) แล้ว: ประวัติ ADR/แพ้ยา, Note และรายการ OR ตามเกณฑ์ native แบบอ่านอย่างเดียว แยกจากงาน 6 จุดเดิม

เพิ่ม [[ER] Quick Order](IPD-ER-QUICK-ORDER.md) ตาม ucScreenAll ใน quick mode แล้ว: 3 ตารางตาม Windows เลือกห้อง/หลายหอ/ตัวกรองได้ เปิดใบยาและกลับคงบริบท ปุ่มจัดยาและพิมพ์ปิดใช้งาน ชุดทดสอบรวมล่าสุด 178 กรณีผ่าน รายละเอียดและข้อจำกัดอยู่ในเอกสารหน้านี้

เพิ่ม [Check Out](IPD-CHECKOUT.md) ตาม ucCheckout/ucCheckoutdetail แล้ว: หอ/หัวใบ/รายละเอียด JVM/จัดมือ/Stat แบบอ่านอย่างเดียว ไม่ทำเปิดใบแสกน ตรวจ MSSQL และ API จริงผ่าน ชุดทดสอบรวมล่าสุด 185 กรณีผ่าน

## แก้โค้ดครบทั้ง 6 จุด

| ส่วน | ผลที่แก้ |
|---|---|
| รายการสั่งยา | หัวใบ 6 คอลัมน์ แยกวันที่/เวลา/สถานะ; รายการยา 61 คอลัมน์ตาม ucMedicationHistory; L/M/V/C/T และช่องเลือกเป็น checkbox disabled; แสดงค่าขนาด/จำนวน/Off/ใบอนุมัติ/สี/สถานะตามกติกาของหน้านี้ และเพิ่มตารางคู่ยา Drug Interaction ที่บันทึกไว้ |
| Medical Reconcile | ประวัติซ้าย 4 คอลัมน์และตารางยา 11 คอลัมน์ตาม dgvOrderdetail; ไม่ใช้ตารางยา 29 คอลัมน์กลางหรือสร้างตะกร้า transfer; แสดงชื่อและผู้สั่งตาม OPD/IPD/MRC แต่ละกิ่ง |
| Medication Profile | 60 คอลัมน์ตาม Designer แสดง/ซ่อนและลำดับตรงต้นฉบับ; เอาคอลัมน์เสริม/High Alert/Protocol ที่ native ซ่อนออกจากตาราง คงข้อมูล Protocol ใน API และกรอบด้านบนเมื่อเลือกยา; เติม doctorcode/statusevent/displaycolour ที่ native มองเห็น |
| LAB Result ด้านขวา | 8 คอลัมน์ตาม dgvlabresults, ไอคอน H/L จากทรัพยากรเดิม ไม่มีการคำนวณ flag จากผล; ค่าว่างไม่กลายเป็นขีด รักษา 0 และข้อความตัวเลข; วันที่แสดง dd/MM/yyyy HH:mm:ss ไม่เลื่อน SQL calendar day |
| Note DRP ด้านขวา | 29 คอลัมน์ตาม dgvDRPdetail; Process ใช้รหัส, มี No/Occur/รหัส Cause/Action/Acceptance/Outcome/ผู้เกี่ยวข้อง/ผู้รายงานครบ; ชื่อยา EN และ fallback ชื่อผู้ใช้เฉพาะ fullname เป็น NULL ตาม native |
| รายการผู้ป่วย IPD | ซ่อน Discharge Date เหลือ 6 คอลัมน์ตาม native; คงข้อมูลวันจำหน่ายใน response และการเปิดผู้ป่วย/ค้นหา/วอร์ดเดิม |

โครงเมนู กรอบผู้ป่วย และส่วนซ้าย/ขวาเดิมยังอยู่ ข้อความยาวเก็บเต็ม อ่านได้ผ่านช่องเลื่อน/tooltip; จำกัดความสูงในช่องเพื่อไม่ทำให้ทุกแถวขยายตามข้อความยาว ตารางใบยาและคู่ยาเลื่อนดูได้ในจอเล็ก

## Mapping และความต่างที่ต้องรู้

- รายการสั่งยาใช้ชื่อยาที่บันทึก ไม่แทนด้วยชื่อ master; Off เติม [OFF]/จำนวนจ่าย 0/ปิด L เพื่อแสดง แต่ไม่เปลี่ยนค่าที่บันทึก Hold ไม่ใช้กติกาเดียวกับ Medication Profile โดยอัตโนมัติ
- วิธีใช้/ความถี่/เวลาในคอลัมน์รหัสใช้ instructioncode/frequencycode/timecode; ช่อง pricetype ของหน้าใบยาใช้ calprice และช่องใบสั่งยาใน detail เว้นว่างตาม Rows.Add แม้ API มีเลขใบ
- จำนวนวันของหน้าใบยาเดินจาก enddate เมื่อมี ตาม showorderdetail; จึงอาจมีค่าติดลบเมื่อ enddate อยู่ในอนาคต ไม่ตีความหรือเปลี่ยนวันสิ้นสุดยา
- สถานะ detail ของใบยาใช้ meditemindex กับรอบปัจจุบันของ checkscreenfinish แยกจากรอบวันที่เลือก; ก่อน 08:00 ต้นฉบับเริ่มที่ 01:00 ของวันก่อน ไม่ปรับเป็น 08:00 เงียบ ๆ lookup อ่านรวมใน query แทนยิงต่อแถว
- **คงการแก้ key ผิดของต้นฉบับ:** checkscreen ของรายการหัวใบส่ง prescriptionno ไปเทียบ meditemindex เว็บใช้ prescriptionno จริงของใบและ AN/HN/active ward/genorderdatetime ที่บันทึก สถานะนี้เป็นสถานะจัดยาของใบ ไม่ใช่หลักฐานการให้ยา
- ใบอนุมัติซ้ำใช้ AllowCd ล่าสุด และ master ซ้ำเลือกอย่างแน่นอนเพื่อไม่เพิ่มแถวโดย join; ไม่จำลองการสุ่มแถวแรกของ SQL ที่ไม่มี ORDER BY
- คู่ยาอ่านเฉพาะ ms_drugintereactionhistory ของ AN/HN ที่ resolve ฝั่ง server และ prescriptionno IS NULL ตาม native; ไม่มีการตรวจคู่ยาใหม่ ไม่มี insert/update หรือ mark screen
- Reconcile หน่วยจ่าย OPD/MRC ใช้ drugname.mc_id -> Sum_MCID ที่เป็นยาที่เปิดใช้และไม่ใช่เวชภัณฑ์ -> ms_drug/ms_orderunit ตาม changordercode; batch ทีละไม่เกิน 500 รหัส ไม่ query ต่อแถว และคงรหัส/ชื่อยาที่บันทึก
- Reconcile แสดงผู้สั่ง fullname เฉพาะ Unitdose/IPD; OPD/MRC ช่องนี้ว่าง และ firstdosestatus เป็นช่องว่างทั้งสามกิ่งตาม Rows.Add แม้ฐานอาจมีค่า ช่อง varymealstatus ยังคงแสดงค่าตาม source/default N ที่ต้นฉบับกำหนด
- ไม่ทำ side effects ของ Windows ระหว่างเปิดหน้า: ไม่ auto-Off, reset first dose, เลื่อนวัน, แก้ใบอนุมัติ หรือส่งเครื่อง

## การตรวจ

- อ่าน Designer ของ Windows โดยตรงเทียบหัว/ลำดับ/visible ของ 5 ตาราง: ใบยา 61, Medication Profile 60, Reconcile 11, LAB summary 8, DRP summary 29 ตรงครบ
- Unit/API tests เพิ่มการเทียบคอลัมน์ ค่าว่าง/0/Off/Hold/ชื่อที่บันทึก/สูตรจำนวนวัน ขอบก่อน-หลัง 08:00, SQL parameter bindings, batch lookup และสิทธิ์ API คู่ยา; ใช้ DB stub ไม่เปิด MySQL
- MSSQL จริง: หัวใบ 1 ใบ/ยา 5 รายการ อ่าน approval/status batch ผ่าน; คู่ยาอ่านผ่านกรณีว่าง; Medication Profile 4 แถว; DRP summary 7 แถว; LAB summary อ่านผ่านกรณีว่าง; MRC 1 แถวพร้อม lookup หน่วยจ่ายผ่าน ไม่บันทึกข้อมูลผู้ป่วยลง log/ภาพ
- Browser ใช้ component/hook จริงและ adapter ข้อมูลสมมติทั้งหมด ตรวจตารางและการเลือกใบ/ประวัติ สลับ IPD/OPD/MRC, ช่อง checkbox disabled, ข้อความยาว/0/ว่าง และ error ล้างข้อมูลเก่า แยกจาก empty
- ผลตรวจ MSSQL เป็นตัวอย่าง ไม่รับรองทุกระเบียน และไม่ได้เปิด Windows เทียบภาพสดทุกสถานะ
- ชุดทดสอบทั้งหมด **165 กรณีผ่าน**, production build และ ESLint เฉพาะไฟล์ที่แก้ผ่าน เริ่ม API ในเครื่องด้วยโค้ดใหม่แล้ว ไม่ commit/push และลบ fixture/probe ชั่วคราวหลังตรวจ

## ทำแล้ว รอตรวจข้อมูลจริง แยกจากงานเขียนโค้ด

- Medical Reconcile OPD และ LAB ย้อนหลัง: โค้ดพร้อม รอตรวจ MySQL ในเครือข่ายโรงพยาบาล **ไม่ได้เชื่อมต่อหรือทดสอบ MySQL จริงในงานรอบนี้ตามคำขอผู้ใช้**
- Drug Profile: การแก้แสดงผลรอบก่อนพร้อมแล้ว การเทียบตัวอย่างมีรายการจริงยังเป็นงานตรวจรับแยก ไม่ได้กลับมาแก้หน้านี้
- IHOS DUE และ DUE Online: โค้ดเดิมพร้อม รอตรวจ response จริงจากโรงพยาบาล ไม่ได้เรียก hospital API ในรอบนี้

ส่วนที่เสร็จเดิมยังคงเดิม: Login/การเลือกห้องยาและวอร์ด/ค้น AN/นำทางผู้ป่วย, ข้อมูลด้านบน, ME/DRP, Note, ประวัติแพ้ยา และ Screening 8 โหมด ไม่เปิดงานเหล่านี้ซ้ำจาก checkbox ค้างในบันทึกเก่า
