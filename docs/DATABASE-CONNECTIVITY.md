# การใช้ฐานข้อมูลผ่านเครือข่ายภายใน

ผู้ใช้แจ้งวันที่ 18 ตุลาคม 2026 ว่าส่วนที่ใช้ MySQL ทุกส่วนต้องเข้าถึงผ่านเครือข่ายภายในโรงพยาบาล ให้เตรียมโค้ดไว้ก่อนและตรวจข้อมูลจริงเมื่ออยู่ในเครือข่ายที่เข้าถึงได้ ข้อกำหนดนี้ใช้กับงาน MySQL ในเฟสถัดไปด้วย

เครื่องที่ต้องเข้าถึง MySQL คือ **เครื่องที่รัน backend** เพราะเว็บเรียก API แล้ว backend เป็นผู้เชื่อมฐานข้อมูล ไม่ใช่ browser เชื่อม MySQL โดยตรง

- คง query, การตรวจผู้ป่วย, API และหน้าจอที่เตรียมไว้ ไม่ถอดแหล่งข้อมูลเพราะทดสอบจากนอกเครือข่ายแล้ว timeout
- อ่านค่าการเชื่อมต่อจาก environment เดิม: `SERVER_HOSPITALKKH`, `USER_HOSPITALKKH`, `PASSWORD_HOSPITALKKH`, `DATABASE_HOSPITALKKH` ไม่ใส่รหัสผ่านใน source
- เมื่อเข้าถึงไม่ได้ ให้แสดงเชื่อมต่อข้อมูลไม่ได้และลองใหม่ได้ แยกจากผลลัพธ์ว่าไม่มีข้อมูล ไม่ใช้ข้อมูลสมมติแทนข้อมูลจริงในการใช้งาน
- โหลดแหล่งข้อมูลแยกกันเพื่อให้ส่วนที่เชื่อมต่อได้ยังใช้งานต่อได้
- การยืนยันผล MySQL จริงให้รอทดสอบภายในเครือข่าย ไม่ถือ timeout ที่พบจากภายนอกเป็นหลักฐานว่า query ผิด และไม่อ้างว่า query ผ่านกับฐานจริงก่อนทดสอบ

## Medical Reconcile ที่เตรียมแล้ว

OPD มี query อ่าน `view_pharmacy_opd_drug_item`, API ประวัติและรายการยา, การตรวจ HN ฝั่ง backend, การเลือกวันที่/VN บนหน้าจอ และการลองใหม่พร้อมแล้ว ใช้ connection pool ซึ่งเริ่มเชื่อมเมื่อเรียก OPD และสามารถลองเชื่อมใหม่ในคำขอถัดไปได้

เมื่อ backend เข้าเครือข่ายภายในและค่าการเชื่อมต่อถูกต้อง เปิด Medical Reconcile แล้วกด **โหลดประวัติใหม่** เพื่อเรียกฐานจริง ไม่ต้องเปิดฟังก์ชัน OPD เพิ่ม หากเปลี่ยนค่า environment ให้ restart backend เพื่อโหลดค่าใหม่

รอบตรวจภายในยังต้องยืนยันชื่อ field ของ view กับฐานที่ใช้งานจริง เทียบวันที่/VN/ชุดยากับ Windows และตรวจทั้งกรณีมีประวัติ/ไม่มีประวัติ/สลับผู้ป่วย การเตรียมโค้ดเสร็จแล้วแยกจากการรับรองผลข้อมูลจริง

## LAB ย้อนหลังที่เตรียมแล้ว

ปุ่ม LAB ในรายละเอียดผู้ป่วยอ่าน `view_lab_result` ผ่าน MySQL ด้วย environment เดียวกัน มี API รายการวันและผลรายวัน การเลือกช่วงวัน/วันที่ตรวจ ข้อความผลตรวจและลองใหม่พร้อมแล้ว แยกจาก LAB Result สรุป 7 วันทางขวาที่อ่าน MSSQL ไม่ใช้ผลสรุปมาแทนข้อมูล MySQL เมื่อเข้าไม่ถึง

เมื่อ backend เข้าถึงเครือข่ายภายใน เปิด **LAB → ค้นหา LAB** หรือ **โหลด LAB ใหม่** เพื่ออ่านต้นทาง ไม่มีขั้นตอนเปิดฟังก์ชันหรือเปลี่ยนไปใช้ข้อมูลจริงเพิ่มเติม รอตรวจ schema/การแปลง tis620 และเทียบผลตาม [รายละเอียด LAB](IPD-LAB-HISTORY.md) กับ Windows ก่อนรับรอง parity
