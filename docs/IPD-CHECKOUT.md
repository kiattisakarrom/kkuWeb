# Check Out viewer — 20 ตุลาคม 2026

เพิ่ม `/ipd/checkout` และทางเข้าจากเมนูห้องยา IPD, Screening และ [ER] Quick Order อ้างอิง `frmMain.CheckOutToolStripMenuItem_Click`, `Checkout/ucCheckout.vb`, `Checkout/ucCheckoutdetail.vb`, Designer และ `Checkout/cls/clscheckout*.vb` ในซอร์ส Windows ที่ผู้ใช้ให้มา

## หน้าหลัก

- ฟอร์ม AN / วันที่ / แสดงทั้งหมด / รอ Check Out / Check Out แล้ว / ค้นหา ค่าเริ่มต้นรอ Check Out เปลี่ยนตัวกรองแล้วกดค้นหาตาม Windows
- สองส่วนประมาณ 28/72: ตารางหอ 3 คอลัมน์ (ช่องเลือก, หอผู้ป่วย, จำนวน) และตารางใบ 7 คอลัมน์ (ช่องเลือก, ใบสั่งยา, ordertype, HN, AN, ชื่อ - นามสกุล, สถานะ) ซ่อน Admit Date/รหัสหอ/หอ/ห้อง/เตียงตาม Designer
- **ไม่มีเช็คบ็อกซ์ “เปิดใบแสกน”** ตามคำขอ ไม่สร้างช่องรับสแกนหรือเปิดภาพใบสั่งยาอัตโนมัติ
- โหลดเฉพาะหอที่มีรายการ จาก `packagemaster` ของทุกห้องยา รวม inactive wards ตาม native หน้านี้ไม่มีตัวกรองห้องยาใน Windows จึงไม่เพิ่มเงื่อนไขห้องยาที่ล็อกอินซึ่งจะทำให้รายการหาย
- หอต้องมี prescription ที่ `genorderdatetime IS NOT NULL`; ซอง `ordertype <> '1'`; ค้นหา AN แบบตรงค่า สถานะตัวกรองใช้ `checkoutdatetime IS NULL / IS NOT NULL`
- รอบทำงานก่อน 08:00 เป็นวันที่เลือกวันก่อน 08:00 ถึงวันที่เลือก 07:59:59 หลัง 08:00 เป็นวันที่เลือก 08:00 ถึงวันถัดไป 07:59:59 เซิร์ฟเวอร์ resolve รอบและเว็บคงรอบนั้นขณะเลือกหอ/ดูรายละเอียด ไม่คาดเดาจากเวลาเครื่องผู้ใช้
- จำนวนฝั่งหอคือ `COUNT(DISTINCT prescriptionno)` แต่หัวใบแยกกลุ่มตาม HN/AN/ชื่อ/เตียง/ordertype/checkoutuserid ตาม native ใบเดียวที่มีหลายสถานะจึงมีหลายแถวได้ และจำนวนหัวใบอาจมากกว่ายอดหอ
- เริ่มต้นยังไม่เลือกหอ คลิกหอเพื่อดูใบ ไม่ query จำนวนแยกทีละหอ และไม่โหลดรายชื่อหอซ้ำเมื่อคลิกหอครั้งแรก

## รายละเอียด

- ดับเบิลคลิกหัวใบหรือ Enter บนเลขใบเพื่อดูรายละเอียด Checkout ไม่พาไป Medication Profile แทน กลับแล้วคงวัน/AN/สถานะ/หอ/รอบเดิม
- จัดกลุ่มฟอร์มผู้ป่วยตามต้นฉบับ: HN/AN/วันเกิด, ชื่อ/เพศ, หอ/ห้อง/เตียง, แพทย์/อายุ, แพ้ยา, สิทธิ/น้ำหนัก/ส่วนสูง/BSA/GFR/วินิจฉัย/Protocol และผู้ Screen / ผู้จัด LED/HAD
- ข้อมูลผู้ป่วยอ่านจาก admit + patient + bedmove ปัจจุบัน (`status=0`) ไม่บังคับ active ward แบบหน้าหลัก IPD; ADR อ่านตาม HN ของใบที่ resolve ฝั่งเซิร์ฟเวอร์ และมีแจ้งเตือนเมื่อพบประวัติตาม `showadr`
- **ช่องที่ Windows ไม่ได้เติมข้อมูลที่ entry นี้ยังคงว่าง/ค่าเริ่มต้นตาม source:** แพทย์, วินิจฉัยโรค, Protocol ว่าง; น้ำหนัก/ส่วนสูง/GFR เป็น 0 และ BSA เป็น .00 ไม่ได้นำค่าจากหน้า Profile อื่นมาปะปน และไม่ใช่การอ่านผลตรวจหรือคำนวณ clinical ใหม่
- แท็บ `ยาจัดจากเครือง JVM`: คอลัมน์ประเภท / ชื่อยา แล้วเพิ่มคอลัมน์มื้อจาก `frequencyTime`, `frequencyTimedesc`, `takedate` พร้อมจำนวนรายการยา รักษากลุ่ม timestamp ตาม native แม้หัววันที่ที่แสดงเหมือนกัน ไม่รวมคนละรายการ/ความถี่/เวลา/วันที่เข้าด้วยกัน
- แท็บยาจัดมือและยา STAT: รูปภาพ / ประเภท / ชื่อยา / จำนวนรวม แสดงเลขแถวเป็น row header ตาม native
- JVM ใช้ `locationcode='1'`; จัดมือใช้ `locationcode<>'1'` และความถี่ไม่ใช่ S/E/STAT หรือ NULL; Stat ใช้ location ที่ไม่ใช่ 1 และ S/E/STAT
- ตาม `getgrouppackagemaster` ขนาดยาในข้อความใช้ `varymeal`; ขนาดที่วางบนรูปมื้อใช้ `dosage` ของซองจริง ข้อความท้ายใช้ freetext2 เมื่อเลขใบยาวอย่างน้อย 11 ตัว มิฉะนั้น freetext1 รักษาชื่อยาที่บันทึก/0/ค่าว่าง
- จัดมือข้ามเฉพาะจำนวน 0 ที่เป็นยาฉีดและ prescription `sendmix='N'`; ไม่ตัด Stat หรือ Off/Hold ออก สีเทาเมื่อ printstatus=0 สีเขียวเมื่อเลือกชุดที่ Checkout แล้วและ printstatus ไม่ใช่ 0 ตามต้นฉบับ
- รูปยาใช้ JPG ก่อน PNG ตามขนาด .25/.5/อื่น ๆ แล้วภาพสำรอง พร้อม Off/Hold และเครื่องหมายจาก `checkoutdatetime` ที่บันทึกไว้ กดรูปเพื่อขยายอ่านได้ ไม่มีการยืนยันตรวจซองหรือเขียนสถานะ
- รูปจากโฟลเดอร์ `picDrug` ในซอร์สที่ได้รับ 7 ไฟล์เก็บใน `back/assets/checkout-drugs` เพิ่ม `CHECKOUT_DRUG_IMAGE_DIR` ใน `.env.example` สำหรับชี้ชุดภาพเต็มของโรงพยาบาล รูปที่ไม่มีใช้ `no_picture.png` ตาม native; พาธ D: ใน config Windows เดิมไม่มีบนเครื่องนี้
- ตั้ง `back/.env` และ `.env.example` เตรียมไว้เป็น `D:\Program_H\H_Khonkaen\Interface\Interface\picDrug` ตามคำขอแล้ว ถ้าโฟลเดอร์นี้ไม่มีหรืออ่านไม่ได้จะกลับไปใช้ชุดภาพในโปรเจกต์โดยอัตโนมัติ ถ้าโฟลเดอร์อ่านได้แต่ไม่มีรูปยาหรือ `no_picture.png` จะใช้ภาพสำรองจากโปรเจกต์ โดยส่งภาพเดิมเพียงครั้งเดียวต่อ response คงคีย์ IHOS และค่าอื่นใน `.env` เดิมไว้
- ส่งภาพแต่ละไฟล์เพียงครั้งเดียวใน response แล้วอ้างอิงจากหลายยา/มื้อ ลดการส่ง Base64 ซ้ำ และอ่านรายละเอียด/มื้อ/ผู้ป่วย/บุคลากร/ADR แบบ batch ไม่มี SQL ต่อช่องตาราง

## ความต่างที่แก้ปัญหาต้นฉบับโดยตั้งใจ

- หน้ารายการใช้รอบ 08:00 แต่ native double-click อ่านรายละเอียดใน **วันปฏิทินที่เลือก 00:00–23:59:59** เว็บคงเกณฑ์นี้ ไม่ขยายวันเงียบ ๆ จึงอาจพบหัวใบในรอบแต่รายละเอียดวันนั้นว่างได้ แสดงวัน/สถานะที่ใช้ในข้อความว่าง
- ใน native การ double-click เลือก `packagemaster` แถวแรกที่ไม่มี ORDER BY แล้วใช้ checkoutuserid ของแถวนั้น เว็บ resolve หัวใบที่คลิกจริงด้วยรหัส SHA-256 ของกลุ่ม ไม่สลับไปสถานะ/ผู้ป่วยอื่น ไม่ใส่ชื่อ/HN ลงรหัสใน URL และไม่เชื่อ HN/AN/สถานะจาก client
- ต้นฉบับเลือกแท็บเริ่มต้นตรวจ JVM ซ้ำในกิ่ง Stat ทำให้ใบที่มีเฉพาะ Stat ไปเริ่มแท็บว่าง เว็บเริ่มแท็บที่มีรายการจริงตามลำดับ JVM → จัดมือ → Stat
- ผู้ Screen/ผู้จัดที่มีหลายแถวใช้ลำดับวันที่และรหัสอย่างแน่นอน แทน TOP 1 แบบไม่กำหนดลำดับของ native; แยก error จาก empty และล้างข้อมูลเก่าทุกครั้งที่เปลี่ยน request
