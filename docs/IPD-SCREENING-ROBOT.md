# Screening — ยารอส่ง Robot (ดูข้อมูล)

ตรวจ 18 ตุลาคม 2026 จาก Windows `Screenning/ucScreenSendRobot.vb` (`Showward` ~55, `ShowPrescriptionHeader` ~442), Designer ของหน้าเดียวกัน และ `Screenning/cls/clspackagemaster.vb.vb` (`getgroupWard`, `getPresHeader`)

## โครงหน้าและขอบเขตปัจจุบัน

ห้องยา IPD → Screening → **ยารอส่ง Robot** ใช้ `mode=robot-wait` มี **สองตารางตาม Windows** เท่านั้น: หอผู้ป่วยทางซ้าย → ใบสั่งยาทางขวาเต็มพื้นที่ ไม่มีตารางยาด้านล่าง และไม่เรียก API รายการยารายใบเมื่อเลือกแถวในโหมด Robot

เมื่อเข้าโหมด เริ่ม **ทุกห้องยา** แสดงทุกหอที่มีคิวตามรอบวันที่ รวมข้อมูลจากห้องอื่นและแหล่งส่งที่ไม่ได้ตรงกับ master ห้องยา การเลือกห้องเฉพาะยังทำได้เพื่อกรองตามคำขอก่อนหน้า แต่เป็นตัวกรองเสริม ไม่จำกัดตามห้อง login โดยอัตโนมัติ โหมด Stat/Continue ยังคงเริ่มด้วยห้อง login ตามเดิมและไม่รับค่า all

นับ distinct ใบต่อหอ เฉพาะหอที่มีรายการ ค้น AN/HN/เลขใบแบบตรงกัน เลือกหอเพื่อดูใบ เลือกแถวใบเป็น selection โดยไม่มีตารางที่สาม ดับเบิลคลิก/ปุ่มดูรายละเอียดผู้ป่วยเปิด AN ที่ backend ตรวจและวอร์ดปัจจุบัน กลับคงโหมด/ห้อง/วัน/รอบ/คำค้น/หอของใบ/เลขใบ

เปลี่ยนห้อง/วัน/โหมด/ค้นหาแล้วล้าง selection เก่า ยกเลิกคำขอและตรวจ request key แยก loading/error/empty และลองใหม่ ปุ่มส่งตามใบ/ส่งตามวอร์ด/ยกเลิกปิด ไม่มีการส่งเครื่องจริง สร้าง OCS file หรือเปลี่ยนสถานะใดเมื่อเปิดดู

## แหล่งและเงื่อนไขตามต้นฉบับ

อ่าน **MSSQL packagemaster** ไม่ใช่ prescription หรือ packagemasterctx โดยใช้ locationcode='1', dosage>0, orderqty>0, instructioncode NOT IN ('PAY'), printstatus=0, voiddatetime/holddatetime/genOCSdatetime IS NULL เหมือน Windows

- instructioncode null ถูก SQL NOT IN ตัดออกตามต้นฉบับ ไม่ใช้ ISNULL ให้กลายเป็นคิว
- ไม่เพิ่มเงื่อนไข Stat/non-Stat, non-home, priority C, genorderdatetime หรือ active ward ของหน้าคิวอื่น
- ทุกห้องยาไม่กรอง fromlocationname ไม่ต้องตรง master จึงเห็นทุกหอที่มีคิวเหมือน Windows หากผู้ใช้เลือกห้องเฉพาะจึงกรอง fromlocationname=roomname+'['+roomcode+']' จาก master จริง ไม่เดาห้องจาก locationcode
- รอบเริ่ม 08:00 ก่อน 08:00 กรุงเทพฯ ถอยวันที่เลือกหนึ่งวันรวมวันที่ย้อนหลัง วอร์ดถึงวันถัดไป **07:59:00**, หัวใบถึง **07:59:59** คงความต่าง native และส่ง workdate จาก backend ให้ตารางลูกเพื่อไม่เปลี่ยนรอบกลางทาง
- หัวใบ group ตามวันสร้าง/เลขใบ/HN/AN/ชื่อ/วอร์ด/เตียง/ordertype/วัน genOCS ไม่แยกใบซ้ำตามห้อง ถ้าใบเดียวมีหลาย fromlocationname ช่องห้องแสดง “หลายห้องยา” ไม่ใช้ชื่อห้องเดียวแทนทั้งหมด
- แสดงสถานะ “รอส่ง Robot” ตามความหมาย genOCS ว่าง แทนข้อความ native “รอ Screen” ในหน้าคิว Robot ไม่ใช้ยืนยันการจ่าย/บริหารยา

API GET `/api/ipd/screening/wards` และ `/prescriptions` ต้องมี JWT; Robot เมื่อไม่ส่ง roomCode ใช้ all หรือส่ง all ชัดเจนได้ การเลือกห้องจริงยัง validate master ส่วน context ห้อง login ไม่เปลี่ยน ใช้ SQL parameters/pool ร่วม ไม่เปิด send/mutation route

API อ่านรายละเอียด packagemaster ที่เตรียมก่อนหน้ายังคงเป็น readonly และตรวจตัวตน/ขอบเขต แต่ **หน้า Robot สองตารางไม่เรียกใช้** ไม่มี query/HTTP ต่อแถวยา ส่วนนี้ไม่มี MySQL ตามต้นฉบับ

## ผลตรวจล่าสุดหลังแก้ตามข้อทักท้วง

- ตรวจ Designer/source ยืนยัน Windows มี DataGridView เพียงสองตัว และ Showward ไม่มีตัวกรองห้อง
- **100/100 backend tests ผ่าน**, frontend build/ESLint ผ่าน ครอบคลุม Robot default all, ห้องเฉพาะ, ล้างตัวกรองเก่าเมื่อกด Robot ซ้ำ, หอจากห้องอื่น/แหล่งส่งที่ไม่ผูก master, headers, auth, ไม่เปลี่ยนห้อง login และ all ใช้ไม่ได้กับ Stat/Continue รวมชุดทดสอบเดิมเรื่องคิว/สิทธิ์/writes/errors
- ฐานจริงรอบที่ตรวจ: **ทุกห้อง 2 หอ / 3 ใบ** ยอดรายหอและหัวใบทั้ง 3 แถวตรงกับ SQL Windows ที่ไม่กรองห้อง ส่วนกรองห้อง 001 เหลือ **1 หอ** อธิบายเหตุที่เวอร์ชันก่อนแสดงไม่ครบ ไม่บันทึก PHI ลงเอกสาร/log
- API จริงหลัง restart: ไม่ส่งห้องและส่ง roomCode=all คืนทุกห้อง ส่วน roomCode=001 ยังจำกัดตามห้องที่เลือก
- Browser fixture: เลือกทุกห้องเห็น 3 หอ รวมแหล่งส่งไม่ระบุห้อง เลือกห้อง 001 เหลือหอเดียว; เลือกหอ/ใบแล้วจำนวนตารางยังเป็น **2** และไม่มีตารางยา; เข้า Robot จาก Stat กลับเป็นทุกห้อง ส่วน Stat ไม่มี option all ภาพยืนยันใช้ข้อมูลสมมติทั้งหมด

การแก้ครั้งนี้นำตารางยาที่เพิ่มเกิน Windows ออกและเปลี่ยน Robot ให้เริ่มทุกห้อง แก้เอกสารเฟสก่อนที่ระบุว่ากรองตามห้อง login โดยอัตโนมัติ ยังต้องตรวจรับข้อมูลจริงทุกช่วง/ทุกห้องและโหลดหลายผู้ใช้โดยไม่ส่งเครื่องจริง
