## แหล่งข้อมูลและตัวกรอง

ใช้ MSSQL เพียง query เดียวต่อการค้นหา: `prescriptiondetail pt LEFT JOIN ms_drug mdr ON orderitemcode` ไม่ใช่ตาราง prescription และไม่มี MySQL ในเส้นทาง IPD นี้

เงื่อนไขหลัก: departmentcode=`001`, sendmachine=`Y` หรือ printstatus=`1`, ordertype อยู่ใน `0`,`3` ไม่เติมเงื่อนไข void/hold/unused/genorderdatetime หรือห้องยาจาก session เพราะต้นฉบับไม่กรอง

| ตัวเลือก | sendStore | sendF3F4 |
| --- | --- | --- |
| รพ.ผลิตเอง | 1 | 0 |
| ยาฆ่าเชื้อ | 1 | 2 |
| ส่งใบเบิกชั้น 4 | 1 | 1 |
| ยาเสพติด | 2 | ไม่กรอง |

- เวลาใช้ Asia/Bangkok ตอนกดค้นหา: ก่อน 08:00 เริ่มวันก่อนวันที่เริ่มที่ 08:00 และจบวันที่สิ้นสุด 07:59:00; ตั้งแต่ 08:00 เริ่มวันที่เริ่ม 08:00 และจบวันถัดจากวันที่สิ้นสุด 07:59:00 คงวินาที `:00` ตามต้นฉบับ
- รวม `SUM(CAST(orderqty AS DEC(10,2)))` แยกตามรหัส/ชื่อยาในรายการเดิม และ drugform, orderunitcode, Inventorycode, pack ของ master เรียงชื่อยาจาก SQL ไม่เปลี่ยนเป็นชื่อปัจจุบันใน master
- ไม่ตัดแถวซ้ำเพิ่มหรือเลือก master เพียงแถวเดียว เพราะจะทำให้ผลต่างจาก LEFT JOIN/GROUP BY เดิม
- ไม่เรียกโหลด ms_drug ทั้งตารางและ drugname ซ้ำแบบ ucUD_Load เนื่องจากสอง cache นั้นไม่ได้ถูกใช้ใน IPD() ใช้ master join เดียวใน query ตาม getUsageDrug

## ปริมาณ แพ็ก และการจัดกลุ่ม

- จำนวนใช้ไปแปลงด้วยกติกา VB CInt: ครึ่งหน่วยปัดเข้าจำนวนคู่ เช่น 24.5 → 24, 25.5 → 26; ตรวจขอบเขต Int32 ไม่ใช้ Math.round หรือปัดใน SQL
- ถ้ามี pack: `Ceiling(CInt(orderqty)/CInt(pack)) + " x " + ข้อความ pack เดิม`; ถ้าว่างใช้จำนวน orderqty ที่แปลงเป็นจำนวนเต็มแล้ว
- เลขใบเบิก `UD` + ddMMyyyy ของวันที่พิมพ์ปัจจุบัน ไม่ใช่วันที่ตัวกรอง และชื่อห้องเป็น “ห้องยา IPD”
- drugform ว่างแสดง “อื่นๆ”; จัดกลุ่ม drugform จากน้อยไปมากตาม Crystal เก็บลำดับชื่อยาที่ SQL คืนภายในกลุ่ม เลขลำดับนับต่อเนื่องข้ามกลุ่ม ไม่ reset ตาม drugform
- รวมทั้งหมดคือจำนวนแถวรายการ ไม่ใช่ผลรวมจำนวนยา ตาม CountRow และ RunningTotal RTotal0 ของแบบพิมพ์

### ข้อมูล pack เป็นศูนย์ที่พบจริง

ในการตรวจวันที่ 2026-10-21 พบ 7 รายการของชั้น 4 และ 1 รายการของ รพ.ผลิตเอง มี pack ที่ทำให้การหารเป็น Infinity/NaN สูตร VB เดิมให้ข้อความ `Infinity x 0` หรือ `NaN x 0` เว็บคงผลนี้ไว้เพื่อให้ตรงต้นฉบับ ไม่แทนด้วยจำนวนแพ็กที่เดาขึ้น และไม่มีการแก้ master ในฐาน กรณีนี้มี unit test แยกไว้ หากต้องการเปลี่ยนผลควรตกลงเกณฑ์แก้ pack master/สูตรอีกงานหนึ่ง

## คอลัมน์และ PDF

- คงลำดับช่องข้อมูลเดิม: เลขลำดับ, INV_Code, รหัสยา, รายการยา, min Stock, ใช้ไป, Rate/วัน, ขอเบิก, หน่วย โดยหัวตารางต้นฉบับไม่มีชื่อกำกับเลขลำดับและรหัสยาแยกต่างหาก
- min Stock และ Rate/วันว่างตาม Text23/Text25 ของ RPT ไม่สร้างตัวเลขเพิ่มเติม ช่องขอเบิกเป็นข้อความ Pack และหน่วยใช้ master.orderunitcode
- A4 แนวตั้ง 595 × 842 pt ระยะขอบ 18 pt ตำแหน่งกล่องหัวกระดาษ/คอลัมน์/เส้นคั่นแถวอิง layout ของ RPT
- ส่วนหัวใช้โลโก้ ชื่อรายงาน Requisition Report ชื่อโรงพยาบาลและที่อยู่ที่ส่งออกจากต้นฉบับโดยตรง แสดงโลโก้หน้าแรก และซ้ำกล่องเลขใบเบิก/วันที่พิมพ์/หัวคอลัมน์ทุกหน้า
- ฝัง Sarabun สำหรับข้อมูลและหัวตารางเพื่อแสดงภาษาไทยครบ ชื่อยา รหัส แพ็ก หรือหน่วยยาวขึ้นบรรทัดได้ วัดความสูงก่อนแบ่งหน้า ไม่มีการตัดทิ้ง
- ส่วนท้ายรวมจำนวนรายการและช่องลงชื่อ ผู้ขอเบิก / ผู้อนุมัติ / ผู้จ่าย / ผู้รับ ใช้ภาพช่องลงชื่อจากแบบพิมพ์เดิม วางทั้งส่วนไว้หน้าเดียวกัน มีเลขหน้าทุกหน้า
- ข้อมูลเดียวกันใน Blob ใช้ทั้งดูและดาวน์โหลด ไม่อ่านฐานใหม่เมื่อกดดาวน์โหลด
- ทรัพยากรใน `back/assets/reports/requisition-ipd/` มีเฉพาะแบบพิมพ์และโลโก้เดิม ไม่มีข้อมูลจริงฝังอยู่ Runtime ของ server ใช้ Node ไม่ต้องติดตั้ง Crystal หรือ PowerShell

## API และผลตรวจ

- POST `/api/reports/requisition-ipd/pdf` รับเฉพาะ `{from,to,kind}` ต้องมี session เดิม ใช้ bound parameters ไม่รับเซลล์หรือ override department จาก client
- ส่ง PDF เป็น attachment, no-store, มี X-Report-Pages/X-Report-Rows ให้ viewer กรณีไม่มีข้อมูลคืน PDF ว่างและ rows=0 เพื่อให้ frontend แสดง modal ตาม native
- Backend regression ผ่าน **249/249 tests** รวม 9 tests ของรายงานนี้; targeted frontend ESLint และ production build ผ่าน
- อ่าน SQL StringBuilder จาก Windows แล้วเปรียบเทียบกับ query เว็บโดย `tools/check-requisition-ipd-native.cjs` ผลทุกแถวตรงกันทั้ง 4 แบบ ช่วงวันที่ 2026-10-21 โดยกำหนดเวลาค้นหาเป็นหลัง 08:00: ชั้น 4=360, รพ.ผลิตเอง=24, ยาฆ่าเชื้อ=0, ยาเสพติด=5 รายการ การอ่านแต่ละแบบประมาณ 0.6–1.1 วินาทีในการทดลองครั้งแรก (ไม่ใช่ SLA) ผลที่ค้นหาจริงก่อน 08:00 อาจต่างกัน เพราะ Windows และเว็บย้อนหลังรอบอีกหนึ่งวันเหมือนกัน
- ตรวจ PDF จำลอง 6 รายการเทียบกับ Windows: ลำดับรหัสตรงกัน, กลุ่มยา, เลขลำดับ 1–6 ต่อเนื่อง และช่องลงชื่อเหมือนเดิม
- ตรวจ PDF จำลอง 120 รายการ/5 หน้า พบชื่อครบ 120 ไม่ซ้ำ ปลายชื่อยาวครบ 4 จุด หัวคอลัมน์ครบทุกหน้า และไม่มีตัวอักษรนอกกระดาษ ตรวจภาพหน้าแรก/หน้ากลาง/หน้าสุดท้ายแล้ว
- Browser เปิดจาก Report > ใบเบิก > ห้องยา IPD ได้ ค่าเริ่มต้นวันที่วันนี้/ชั้น 4 ถูกต้อง ในเวลาทดสอบจริงก่อน 08:00 รายงานชั้น 4 แสดง 12 หน้า, รพ.ผลิตเอง 2 หน้า, ยาเสพติด 1 หน้า และยาฆ่าเชื้อ 1 หน้า พร้อมการเปลี่ยนเงื่อนไขล้าง PDF เก่า
- ทดสอบวันที่ไม่มีรายการ 2099-01-01: ขึ้น modal “ไม่พบข้อมูล” ปิดแล้วแสดงแบบใบเบิกว่าง และกดดาวน์โหลดจริงได้ PDF A4 แนวตั้ง 1 หน้า
