# Report > ใบเบิก > ห้องยา ER (OPD)

**อัปเดต 23 ต.ค. 2026: นำหน้าใบเบิกนี้ออกตามคำขอผู้ใช้แล้ว** ไม่มีเมนู/ตัวอ่านข้อมูล/API ของรายงานนี้ ลิงก์เดิมกลับหน้า IPD เอกสารด้านล่างเก็บเป็นประวัติเท่านั้น ส่วนแปลงข้อมูล OPD ที่ห้องยา OPD อาคารรังสียังใช้ย้ายเป็น `reportRequisitionOpd.js` / `opdRequisitionRoutes.js` ไม่ใช่หน้ารายงาน ER (OPD) ที่ยังเปิดใช้

พัฒนา 22 ตุลาคม 2026 เปิดที่ `/ipd/reports/requisition-er-opd` ผ่าน session เดิม เป็นหน้าดูข้อมูล ไม่สร้างใบเบิก ไม่ตัดสต็อก และไม่ส่งเครื่องพิมพ์หรือ Robot

## ต้นฉบับและฟอร์ม

- ปุ่ม OK เรียก **OPD()** คนละฟังก์ชันกับเมนู “ห้องยา ER” ที่เรียก ER()
- ใช้ ucUD.Designer และ crpRequisitionNew.rpt เดียวกับใบเบิกห้องยาอื่น วันที่เริ่ม/สิ้นสุดเริ่มวันนี้ เลือกส่งใบเบิกชั้น 4 เป็นค่าเริ่มต้น
- ตัวเลือกครบ รพ.ผลิตเอง / ยาฆ่าเชื้อ (ใต้ส่งใบเบิกชั้น 3) / ส่งใบเบิกชั้น 4 / ยาเสพติด กด OK จึงค้นหา
- เปลี่ยนเงื่อนไขแล้วซ่อน PDF เก่าและยกเลิกคำขอเดิม ไม่ค้นหาอัตโนมัติ สลับห้องยาเริ่มฟอร์มใหม่

## ข้อมูลและการแปลงตาม OPD()

- แหล่งรายการเป็น MySQL เพียงฝั่งเดียว: `view_pharmacy_opd_drug_item`, location=`ER`, inv_type != `9`, Date BETWEEN วันที่เริ่ม/สิ้นสุดตามปฏิทิน รวม `IFNULL(SUM(CAST(no AS DEC(10,2))),0)` GROUP BY drugcode
- ไม่รวมรายการ IPD ไม่ใช้รอบเวลา 08:00 ไม่เพิ่มเงื่อนไข ordertype หรือกรอง drugcode `zzzzzz` ซึ่งใน native เป็นเพียง comment
- แปลงรหัสด้วย drugname.mc_id → Sum_MCID จาก MSSQL เลือกแถวแรก ถ้าไม่พบหรือปลายทางว่างใช้รหัสเดิม
- เลือก master ms_drug แถวแรกของรหัสที่แปลงแล้วซึ่งตรงประเภทใบเบิก ใช้ orderitemENname, drugform, orderunitcode, Inventorycode และ ISNULL(pack,0) ไม่กรอง unused

| ตัวเลือก | sendStore | sendF3F4 |
| --- | --- | --- |
| รพ.ผลิตเอง | 1 | 0 |
| ยาฆ่าเชื้อ | 1 | 2 |
| ส่งใบเบิกชั้น 4 | 1 | 1 |
| ยาเสพติด | 2 | ไม่กรอง |

- กรองประเภทหลังแปลงรหัส ไม่กรองใน SQL ต้นทางก่อนแปลง
- **แต่ละรหัสต้นทางยังเป็นคนละแถว** แม้แปลงเป็นรหัสยาเดียวกัน ไม่รวมซ้ำแบบ ER() ตัวอย่าง 24.5 และ 25.5 จากสอง alias ของยาเดียวกัน ได้สองแถวจำนวน 24 และ 26 แพ็กละ 3 x 10 ไม่ใช่แถวเดียว 50 / 5 x 10
- จำนวนใช้ไปใช้ VB CInt ปัดครึ่งเข้าจำนวนคู่และตรวจ Int32 ขอเบิก=`Ceiling(CInt(qty)/CInt(pack)) x pack` ถ้า pack ว่างใช้จำนวนเต็ม ถ้า pack=0 คง Infinity/NaN ตาม native ไม่แก้ master
- drugform ว่างเป็น “อื่นๆ” เรียงชื่อยาแล้วจัดกลุ่ม drugform ใน PDF เลขลำดับต่อเนื่อง ยอดรวมเป็นจำนวนแถว
- เลขใบเบิกยังขึ้นต้น **ER** + ddMMyyyy ของวันพิมพ์ ไม่ใช่ ER_OPD หรือวันค้นหา ชื่อห้อง “ห้องยา ER (OPD)”
- ใช้ Map สำหรับ lookup แทน DataTable.Select ซ้ำทุกแถว เมื่อมีรายการจึงอ่าน master/mapping สองคำสั่งพร้อมกัน ไม่มี query รายตัวยา

## MySQL เขียนเตรียมไว้เท่านั้น

- ไม่ทดสอบเชื่อมต่อหรือ query MySQL จริงตามที่ผู้ใช้ระบุ
- ค่าเริ่มต้น `REPORT_REQUISITION_ER_OPD_ONLY_ENABLED=false` หรือไม่กำหนด จะไม่เรียกทั้ง MySQL และ master/mapping ของรายงานนี้
- หน้าเว็บแสดง “ยังไม่เปิดข้อมูล ER (OPD) จาก MySQL จึงยังแสดงยอดใบเบิกไม่ได้” และปิดดาวน์โหลด ไม่สร้าง PDF ว่างหรือแสดงว่าไม่พบข้อมูลแทนฐานที่ยังไม่ได้อ่าน
- ถ้าเปิดแล้ว MySQL อ่านไม่ได้ แสดงสถานะแหล่งข้อมูลอ่านไม่ได้ ไม่มี PDF ยอดศูนย์ปลอม
- เปิดภายหลังโดยตั้ง `REPORT_REQUISITION_ER_OPD_ONLY_ENABLED=true` ใน back/.env และใช้ SERVER/USER/PASSWORD/DATABASE_HOSPITALKKH เดิม แล้วรีสตาร์ต backend
- flag นี้แยกจาก `REPORT_REQUISITION_ER_OPD_ENABLED` ซึ่งใช้เฉพาะส่วน OPD ของรายงาน ER แบบรวม การเปิดรายงานหนึ่งไม่เปิดอีกอัน
- ใช้ pool แบบ lazy ร่วมกับรายงาน OPD มี connectTimeout 8 วินาที/query timeout 120 วินาทีตามการแก้รายงานช่วงยาว ไม่มีการสร้าง connection ตอน import module และไม่มี secret อยู่ใน frontend

## คอลัมน์ ป๊อปอัป และ PDF

- ใบเบิก A4 แนวตั้ง คอลัมน์เลขลำดับ, INV_Code, รหัสยา, รายการยา, min Stock (ว่าง), ใช้ไป, Rate/วัน (ว่าง), ขอเบิก, หน่วย ตาม RPT เดิม
- โลโก้/ชื่อโรงพยาบาล/ที่อยู่หน้าแรก เลขใบเบิก ER/ห้องยา ER (OPD)/วันที่พิมพ์และหัวคอลัมน์ซ้ำทุกหน้า ยอดรวมจำนวนแถวและช่องลงชื่อผู้ขอเบิก/ผู้อนุมัติ/ผู้จ่าย/ผู้รับเดิม
- ใช้ renderer/assets ร่วมกับ IPD/D/C/ER ชื่อยาและรหัสยาวขึ้นบรรทัดและแบ่งหน้าตามความสูง ฝังฟอนต์ไทย ไม่ใช้ Crystal ตอนรัน server
- หากอ่าน OPD สำเร็จแต่ไม่มีแถวต้นทาง: แจ้ง “ไม่พบข้อมูล” แล้วแสดง PDF ว่าง ตาม OPD() ซึ่งไม่ได้ Exit Sub แบบ ER()
- หากมีแถวแต่ประเภทที่เลือกไม่เหลือรายการ: แสดงแบบพิมพ์ว่างโดยไม่แจ้งว่าไม่มีข้อมูล
- ไม่พบ master ของรหัสหลังแปลง: dialog “ระบบแจ้งเตือนรหัสยา OPD ที่ไม่มีใน Unitdose” มีรหัสยา/ชื่อยาและจำนวน เก็บรายการซ้ำ ไม่ถือว่ายาที่อยู่ประเภทอื่นเป็นรหัสหาย
- ปุ่ม PDF รายการยาแทน Print ของ frmMessageDrug ใช้แบบ crpRequisitionDrug.rpt (US Letter) พร้อมโลโก้ Drug Report/วันที่/เลขหน้าและลำดับ/รหัส/ชื่อยา เรียงชื่อยา
- ดาวน์โหลด `ER-OPD-Requisition-Report.pdf` และ `ER-OPD-Unmapped-Drugs.pdf` จาก snapshot การค้นหาเดียวกัน ไม่อ่านฐานใหม่เมื่อดาวน์โหลด

- POST `/api/reports/requisition-er-opd/preview` รับเฉพาะ `{from,to,kind}` ต้องมี session/no-store ไม่รับข้อมูลแถว/override ห้องยา/เปิด MySQL จาก client

- Backend regression **268/268 ผ่าน** รวม ER (OPD) 7 tests ทดสอบ alias แยกแถว, การปัด, 4 ประเภท, master/map แถวแรก, รหัสหาย, pack ว่าง/ศูนย์, ก่อน/หลัง 08:00, unavailable/empty/category-empty, auth/filters/read-only และ PDF ทั้งสองแบบ
- Frontend targeted ESLint และ production build ผ่าน
- PDF จำลอง 6 แถว 1 หน้า ยืนยันสอง alias ของยาเดียวกันยังแยกแถว; stress 120 แถว 7 หน้า ชื่อครบ 120 และปลายชื่อยาวครบ 4 จุด ไม่มีอักขระนอกกระดาษ ตรวจภาพหน้าแรก/กลาง/ท้ายแล้ว
- PDF รหัสยาที่ขาดจำลอง 90 แถว 4 หน้า ชื่อครบ 90 และปลายชื่อยาวครบ 3 จุด ไม่มีอักขระนอกกระดาษ โลโก้/หัวตารางครบ
- Browser หน้าจริงเปิดจากเมนูได้ ค่าเริ่มต้นวันนี้/ชั้น 4 ถูกต้อง กด OK ในโหมดปิด MySQL ขึ้นสถานะยังไม่เปิดข้อมูล ไม่มี modal ไม่พบข้อมูลและไม่เปิดปุ่มดาวน์โหลด
- Browser ทดสอบผ่าน production build กับ server ชั่วคราวเฉพาะ localhost ซึ่งใช้ข้อมูลจำลองทั้งหมด: dialog รหัสยาที่ขาดแสดง 2 คอลัมน์/จำนวนถูกต้อง ปุ่ม PDF รายการยาเรียกดาวน์โหลดได้ และกรณีแหล่งข้อมูลว่างแจ้ง “ไม่พบข้อมูล” ตาม native
- Browser production จำลอง 120 แถวแสดง 4 หน้า เปลี่ยนหน้าสุดท้าย/ซูมพอดีหน้าได้พร้อมช่องลงชื่อครบ กรณีแหล่งข้อมูลมีแถวแต่ไม่อยู่ประเภทที่เลือกแสดง PDF ว่าง 1 หน้าและไม่มี dialog ไม่พบข้อมูล จากนั้นปิด server จำลองแล้ว
- แก้ class สีพื้นของปุ่ม OK ที่มีทั้ง bg-white/bg-slate-500 จนสีทับกันใน production ให้เหลือสีเดียว โดยใช้ฟอร์มร่วมเดิม
