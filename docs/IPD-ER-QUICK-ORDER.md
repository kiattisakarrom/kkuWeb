# [ER] Quick Order — 20 ตุลาคม 2026

เพิ่มหน้าที่ `/ipd/quick-order` และทางเข้าจากเมนูห้องยา IPD / Screening แบบดูข้อมูลเท่านั้น อ้างอิง `frmMain.QuickPrescirptionOrderToolStripMenuItem_Click`, `Screenning/ucScreenAll.vb`, Designer ของ control เดียวกัน และ `clsPrescription.getPresHeader` ในซอร์ส Windows ที่ผู้ใช้ให้มา

## รูปแบบและข้อมูล

- Windows ตั้ง `changquickmode=True` แล้วเปิด `ucScreenAll` จึงใช้ protected API และ MSSQL reader เดียวกับ Screening “รอ Screen ทั้งหมด” ไม่ใช้เงื่อนไข Stat หรือ Continue แทน
- สามส่วนตาม Windows: หอผู้ป่วย 3 คอลัมน์, หัวใบสั่งยา 9 คอลัมน์, เลขใบที่เลือกดู 2 คอลัมน์ สัดส่วนประมาณ 19/61/20; ตารางหัวใบเลื่อนแนวนอนเพื่ออ่านครบ
- หอผู้ป่วย: ช่องเลือก / หอผู้ป่วย / จำนวน ไม่เติมรหัสหน้าชื่อที่บันทึก
- หัวใบ: ช่องเลือก / ใบสั่งยา / วันที่ / ประเภท / HN / AN / ชื่อ - นามสกุล / หอผู้ป่วย / สถานะใบสั่งยา ซ่อนเตียงและฟิลด์เทคนิคตาม Designer
- รายการด้านขวา: เลขที่ใบสั่งยา / ลบ ใช้เป็นรายการเลือกดูในหน้าเว็บเท่านั้น
- เลือกห้องยาจากข้อมูลจริง วันที่ Order Type และสถานะส่งจัดยาได้ ค่าเริ่มต้นเป็น Order Type ทั้งหมด และยังไม่จ่าย ตัวเลือกประเภท 1 ซ่อนตาม Windows แต่ข้อมูลประเภท 1 ยังรวมอยู่เมื่อเลือกทั้งหมด
- วันที่ในหัวใบใช้วันสร้าง order ตาม native และแสดง dd/MM/yyyy สถานะมาจาก `genorderdatetime` มีค่าเป็น Screen แล้ว พร้อมสีเขียว; ไม่มีค่าเป็นรอ Screen
- SQL เดิมอ่าน prescription ที่อยู่ใน active master wards และชื่อห้องใน fromlocationname; ใช้ parameter binding ก่อน 08:00 ใช้วันก่อน 08:00 ถึงวันที่เลือก 07:59:00 หลัง 08:00 ใช้วันที่เลือก 08:00 ถึง 23:59:00; Stat ใช้ S/E/STAT ตาม source

## การใช้งานแบบอ่านอย่างเดียว

- เริ่มต้นแสดงทุกหอที่มีรายการ เลือกหลายหอได้ เมื่อเอาเครื่องหมายสุดท้ายออกจะแสดงหัวใบว่างตามพฤติกรรม native โหลดหัวใบรวมหนึ่งครั้งแล้วกรองหอในเว็บ ไม่เรียก SQL ใหม่ต่อการคลิกหอ
- เปลี่ยนห้อง/วันที่/ประเภท/สถานะ โหลดทั้งหอและหัวใบให้ใช้เงื่อนไขเดียวกัน ไม่คงยอดหอเก่าหรือสะสมแถวจากรอบก่อน แสดงยอดจริงแทน label จำนวน 0 ที่ค้างใน native
- ดับเบิลคลิกเลขใบเพิ่มเลขใบในรายการเลือกดูด้านขวา รับเลขซ้ำและนำออกทีละแถวได้ตาม native แต่ไม่สร้างใบ ไม่ลบข้อมูลจริง ไม่ส่งจัดยา
- ดับเบิลคลิกข้อมูลอื่นในหัวใบเปิดรายละเอียดผู้ป่วยที่แท็บรายการสั่งยาพร้อมเลขใบที่เลือก ใช้วอร์ดปัจจุบันของผู้ป่วย กลับแล้วคงห้อง/วัน/รอบ/ตัวกรอง/หอที่เลือก/เลขใบและรายการเลือกดู ถ้าไม่มีวอร์ดปัจจุบันจะแจ้งเหตุผลและไม่เปิดผิดบริบท
- ปุ่มจัดยา พิมพ์สติกเกอร์ พิมพ์ใบสั่งยา และช่องเลือกใบเพื่อจัดยาปิดใช้งาน ไม่มีคำสั่งเขียนฐานข้อมูลหรือส่งเครื่อง
- แยกข้อมูลว่างจากโหลดล้มเหลว ล้างข้อมูลเก่าเมื่อ request เปลี่ยน และไม่แสดงจำนวน 0 แทน error

- อ่าน visible/header/order จาก Windows Designer โดยตรง: ตาราง 3/9/2 คอลัมน์ตรงทั้งหมด
- เพิ่ม unit tests 6 กรณีสำหรับคอลัมน์/ตัวกรอง/วันที่/ค่าว่างและศูนย์/แถวซ้ำ/การเลือกหลายหอ/รายการเลือกดู/การเปิดรายละเอียดและกลับอย่างปลอดภัย ชุดทดสอบทั้งหมด 178 กรณีผ่าน ใช้ DB stub ไม่เปิด MySQL
- Production build และ ESLint เฉพาะไฟล์ที่แก้ผ่าน
- Browser ใช้ component จริงกับข้อมูลสมมติ ตรวจทางเข้าจาก IPD และ Screening การเปลี่ยนห้อง/วัน/ประเภท/สถานะ เลือกหลายหอ เลขใบซ้ำและนำออก เปิดใบยาและกลับครบ กรณีไม่มีวอร์ด ข้อมูลว่าง และ error; ไม่พบ console error และจำนวน request เขียนข้อมูลเป็น 0
- การเลือกหอครั้งแรกและครั้งถัดไปไม่เพิ่ม ward/header requests ไม่ทำให้ทั้งหน้ากระพริบโหลดซ้ำ

- ภาพประกอบเป็นข้อมูลสมมติ การตรวจ MSSQL เป็นตัวอย่าง ไม่ใช่การเทียบ Windows สดทุกสถานะ ไม่มีการเรียก MySQL หรือ hospital API ไม่มี commit/push
