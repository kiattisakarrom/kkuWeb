# ป๊อปอัปเมื่อเปิดโปรไฟล์ผู้ป่วย — 20 ตุลาคม 2026

เพิ่มป๊อปอัปในกรอบ FrmProfile เดิม ใช้ข้อมูลจริงที่บันทึกไว้และอ่านอย่างเดียว ใช้ได้ทั้งเปิดผู้ป่วยจาก IPD, Screening และ URL รายละเอียดที่ผ่านการตรวจสิทธิ์ ไม่เกี่ยวกับหน้าใบสั่งยาที่มีภาพ

## เงื่อนไขที่ใช้งานจริงในซอร์ส Windows

1. `ucAddOrderdispense.ShowdataPatient -> showadr`: มีแถวประวัติ ADR ของ HN จึงแสดงประวัติ/ชนิด ADR/อาการ/คำเตือนที่บันทึก ไม่กรองเฉพาะ Type B และไม่คำนวณความเสี่ยงขึ้นใหม่ ใช้ response `/allergies` ที่กรอบด้านบนอ่านอยู่แล้ว ไม่ยิง query ประวัติแพ้ยาซ้ำ
2. `ShowdataPatient -> frmNote.Getdata`: มีบันทึก ms_note ของ HN จึงเปิดรายการ Note แม้บันทึกเก่าหรือข้อความในแถวนั้นว่าง คง 4 คอลัมน์เดิม เลือกแถว/ปุ่มวันที่แล้วอ่าน Problem และ Note เต็มใน textarea readOnly ไม่มีปุ่มเพิ่ม/แก้/ลบ
3. `ucDispense -> ucMedicationprofile.CheckOrderOR`: จำนวนที่นับใน Medication Profile กับ prescription ไม่เท่ากันตาม query native จึงแสดงข้อความรายการยาห้องผ่าตัด พร้อมยอดที่อ่านได้

คิวเปิดตามลำดับ ADR -> Note -> OR แม้คำขอหลังเสร็จก่อน ถ้าไม่มีแถว/ยอดเท่ากันจะไม่เปิดป๊อปอัปนั้น ไม่เปิดกล่องว่าง

**OR ใช้เกณฑ์ legacy ตามต้นฉบับ:** `LEN(m.meditemindex) BETWEEN 10 AND 13`, join `m.meditemindex = p.itemindex` และเปรียบเทียบ COUNT ที่ได้ ไม่เปลี่ยนเป็น meditemindex/timecode/ความหมายของ OR ที่เดาขึ้นเอง เพิ่ม AN/HN ในทั้งสองฝั่งเพื่อจำกัดข้อมูลของผู้ป่วยที่ server resolve

ไม่เรียก `AddOrderOR` หรือการนำเข้ารายการก่อนตรวจ จึงแจ้งเฉพาะรายการที่มีบันทึกใน Medication Profile แล้ว ไม่มีการสร้างใบสั่งยา คิดเงิน หรือปรับสถานะใด ๆ

## พฤติกรรมเว็บ

- ปิดด้วยปุ่มหรือ Escape เลื่อนไปแจ้งเตือนถัดไป เก็บการปิดเฉพาะหน่วยความจำของการเปิดโปรไฟล์ครั้งนี้ ไม่บันทึกว่าอ่านแล้วลงฐานข้อมูล
- สลับแท็บ เปลี่ยนหมวด และโหลดรายละเอียดใหม่ไม่เด้งรายการที่ปิดแล้วซ้ำ กลับออกไปแล้วเปิดผู้ป่วยใหม่จะตรวจ/แจ้งใหม่ ไม่ใช้ localStorage หรือ sessionStorage จำการปิด
- ปุ่ม “ดูแจ้งเตือนผู้ป่วยอีกครั้ง” เปิดคิวอ่านซ้ำได้ เปลี่ยน AN/วอร์ดแยกสถานะการปิด ไม่ส่งคำเตือนของผู้ป่วยเดิมไปผู้ป่วยใหม่
- ใช้ native modal dialog พร้อม portal, focus ภายในกล่อง, แสดงชื่อ/HN/AN ของผู้ป่วยตรงบริบท และคืน focus เมื่อปิด ข้อความแสดงเป็น React text ไม่รับ HTML จากข้อมูลบันทึก
- ถ้าแหล่งใดโหลดไม่ได้ แสดง “ตรวจแจ้งเตือนได้ไม่ครบ” พร้อมชื่อแหล่งและปุ่มลองใหม่ ยังเปิดแจ้งเตือนจากแหล่งที่อ่านสำเร็จ ไม่แปลข้อผิดพลาดเป็น “ไม่มีแจ้งเตือน”

จุดเปิดโปรไฟล์ใน Windows ที่ตรวจได้ comment การเรียก checkadr/checkredrug/checkdruginteraction/checkdruglabbytypename ไว้ จึงไม่เพิ่มการตรวจยา/LAB หรือคู่ยาซ้ำอัตโนมัติจากฟังก์ชันเหล่านั้น ไม่เปลี่ยนปุ่มยืนยันสร้าง/แก้ไขใน Windows มาเป็นการทำงานในเว็บ

## API และการตรวจ

- ใช้ `/pharmacist-notes` เดิม และเพิ่ม GET `/api/ipd/patients/:an/operating-room-alert` ซึ่งผ่าน JWT/current ward/current AN/HN resolver เดิม ใช้ SQL parameters ทุกค่า ไม่รับ HN override และปิด mutation เช่นเดิม
- ทุกแหล่งของงานนี้เป็น MSSQL ไม่เรียก MySQL หรือ hospital HTTP API เพื่อทดสอบ
- ชุดทดสอบทั้งหมด 172 กรณีผ่าน รวมคิว/เงื่อนไข/ค่าว่าง/0/การปิดตามบริบท/partial failure/SQL bindings/ไม่ import หรือ write และสิทธิ์ endpoint ใหม่; production build และ ESLint ไฟล์ที่แก้ผ่าน
- Browser ใช้ component/hook จริงกับข้อมูลสมมติ: ADR ก่อน Note ก่อน OR, Note 793 ตัวอักษรครบและ readOnly, เลือกแถวว่างล้างรายละเอียด, Escape, ไม่เด้งซ้ำหลังสลับแท็บ/โหลดใหม่, เปิดอ่านซ้ำ, ผู้ป่วยไม่มีคำเตือนไม่เปิดกล่อง, Note อย่างเดียว, ต้นทางบางส่วนล่มและลองใหม่, ออกจากผู้ป่วยแล้วกลับมาตรวจใหม่
- ภาพหลักฐานใช้ข้อมูลสมมติเท่านั้น ไม่รับรองข้อมูลผู้ป่วยจริงทุกกรณี ไม่ commit/push
- ทดลอง query OR กับ MSSQL จริงด้วย AN/HN สมมติที่ไม่มีผู้ป่วย ได้ aggregate รูปแบบถูกต้อง เป็นการตรวจ compile/query กรณีว่าง ไม่ใช่ผลเทียบผู้ป่วย OR จริง
