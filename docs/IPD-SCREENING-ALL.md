# Screening — ยารอ Screen ทั้งหมด (ดูข้อมูล)

ตรวจ 18 ตุลาคม 2026 เทียบ Windows `Screenning/ucScreenAll.vb` และ Designer, `ucScreenningMain.btnContinueAll_Click` และ `clsPrescription.getgroupWard/getPresHeader`

## หน้าจอและขอบเขต

เปิดปุ่ม **ยารอ Screen ทั้งหมด** ในโครงเมนู Screening เดิม (`mode=screen-all`) เลือกห้องยาจาก `ms_room` จริง เริ่มห้อง login หรือห้องเฉพาะที่เลือกอยู่ หากมาจาก Robot ทุกห้องจะกลับใช้ห้อง login

แสดงวอร์ดที่มีรายการทางซ้าย และหัวใบทุกวอร์ดทางขวาเมื่อยังไม่ได้เลือกวอร์ด เลือกวอร์ดเพื่อจำกัดหัวใบ หรือกด “ทุกหอผู้ป่วยที่มีรายการ” เพื่อกลับทั้งหมด ค้น AN/HN/เลขใบแบบตรงกันข้ามทุกวอร์ดในห้องและตัวกรองที่เลือก เปลี่ยนตัวกรองแล้วล้าง selection เก่า

- ส่งจัดยา: **ยังไม่จ่าย / จ่ายแล้ว / ทั้งหมด** ตามคำใน Windows; ค่าเริ่มต้นยังไม่จ่าย หมายถึง `genorderdatetime IS NULL / IS NOT NULL / ไม่จำกัด` ไม่ใช่หลักฐานการบริหารยา
- Order Type: **ทั้งหมด / 0 / 1 / 3 / Stat**; ค่าเริ่มต้นทั้งหมด และรวมยากลับบ้านด้วยเมื่อเข้าเงื่อนไข Stat ใช้ frequency S/E/STAT โดยไม่จำกัด ordertype
- สถานะหัวใบอ่านรายแถวจากวัน gen แสดง “รอ Screen / Screen แล้ว”; ใบที่ Screen แล้วพื้นเขียว
- ดับเบิลคลิกหรือปุ่มรายละเอียดเปิดหน้า patient prescription ที่มีอยู่ พร้อมรอบและเลขใบที่เลือก กลับคง mode/ห้อง/วัน/รอบ/คำค้น/วอร์ด/ใบ/สถานะ/ประเภท

Windows มีตารางที่สาม `dgvAddPres` สำหรับรวมเลขใบแล้วส่งจัดยา ไม่ใช่ตารางยา ในรุ่นดูข้อมูลจึงคงเฉพาะตารางวอร์ดและหัวใบ ไม่สร้างตะกร้าจัดยา ไม่มี checkbox จัด/ส่ง/พิมพ์หรือ mutation ผ่าน double-click ปุ่มเขียนปิดไว้ทั้งหมด รายละเอียดยาดูผ่านหน้าผู้ป่วย ไม่เรียก detail API ของคิว Stat แทน

## กติกาข้อมูล

ใช้ MSSQL `prescription` ตามต้นฉบับ หน้านี้ไม่มีแหล่ง MySQL ที่ต้องรอเครือข่ายโรงพยาบาล

- ทั้งวอร์ดและหัวใบต้องมี master วอร์ด `wardstatus='Y'` นับ distinct เลขใบต่อวอร์ด และ group หัวใบตามวันสร้าง/เลขใบ/HN/AN/ชื่อ/วอร์ด/เตียง/ordertype/ห้อง/วัน gen
- ห้องยาใช้ **substring รหัสห้องใน fromlocationname** ตาม native ไม่เปลี่ยนเป็นการเทียบชื่อห้องแบบ exact ใช้ parameter และ escape wildcard ให้รหัสเป็นข้อความจริง
- ไม่เพิ่ม non-home, non-Stat, Off/Hold หรือ priority exclusion ของหน้าคิวอื่น
- เวลาไทยก่อน 08:00: วันที่เลือกถอยหนึ่งวัน 08:00 ถึงวันที่เลือก 07:59:**00**; ตั้งแต่ 08:00: วันที่เลือก 08:00 ถึงวันเดียวกัน 23:59:**00** ทั้งยอดวอร์ดและหัวใบ ไม่ใช้รอบถึงเช้าวันถัดไปของโหมด Stat/Continue และไม่ขยายปลายช่วงเป็น :59
- backend คืน workdate ที่ใช้จริงให้คำขอลูกและหน้ารายละเอียด เพื่อคงรอบเมื่อข้าม 08:00 การโหลดใหม่จะคำนวณรอบใหม่
- native เปลี่ยน radio แล้ว refresh เฉพาะหัวใบบาง event ทำให้ยอดวอร์ดอาจค้าง เว็บ refresh ทั้งสองตารางด้วยตัวกรองเดียวกัน เป็นการแก้ความไม่สอดคล้องนี้

API GET `/api/ipd/screening/wards` และ `/prescriptions` ตรวจ JWT, ห้องจริง, วัน/รอบ, enum สถานะและประเภท; โหมด All เท่านั้นที่ไม่ต้องส่ง wardCode ในรายการหัวใบ ต้องไม่ส่ง wardCode ว่างหรือผิดรูปแบบ ไม่รับ HN/AN override ส่วนรายละเอียดผู้ป่วยตรวจ AN/วอร์ดปัจจุบันผ่าน backend เดิม ไม่มี API ส่งจัดยา/พิมพ์/ส่งเครื่อง

SQL แยกจาก Stat/Continue/Robot ใช้ pool ร่วมและ parameters ไม่ใช้ FORMAT หรือ join ms_drug ที่ไม่จำเป็นต่อหัวใบ รองรับ `ordertype` ตัวเลขในฐานจริงด้วยพารามิเตอร์แยกสำหรับ 0/1/3; ค่า all/stat ไม่ถูกนำไปเทียบคอลัมน์ตัวเลข

## ผลตรวจ

- Backend **106 tests ผ่าน** รวมก่อน/ตรง 08:00, leap day/ข้ามปี, pin รอบ, query routing และ literal LIKE, default/15 ชุด enum, optional ward, malformed/array filters, auth, readonly, แยก empty/503 และกลับจากผู้ป่วยคงตัวกรอง
- Frontend build และ ESLint ไฟล์ที่แก้ผ่าน
- เทียบ SQL ต้นฉบับกับ repository บนฐานจริงวันที่ 18 ต.ค. 2026 ห้อง 001 ครบ **15 ชุดสถานะ × ประเภท** ยอดรายวอร์ดและ fields ของหัวใบตรงกันทุกชุด รวมผลเมื่อเลือกวอร์ด ตัวอย่างเริ่มต้น pending/all ได้ **27 วอร์ด / 89 แถวหัวใบ**, all/all ได้ **71 วอร์ด / 1,453 แถวหัวใบ** จำนวนแถวหัวใบอาจมากกว่าจำนวน distinct เลขใบตามการ group ของต้นฉบับ
- ห้อง 002 รอบก่อน 08:00 เทียบ all/all ตรงกัน **14 วอร์ด / 122 แถวหัวใบ**
- API จริงหลัง restart ตอบ 200 ทั้งยอดและหัวใบ ตัวอย่างห้อง 001/002, Stat และยากลับบ้าน ใช้ประมาณ **327–930 ms ต่อคำขอ** จาก 8 คำขอที่วัดบนเครื่องนี้ ไม่ใช่ค่า p95 หรือผลรับรองโหลดหลายผู้ใช้
- Browser fixture: ค่าเริ่มต้น, รวมสองสถานะ/พื้นเขียว, home/Stat, ห้องอื่น, ค้นข้ามวอร์ด, empty, double-click เปิดใบจริงของข้อมูลสมมติ, กลับคงตัวกรอง/selection และมีสองตารางผ่าน เว็บจริงแสดงค่าเริ่มต้น 27 วอร์ด / 89 แถวตรงกับ API
- ไม่บันทึก PHI/token ลงรายงานหรือภาพ ภาพยืนยัน `ipd-screening-all-demo.png` ใช้ข้อมูลสมมติทั้งหมด
