# Report > ADR

เพิ่มสองหน้าในเมนู Report > ADR ของโครง IPD เดิม:

- ADR: `/ipd/reports/adr`
- ประวัติ ADR: `/ipd/reports/adr/history`

## แหล่งและคอลัมน์

อ้างอิง Windows `ctx/ADR/ucReportADR.vb`, `ucADRHistory.vb`, `frmPreviewADR.vb`,
`ctx/class/clsADR.vb` และ `Report/Sendmix/crpADR.rpt` ในซอร์สที่ผู้ใช้ให้มา

ADR ค้นด้วย AN ไม่บังคับวอร์ดหรือห้องยา เพราะ query ของต้นฉบับไม่กรองสองค่านี้
อ่าน `ms_medicationprofile` เฉพาะ priority C/O โดยรวมรายการ Off/สิ้นสุดการใช้ด้วย
เลือกใช้ช่วงวันสร้างรายการยาได้ (เริ่มต้นไม่ใช้วันที่)

ตารางเรียงเหมือน Windows: เลือกสำหรับ PDF, ประเภท, S,O,I, รหัสยา, ชื่อยา, Dose,
หน่วยย่อย, QTY, หน่วยขาย, วิธีใช้, ความถี่, เวลา, วันเริ่ม, วันหยุดใช้
คอลัมน์หน่วย/วิธีใช้/ความถี่/เวลาแสดงรหัสตามหน้าจอ Windows ไม่แทนด้วยคำอธิบาย
ส่วน PDF ใช้คำอธิบายจาก master ตาม frmPreviewADR

ประวัติ ADR เลือกช่วงวันที่สร้างบันทึก และกรอง HN แบบตรงตัวได้ (ว่างคือทุก HN)
คอลัมน์ 18 ช่องตรงต้นฉบับ: HN, ชื่อผู้ป่วย, วันที่, Type of ADR, ประวัติแพ้ยา,
กลุ่มยา, genericname, ingredientname, วันที่เกิด, อาการไม่พึงประสงค์,
Pharmacist note, Onset of ADR, หน่วยของ Onset, Naranjo's score,
Propability, Policy, ผู้ประเมิน, ผู้บันทึก
คงการ join รายการ generic/ingredient ของ native และจำนวนแถวตาม query เดิม

ทั้งสองหน้าใช้ **MSSQL Interface** ไม่มี query MySQL ในเส้นทางต้นฉบับนี้
จึงไม่ได้เชื่อมต่อหรือตรวจข้อมูล MySQL เพิ่ม

## การอ่านอย่างเดียวและ PDF

- ใช้ JWT/session เดิม ต้องเข้าสู่ระบบก่อนอ่านหรือออก PDF
- GET `/api/reports/adr/medications` และ `/history` รับเฉพาะตัวกรองที่ระบุไว้
- POST `/api/reports/adr/pdf` อ่านข้อมูลใหม่จาก AN/ตัวกรองและ meditemindex ที่เลือก
  รับเฉพาะ id และ S/O/I จาก browser ไม่รับชื่อผู้ป่วย/ข้อมูลยาที่ browser แต่งเอง
- เลือกแถว/เลือกทั้งหมด/S,O,I เป็น state ของรายงาน ไม่เขียนฐานข้อมูล
- ไม่มี INSERT/UPDATE/DELETE, เปลี่ยนสถานะ, OCS หรือเครื่องพิมพ์
- ADR ดาวน์โหลด PDF A4 จากแบบฟอร์มเดิม; ประวัติ ADR ดาวน์โหลดตาราง PDF A3 แนวนอน
  แทน Export Excel ใน native สำหรับขอบเขตนี้
- PDF สร้างในหน่วยความจำ ส่งเป็น attachment และ Cache-Control: no-store
- ไม่พบข้อมูล, โหลดไม่สำเร็จ และต้องค้นหาใหม่แสดงแยกกัน; เปลี่ยนตัวกรองซ่อนผลเดิมทันที
- ยกเลิก request เมื่อเปลี่ยนหน้า/เงื่อนไข และหยุด download ของเงื่อนไขเก่า
- PDF รับยาได้ไม่เกิน 200 รายการต่อครั้ง; ถ้ารายการเปลี่ยน/ไม่ตรงกันให้ค้นหาใหม่

## จุดผิดปกติใน native ที่ไม่ทำซ้ำ

- ucADRHistory เปลี่ยนปีของวันที่เก่าเป็นปีปัจจุบันก่อนแสดง เว็บคงวันที่จริงที่บันทึก
- ucReportADR เปรียบเทียบวันสิ้นสุดเป็น string dd/MM/yyyy ซึ่งผิดข้ามเดือน/ปี
  เว็บเทียบวันปฏิทินจริงเพื่อเลือกค่าเริ่มต้นและสีเทา ไม่ซ่อนรายการ
- ค่าว่างวันที่ไม่ทำให้ทั้งตารางโหลดล้มเหลว
- คงค่าที่บันทึกและคะแนน 0 ไม่อนุมานประเภท ADR หรือผลประเมินเพิ่มเติม

## ผลตรวจ

- Backend tests ผ่าน 203/203 (รวม ADR ใหม่ 7 tests) และ frontend build/lint ไฟล์ที่แก้ผ่าน
- MSSQL จริง: AN ตัวอย่างคืนยา 5 แถว; ประวัติ 1–21 ตุลาคม 2026 คืน 789 แถว/18 คอลัมน์
- API PDF กับ MSSQL จริงตอบ 200 application/pdf โดยไม่เก็บ PDF ผู้ป่วยลงดิสก์
- Browser: เปิดจาก Report > ADR ได้, ยาตัวอย่าง 5 แถว, ปุ่ม PDF เปิดใช้งาน,
  เปลี่ยน AN แล้วซ่อนข้อมูล/ปิด PDF เก่า และค้นไม่พบแสดงสถานะถูกต้อง
- PDF ตัวอย่างใช้ข้อมูลสมมติ: ภาษาไทย, แบบฟอร์ม A4, ตารางประวัติครบ 18 คอลัมน์
  และรายงาน 24 รายการแบ่ง 2 หน้าโดยรายการครบ; ตรวจภาพเรนเดอร์แล้ว
- ยังไม่ deploy ขึ้นเซิร์ฟเวอร์โรงพยาบาลจากการทำงานรอบนี้
