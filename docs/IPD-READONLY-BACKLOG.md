# Checklist งานเว็บ IPD แบบดูข้อมูล

อัปเดต 20 ต.ค. 2026: แก้ครบ 6 จุดจากการตรวจล่าสุดแล้ว (รายการสั่งยา, Medical Reconcile, คอลัมน์ Medication Profile, LAB/Note DRP ด้านขวา และซ่อนวันจำหน่ายในตารางผู้ป่วย) ใช้ [สถานะและหลักฐานล่าสุด](IPD-READONLY-STATUS-2026-10-20.md) แยกงานที่แก้แล้วกับการรอข้อมูลจริง อย่านับ checkbox เก่าที่ไม่ติ๊กเป็นงานเขียนหน้าใหม่ MySQL ไม่ได้ทดสอบข้อมูลจริงตามคำขอรอบนี้

อัปเดต 19 ต.ค. 2026: แยกคอลัมน์/ลำดับ/ค่าในตาราง Screening ครบ 8 โหมดตาม Designer และ Rows.Add ของ native เพิ่มแถวเวลาสำหรับการแสดงผลอย่างเดียวแล้ว ดู [ตารางเทียบและผลตรวจ](IPD-SCREENING-NATIVE-COLUMNS.md) ซึ่งแทนข้อจำกัดการแสดงแถวเวลาในบันทึกเฟสก่อน

อัปเดต 19 ต.ค. 2026: แก้ตารางหอกระพริบ/โหลดซ้ำตอนเลือกหอครั้งแรกครบ 8 โหมด Screening แล้ว โดยคงการจำรอบใน URL และการโหลดใหม่เมื่อเปลี่ยนตัวกรอง ดู [สาเหตุและผลตรวจ](IPD-SCREENING-FIRST-WARD-LOAD.md)

อ้างอิง [ผลตรวจและรายละเอียด source](IPD-READONLY-GAP-ANALYSIS.md) วันที่ 18 ตุลาคม 2026

อัปเดต 19 ต.ค. 2026: ข้อมูลด้านบนและ Medication Profile เพิ่ม ANC/Protocol, การเลือก LAB ล่าสุดและสูตรแสดงผลตาม native, คอลัมน์/สี/สถานะใบยา/ใบอนุมัติ และ batch lookup แล้ว ดู [ผลเทียบล่าสุด](IPD-PROFILE-PARITY.md); P02/P04/P06 เหลือการตรวจรับข้อมูลจริงทุกกรณี โดยเฉพาะ DUE Online

ข้อที่ยังไม่ติ๊กเป็น **งานที่ยังต้องทำ/ตรวจรับ** รหัสใช้ติดตามงานได้โดยไม่ต้องสร้างหน้าใหม่หนึ่งหน้าต่อหนึ่งข้อ P0 = ข้อมูล/บริบทถูกต้องก่อน, P1 = เส้นทางหลัก, P2 = รายละเอียดเสริม ดู [ผลดำเนินการ Login/IPD เฟสแรก](LOGIN-IPD-IMPLEMENTATION.md) สำหรับขอบเขตและหลักฐาน ไม่ถือว่าทั้งระบบเสร็จจากการเปิดเส้นทางใหม่

**MySQL ทุกส่วน:** ผู้ใช้ให้เตรียมโค้ดไว้ก่อน เพราะต้องใช้เครือข่ายภายในโรงพยาบาล งานตรวจข้อมูลจริงให้ทดสอบเมื่อ backend เข้าถึงเครือข่ายนั้น ไม่หยุดพัฒนาหรือถอดฟังก์ชันเพราะ timeout จากภายนอก ดู [ข้อกำหนดการเชื่อมต่อ](DATABASE-CONNECTIVITY.md)

## A. Login และขอบเขตห้องยา/วอร์ด

- [x] **L01 · P0 · แก้ V01** อ่านรายการห้องยาจริงจาก `ms_room`; เลิกใช้ “ห้องที่ 1/2” คงที่ และเลือกค่าใช้งานจริงก่อนเข้าสู่ระบบ
- [ ] **L02 · P0 · เพิ่ม V02** ตามคำขอล่าสุด เลือกเฉพาะห้องยาที่ login และเลือกวอร์ดจริงในหน้า IPD (ทำแล้วในเฟสแรก); ยังรอกติกาตัวเลือกทุกวอร์ดและสิทธิ์รายบัญชี ไม่สมมติ ACL จาก master ผู้ใช้
- [ ] **L03 · P0 · แก้ session** ส่งและ validate บริบทห้องยา/วอร์ดที่ backend; คืนผู้ใช้ ชื่อ ตำแหน่ง และขอบเขตอ่านที่อนุญาต
- [ ] **L04 · P0 · แก้ API** ตรวจ token และขอบเขตในทุก data endpoint รวมการเปิดผู้ป่วย/ใบสั่งยา/ภาพด้วยรหัสโดยตรง ไม่ตรวจเพียง route บน frontend
- [ ] **L05 · P0 · แก้การนำทาง** หลัง login เข้า IPD ที่บริบทเลือกไว้; Refresh และแท็บใหม่ทำแล้วในเฟสแรก ส่วนกลับจากรายละเอียดและหน้าอื่นยังรอเชื่อม
- [x] **L06 · P1 · แก้ header/footer** แสดงผู้ใช้/ตำแหน่ง/ห้องยาจาก session และวอร์ดที่เลือกในหน้าทำงาน; ออกจากระบบล้างข้อมูลและ cache ของผู้ใช้เดิม
- [x] **L07 · P0 · แยกรุ่นอ่าน** ถอดการสมัครผู้ใช้/ปุ่มเปลี่ยนข้อมูลจาก viewer และกำหนด endpoint ฝั่ง server ที่อ่านอย่างเดียว ไม่คัดลอกการ update ห้องตาม computername ของ Windows
