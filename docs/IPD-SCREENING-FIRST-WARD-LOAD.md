# แก้ตารางหอกระพริบตอนเลือกครั้งแรก — 19 ตุลาคม 2026

## สาเหตุ

หน้า Screening เข้าครั้งแรกโดยยังไม่มี `workdate` ใน URL หลังโหลดหอ server จะคืนรอบยาที่ใช้จริงใน `window.workdate` เมื่อเลือกหอครั้งแรก `chooseWard()` เพิ่มรอบนี้ใน URL เพื่อให้รอบยาไม่เปลี่ยนระหว่างเลือกหรือกลับจากรายละเอียดผู้ป่วย

ตัวโหลดเดิมใช้ JSON ของ parameters เป็น request key จึงมองการเพิ่ม `workdate` เป็นคำขอใหม่ ล้างข้อมูลหอและแสดง loading ทำให้ตารางหอหายชั่วคราว ทั้งที่ filter และรอบจริงไม่ได้เปลี่ยน ครั้งถัดไปมี workdate แล้วจึงไม่เกิดซ้ำ

## การแก้

- ใช้ `useScreeningWards` เฉพาะรายการหอของ Screening ทั้ง 8 โหมด ไม่เปลี่ยนตัวโหลดกลางของหน้าประวัติหรือรายละเอียดผู้ป่วย
- เมื่อ URL เพิ่มรอบเดียวกับที่ server คืนมา และ mode/date/room/search/status/type/refresh เดิม ให้ใช้ response หอเดิม จึงคงตาราง จำนวน และตำแหน่งเลื่อน ไม่ส่งคำขอหอซ้ำ
- ยังคงบันทึกรอบใน URL เพื่อรักษารอบ 08:00 และกติกาแต่ละหน้าตามต้นฉบับ ไม่เดารอบด้วยนาฬิกาฝั่ง browser
- เปลี่ยนหอจะอ่านเฉพาะใบ/ยาในหอใหม่ ล้างใบ/ยาเก่าตาม key เดิม
- เปลี่ยนตัวกรองหรือ workdate คนละรอบ และกดโหลดใหม่ จะอ่านข้อมูลใหม่ ไม่ใช้ response ของบริบทเดิม
- คง abort และการตรวจ request key เพื่อไม่แสดง response เก่าหลังเปลี่ยนตัวกรอง เก็บเพียง response ล่าสุดในหน่วยความจำของ component ไม่ใช้ localStorage หรือ cache ข้ามผู้ใช้

## ผลตรวจ

- Tests รวม 131 กรณีผ่าน เพิ่มการ pin รอบเดิมทั้ง 8 โหมด, วันข้ามปี/ก่อน 08:00, ตัวกรองต่างกัน, round ต่างกันและ refresh ใหม่ รวมถึงลำดับ fields ของ query
- Frontend build และ ESLint ไฟล์ที่เปลี่ยนผ่าน
- Browser ข้อมูลสมมติหน่วง response 350 ms: ทดสอบเลือกหอครั้งแรกครบ 8 โหมด ตารางหอยัง visible และจำนวนคำขอ wards ไม่เพิ่ม แต่ตารางใบโหลดตามหอได้
- Browser ตรวจเปลี่ยนห้องและวันที่แล้วมีคำขอใหม่ กดโหลดใหม่เพิ่มคำขอหอหนึ่งครั้ง และเลือกหอถัดไปไม่เพิ่มคำขอหอ
- ใช้แหล่งข้อมูล/SQL/ยอดเดิม ไม่เพิ่มการเขียนข้อมูลหรือคำสั่งฮาร์ดแวร์ และไม่ต้องเปลี่ยน backend
