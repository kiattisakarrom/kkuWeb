# คอลัมน์และค่าที่แสดงของ Screening — 19 ตุลาคม 2026

เทียบ `ucScreenning`, `ucScreenTakeHome`, `ucScreenAll`, `ucScreenSendRobot` ทั้ง Designer และ Rows.Add ใน source Windows ที่ผู้ใช้ให้มา ไม่รวมหน้าใบสั่งยาที่มีภาพและหน้ารายการยามีปัญหาที่เลิกใช้แล้ว

## ตารางที่แสดง

ทุกหน้าคงกรอบเดิมและหอด้านซ้าย: ช่องเลือก (disabled), หอผู้ป่วย, จำนวน ชื่อหอใช้ `[ รหัส ]ชื่อ` ตาม source

| หน้า | หัวใบที่มองเห็นตามลำดับ (ถัดจากช่องเลือก) | ตารางยา |
|---|---|---|
| Stat รอจัด / จัดแล้ว, Continue รอ Screen / Screen แล้ว | วันที่, ประเภท, ใบสั่งยา, HN, AN, ชื่อ - นามสกุล, หอผู้ป่วย, STS, สถานะใบสั่งยา, ห้อง | วันที่กินยา, เวลารับประทาน, รหัสยา, ชื่อยา, Dose, QTY, รหัสวิธีใช้, คำอธิบายวิธีใช้, ที่เก็บยา, Print, ห้อง |
| ยากลับบ้านรอจัด / จัดแล้ว | วันที่, ประเภท, ใบสั่งยา, HN, AN, ชื่อ - นามสกุล, หอผู้ป่วย, STS, สถานะใบสั่งยา | เวลารับประทาน, รหัสยา, ชื่อยา, Dose, QTY, รหัสวิธีใช้, คำอธิบายวิธีใช้, STS, ที่เก็บยา, Print |
| รอส่ง Robot | วันที่, ประเภท, ใบสั่งยา, HN, AN, ชื่อ - นามสกุล, หอผู้ป่วย, STS, สถานะใบสั่งยา | ไม่มี ตามต้นฉบับสองตาราง |
| รอ Screen ทั้งหมด | ใบสั่งยา, วันที่, ประเภท, HN, AN, ชื่อ - นามสกุล, หอผู้ป่วย, สถานะใบสั่งยา | ไม่มีตารางยา; ตะกร้าสร้างชุดส่งไม่อยู่ในรุ่นอ่าน |

ตารางยามีช่องเลือกแบบ disabled นำหน้าเหมือน Designer ไม่ใช้ช่องเลือกนี้สั่งงาน การเลือกหอ/ใบผ่านแถวและปุ่มชื่อยังทำงานตามเดิม

เอาคอลัมน์ที่ native ซ่อนออกจากจอ เช่น เตียง วันที่ Screen, seq, itemindex, หมายเหตุ/ความถี่/หน่วย/รหัสเทคนิคส่วนเกิน แต่ข้อมูล API/คีย์ที่ใช้เปิดผู้ป่วยและกลับหน้ายังคงอยู่

## Mapping ที่ต้องตรงกับ source

- วันที่หัวใบ = วันที่ ordercreatedate; ประเภท = ordertype ตามที่บันทึก ไม่แปลชื่อกลุ่มขึ้นเอง
- STS ที่ source ใส่ข้อความว่างยังเว้นว่าง ไม่ใช้ statuscode หรือวันที่แทน
- สถานะใบ = genorderdatetime มี/ไม่มี → Screen แล้ว/รอ Screen; Robot ใช้ genOCSdatetime แบบเดียวกับ Rows.Add จึงแสดง “รอ Screen” ในคิวรอส่ง ไม่เปลี่ยนเป็นข้อความสถานะที่ต้นฉบับไม่ได้ใส่
- รหัสวิธีใช้ในตารางยา = timecode; คำอธิบาย = freetext2 ไม่ใช้ frequencycode/frequencydesc แทน แม้ชื่อคอลัมน์จะชวนให้เข้าใจอีกแบบ
- Dose = dosage หรือ varymeal เฉพาะเวลาที่ตรงกันตาม native; QTY = จำนวนรวมที่บันทึกใน prescription ซ้ำในแต่ละแถวที่แสดง ไม่หารเป็นจำนวนต่อซอง
- ห้อง = fromlocationname เฉพาะกรอบที่ native แสดง คอลัมน์ที่ซ่อนหรือไม่มีในหน้ากลับบ้าน/Robot/All ไม่เพิ่มขึ้นเอง
- Print เป็น checkbox แสดงค่าที่ native เตรียมในหน้าจอจาก location/unused/sendmachine/AW/sendmix/printstatus จึงอาจต่างจาก raw printstatus; ทุก checkbox disabled ไม่มีการส่งพิมพ์
- หัวใบที่ Screen แล้วใช้สีเขียวอ่อนในทุกหน้าตาม native; แถวที่เลือกยังใช้สีเลือกเดิม ช่องว่างเป็นช่องว่างและค่าศูนย์ยังแสดง 0

## แถวเวลาของตารางยา (แสดงผลอย่างเดียว)

`ipdScreeningDisplay.js` จำลองเฉพาะ ShowPrescriptiondetail ก่อน event ส่ง/พิมพ์ ไม่ generate งานจริง และคืน `displayItems` แยกจาก `items` ดิบ

- รายการจัดมือ: ใช้ freetext1 และค่าที่บันทึกหนึ่งแถว; location จาก master หรือจัดมือ, ส่งผลิตใช้ค่าต้นฉบับ “ส่งผลิด”
- JVM PRN: ข้อความ `[ PRN ] timedesc` และจำนวนแถวตามลูป `0..qty-dose` ของต้นฉบับ; time-master timetype=2 แสดง PRN หนึ่งแถว
- JVM ทั่วไป: อ่าน ms_time/ms_timedetail ครั้งเดียวแบบ batch เฉพาะรหัสในใบ ไม่ query ต่อรายการ แล้วใช้ยอดสะสม dose/qty, varymeal/varymealtime ตาม source
- Stat/Continue ใช้วันปัจจุบันเวลาไทยและเกณฑ์เวลา 14:59 / OD / E24 ตาม native รวมถึงวันกินยาที่บันทึกและ time-wrap ในกิ่ง statustimeend; หน้ากลับบ้านไม่มีกิ่งแปลงวันแบบนี้และซ่อนวันที่กินยา
- คงตัวแปรวันที่ระหว่างแถวเหมือน source และเรียงตามเวลา/วันที่ของตาราง ไม่ตีความวันที่ที่แสดงว่าเป็นหลักฐานการให้ยา
- ไม่มี time master ของ JVM จะไม่มีแถวนั้นตาม native; หากข้อมูลจำนวน/เวลาที่ต้นฉบับต้องใช้มีรูปแบบผิด แสดงข้อผิดพลาดแทนการเดาค่า การแสดงเกิน 20,000 แถวไม่ตัดข้อมูลเงียบ

ส่วนนี้แทนข้อจำกัด “ยังไม่แตกแถวเวลา” ในเอกสารเฟสก่อนเฉพาะการแสดงผล ห้ามนำ displayItems ไปส่งเครื่อง/บันทึก/พิมพ์ ไม่เปลี่ยน SQL criteria ของยอดหอ/ใบ/ยา รวมการแก้ยอดหอ Continue จัดแล้วและการเลือกหอครั้งแรกไม่กระพริบก่อนหน้านี้
