# แก้การเลือกจำนวนหอ/เปิดรายละเอียดผู้ป่วย และถอดใบเบิก ER (OPD)

- ถอดเมนู/variant/หน้ารายงาน/API/repository/flag ตัวอย่างของใบเบิก ER (OPD) ลิงก์เก่ากลับ IPD และ API เก่าปิดด้วย 403 ไม่อ่านฐาน ลบตัวทดสอบ/สคริปต์ PDF ที่ใช้เฉพาะรายงานที่เลิกใช้
- ย้ายส่วนกลาง OPD ที่ OPDRAD ยังต้องใช้เป็น reportRequisitionOpd.js และ opdRequisitionRoutes.js ไม่แตะ OPD42 หรือส่วน MySQL ของรายงาน ER แบบรวม
- IPD: เดิมช่องจำนวนเป็นข้อความ ไม่มี event จึงเลือกหอไม่ได้ เพิ่มปุ่มจำนวนเต็มช่องพร้อม aria-label/aria-pressed และเลือกหอจากแถวได้
- Screening: เดิมจำนวนอาศัย event bubbling ของแถว เพิ่มปุ่มตัวเลขโดยตรง ใช้ chooseWard เดิมครบ 8 โหมด ไม่แก้เงื่อนไข/ยอด/ช่วงเวลา/ห้องยา
- เพิ่ม PatientOpenButton เป็นปุ่ม native ที่ชื่อผู้ป่วยใน IPD/Screening/Quick Order กดครั้งเดียวเปิดได้บน touch/เมาส์/คีย์บอร์ด ไม่พึ่ง dblclick และหยุด event ของแถวไม่ให้เลือกใบหรือเปิดซ้ำ
- คงดับเบิลคลิกแถวบน desktop และ Enter ของแถว IPD พร้อมสีแสดงแถวที่เลือก
- หน้ารายละเอียดคงฟอร์มขั้นต่ำ 960px และ main เลื่อนแนวนอนได้บนจอเล็ก เพื่อไม่บีบกริดข้อมูลจนทับกัน ไม่เปลี่ยนฟิลด์หรือข้อมูลผู้ป่วย

## ผลตรวจ

- Backend regression 288/288 ผ่าน รวม OPDRAD และการปิด API รายงานที่เลิกใช้ ไม่มีการเชื่อม MySQL หรือแก้ข้อมูลจริง
- Targeted frontend ESLint / production build ผ่าน
- Browser ใช้ข้อมูลจำลอง แสดงผู้ป่วยด้านขวาตามหอเมื่อกดจำนวนใน IPD และครบ 8 โหมด Screening ตรวจหออื่นไม่ปะปน
- ทดสอบกดชื่อครั้งเดียวเปิดรายละเอียดพร้อม AN/ward และบริบทกลับ Screening ถูกต้อง
- ใช้ iframe ของแอป production จริงที่ viewport 390px ตรวจช่องจำนวนและเปิดรายละเอียด IPD/Screening เป็นการจำลองขนาดจอและทดสอบปุ่มผ่านเบราว์เซอร์ ไม่ใช่การทดสอบบนโทรศัพท์จริง
- ทดสอบ Quick Order ที่ 390px กดชื่อครั้งเดียวเปิด AN/ward ถูกต้องและคงบริบทกลับหน้าเดิม ตรวจดับเบิลคลิกแถว IPD บน desktop และ Enter ของปุ่มจำนวน/ชื่อผู้ป่วยผ่าน
- ตรวจเมนูไม่มี ER (OPD) ขณะที่ OPD อาคารรังสียังอยู่ ลิงก์เก่าของรายงานที่ถอดกลับ IPD ตามต้องการ
- มี `tools/preview-interaction-fixes.cjs` สำหรับทดสอบซ้ำเฉพาะ localhost ด้วยผู้ป่วยจำลอง ไม่มี database imports

ทำใน local ไม่มี commit/deploy และไม่เปลี่ยนฐานข้อมูล

## ปรับรายการผู้ป่วย 24 ตุลาคม 2026

- ถอดปุ่ม “ดูรายละเอียดผู้ป่วย” แยกจากแถบเครื่องมือ IPD และ Screening ตามคำขอ
- คืนความสูงแถวเดิมโดยเอา `min-h-9` ออกจากปุ่มชื่อผู้ป่วยและปุ่มเลือกของตาราง Screening
- ช่องชื่อ–นามสกุลใน IPD/Screening/Quick Order เป็นปุ่มเต็มช่อง โดยย้าย padding เดิมของเซลล์มาไว้ที่ปุ่ม จึงกดพื้นที่ว่างในช่องได้โดยไม่เพิ่มความสูงแถว
- ยังคงเปิดด้วยแตะ/คลิกชื่อครั้งเดียวหรือดับเบิลคลิกแถว และเลือกหอด้วยช่องจำนวนได้
- ตรวจ ESLint และ production build ผ่าน ทดสอบด้วยข้อมูลจำลอง: แถว IPD จาก 52.67px เหลือ 32.67px, Screening 29px, ไม่มีปุ่มรายละเอียดแยก, คลิกชื่อเปิด AN/ward ถูกต้องทั้ง IPD/Screening, ดับเบิลคลิกแถว IPD ได้ และที่ viewport 390px แตะชื่อครั้งเดียวเปิดรายละเอียดได้

## เส้นใต้และการเปิดรายการ Check out 24 ตุลาคม 2026

- เหลือเส้นใต้เฉพาะช่องชื่อ–นามสกุลที่เปิดรายละเอียดใน IPD/Screening/Quick Order/Check out ถอดจากช่องเลือกหอ จำนวน ใบสั่งยา และปุ่มข้อความอื่นในหน้าเหล่านี้
- Check out ใช้ PatientOpenButton เต็มช่องชื่อและ padding เดิม เปิดรายละเอียด Check out ของใบเดิมได้ด้วยคลิก/แตะครั้งเดียวหรือคีย์บอร์ด และยังดับเบิลคลิกแถวได้ เลขใบสั่งยาเป็นข้อความธรรมดา
- Targeted ESLint และ production build ผ่าน ตรวจข้อมูลจำลองแล้ว Screening มีเส้นใต้เฉพาะชื่อ แถว 29px และเลือกเลขใบเพื่อดูรายการยาได้ตามเดิม; Check out แถว 33px มีเส้นใต้เฉพาะชื่อ เปิดรายละเอียดถูก AN/ใบด้วยคลิกชื่อหรือดับเบิลคลิกแถว และแตะชื่อที่ viewport 390px เปิดได้
- ขยาย preview-interaction-fixes.cjs ด้วย repository จำลองของ Check out ไม่มีการเชื่อมฐานข้อมูลจริง
