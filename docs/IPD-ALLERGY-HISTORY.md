# ประวัติ ADR / แพ้ยาแบบดูข้อมูล — ปรับคอลัมน์ 19 ตุลาคม 2026

เปิดจากปุ่มดูประวัติแพ้ยาทั้งหมดในกรอบรายละเอียดผู้ป่วยเดิม คง toolbar/กรอบผู้ป่วย/แท็บประกอบและโครงซ้าย–ขวาเดิม ปรับเฉพาะรายการทางซ้ายเป็นตารางประวัติและรายละเอียดอ่านอย่างเดียวทางขวา ไม่เปิดหน้าต่างเตือนที่ทำให้บันทึกประวัติใช้ยา

## หน้าต้นฉบับที่ใช้เทียบ

ใช้ **Patient/ucPatientADR** กรอบประวัติแพ้ยา dgvDetailADR และฟอร์มเมื่อเลือกแถว อ้างอิง Patient/class/clsPatient.get_admitSelect และ ucPatientADR.showGeneric/dgvDetailADR_CellClick

ไม่ใช้หน้ารายงานรวม ctx/ADR/ucADRHistory ที่ค้นหลายผู้ป่วย/Export และมีการเปลี่ยนปีในรายงานเก่าให้เป็นปีปัจจุบัน ไม่เปลี่ยนปีจริงของเหตุการณ์ในหน้าอ่านประวัติผู้ป่วยนี้

## คอลัมน์และข้อมูล

แสดง 14 คอลัมน์ตาม Designer เรียงดังนี้:

1. วันที่ลงข้อมูลในโปรแกรมเก่า — createdate
2. Type of ADR — typeofadr ดิบ
3. ข้อมูลประวัติแพ้ยา — destination
4. รายการยาที่เกิด — AllergyGroupNm (API ใช้ allergyGroup)
5. วันที่เกิด ADR (เลือกปฏิทิน) — startadrddatetime
6. ข้อมูลอาการไม่พึงประสงค์ — adversereactions
7. Pharmacist note — pharmacistnote
8. Onset of ADR — onsetofadr
9. หน่วยของ Onset — unitonset
10. Naranjo's score — naranjoscore
11. Propability — propability
12. Policy — policy
13. เภสัชผู้ประเมิน — pharmacyname
14. ผู้บันทึกข้อมูล — username

- คอลัมน์ซ่อนของ Windows เช่น adrcode, timestamp, HN, ชื่อผู้ป่วย, รหัสกลุ่ม, รหัสเภสัช และรหัสผู้บันทึกไม่แสดงเป็นคอลัมน์เพิ่ม adrcode ยังใช้เลือกแถวใน URL/API ได้
- วันที่ใช้ **d-MM-yyyy แบบ พ.ศ.** ตาม FORMAT(...,'d-MM-yyyy','TH-th') ของ get_admitSelect ไม่เพิ่มเวลา ไม่เปลี่ยนปีเก่าเป็นปีปัจจุบัน
- createdate บางรายการในฐานจริงเป็นข้อความ yyyy-MM-dd HH:mm:ss จึงอ่านส่วนวันปฏิทินก่อนจัดรูปแบบ ไม่ parse เป็นเวลาท้องถิ่นแล้วแปลง UTC ซึ่งจะทำให้เที่ยงคืนเลื่อนเป็นวันก่อนหน้า
- Type of ADR แสดง typeofadr ตามที่บันทึก ไม่แทนด้วยข้อความสรุป Type A/B ที่ใช้ในกรอบเตือนด้านบน ไม่เพิ่มข้อความไม่ระบุชนิดลงข้อมูลที่ว่าง
- รายการยาที่เกิดใช้ชื่อกลุ่มที่บันทึกจริง ไม่แทนคอลัมน์นี้ด้วย generic หรือชื่อ master ปัจจุบันหากชื่อกลุ่มว่าง
- แยก Onset/หน่วยเป็นคนละคอลัมน์ คงคะแนน 0 และค่าอื่นทุกช่อง ไม่ปัดเศษ/คำนวณ Naranjo/แปลความน่าจะเป็นใหม่ ค่าว่าง/null แสดงว่าง ไม่ใส่ขีดหรือ placeholder
- ทางขวาใช้ input/textarea readOnly สำหรับข้อมูลทั้ง 14 ช่อง อาการ/Pharmacist note/Policy อ่านข้อความหลายบรรทัดเต็มตามที่บันทึก
- **Generic Name** แสดงชื่อยารายตัวจาก ms_adrgeneric ของ adrcode ที่เลือกในตารางเดียวตาม showGeneric ไม่มีปุ่มลบหรือ flg ของงานสร้างรายการ
- ไม่นำสมาชิกกลุ่มจาก master ปัจจุบันมาแสดงเป็น Generic Name ที่บันทึกในเหตุการณ์ master groupIngredients ยังอยู่ใน response/สรุปด้านบนเดิม แต่ไม่ได้เพิ่มคอลัมน์/textarea ในหน้าประวัตินี้
- คงพื้นที่รายการซ้าย 32% และรายละเอียดขวาเดิม ตารางซ้ายเลื่อนแนวนอนเพื่อดู 14 ช่องได้ ค่าเริ่มความกว้าง 100px ต่อช่องตาม Designer; เลือกทั้งแถวหรือปุ่มวันที่ได้โดยไม่เรียกฐานข้อมูลเพิ่ม

## แหล่งข้อมูลและ MySQL

ส่วนอ่านประวัตินี้ใช้ **MSSQL** ms_adr, ms_adrgeneric, ms_allergygroupdetail, ms_ingredient ตามต้นฉบับ ไม่ต้องเพิ่ม MySQL ในเส้นทางนี้ โค้ด MySQL ที่เตรียมไว้ในส่วนอื่นยังคงเดิมตาม [DATABASE-CONNECTIVITY.md](DATABASE-CONNECTIVITY.md)

ใช้ประวัติ HN จาก admission ที่ backend ตรวจแล้ว รวมครั้งก่อน ไม่จำกัด AN/วอร์ดที่เคยบันทึกหรือวันรอบยา คงหนึ่งรายการต่อ adrcode แม้หลายเหตุการณ์ใช้กลุ่มเดียวกัน ไม่ทำ Cartesian join ยารายตัว/สมาชิกกลุ่ม และไม่ทำซ้ำ/ตัดข้อความตามบัคของ showadr สรุปเดิม

ms_adrhistory เป็นบันทึกเหตุการณ์เมื่อคีย์ยา/ยืนยันเหตุผลใช้ยา ไม่ใช้สร้างรายการแพ้ยาใหม่ และไม่เรียก frmMessageADR/frmADRnote ที่เขียนตารางนั้น

## API และการโหลด

GET /api/ipd/patients/:an/allergies?wardCode=...&orderdate=... คง JWT/ห้องยา/current AN/active ward ใช้ HN ที่ backend resolve ไม่รับ HN override ปิด write methods ไม่มี import/save/delete/print/hardware

คง SQL batch เดิม 3 SELECT ในคำขอเดียว: บันทึก ADR, ยารายตัวที่บันทึก และสมาชิกกลุ่มที่เกี่ยวข้อง ทั้งสามใช้ parameter HN ไม่มี query ต่อแถว/master จาก browser ไม่เปลี่ยน schema/index

หน้าประวัติและสรุปด้านบนใช้ response เดียวกัน ไม่มีต้นทางซ้ำเมื่อเปิดประวัติ การเปลี่ยนรูปแบบ Type/วันที่ทำเฉพาะหน้าประวัติ ไม่เปลี่ยน allergySummaryText หรือการแปลข้อความเตือนด้านบน เลือก adrId ได้เฉพาะในแถวที่โหลดมาของผู้ป่วยนี้ จดจำการเลือกเมื่อสลับหน้ากลับมา

คงเรียงวันเกิดอาการล่าสุดก่อนแล้ววันบันทึก/รหัส; get_admitSelect เดิมไม่มี ORDER BY จึงไม่รับประกันลำดับ SQL เดิมระหว่างบันทึกเท่ากัน ข้อผิดพลาดไม่แทนด้วยข้อมูลว่าง รายละเอียดเก่าถูกซ่อนขณะโหลด/error ผลสำเร็จว่างแสดงไม่พบประวัติในฐานข้อมูลนี้ ไม่สรุปว่าผู้ป่วยไม่แพ้ยา

## ผลตรวจรอบนี้

- ชุดทดสอบ **153 กรณีผ่าน** รวม HN scopes/label precedence/หลายยา/หลายเหตุการณ์กลุ่มเดียวกัน/null/0/ข้อความยาว/response ผิด/API สิทธิ์/ปิด mutation เดิม และเพิ่ม 14 คอลัมน์ native, raw typeofadr, Onset แยกหน่วย, พ.ศ./leap day/ประวัติเก่า และวันที่ข้อความ SQL เที่ยงคืนไม่เลื่อนวัน
- Production build และ ESLint ไฟล์ที่แก้ผ่าน
- MSSQL จริง: ตัวอย่างยารายตัวมี 3 บันทึกและกลุ่มยามี 1 บันทึก เทียบ **ทั้ง 14 ช่อง** กับ SQL get_admitSelect รวม FORMAT วันที่ TH-th แล้วตรงครบ จำนวนแถวเท่ากัน รายชื่อ generic ตรงทั้งหมด รอบตัวอย่าง 128ms/50ms ไม่ใช่ SLA
- พบและแก้ createdate แบบข้อความที่การ parse เดิมเลื่อนวันก่อนหน้า จากนั้นเทียบซ้ำทั้งสองชุดได้ sameFields=true และ sameGenerics=true ไม่แสดงข้อมูลสุขภาพจริงหรือ HN ในหลักฐาน
- Browser fixture สมมติ 3 เหตุการณ์: ตารางครบ 14 ช่อง มีเหตุการณ์กลุ่มเดียวกันแยกแถว แสดง Type ดิบ วันที่ พ.ศ. และปีเก่าตามจริง คะแนน 0 ต่างจากช่องว่าง
- Generic Name แสดงเฉพาะรายการที่บันทึก ไม่แสดงข้อมูลทดสอบ HIDDEN จาก group master/รหัส/lastmodify ช่อง input/textarea ทุกช่อง readOnly อาการยาว 935 ตัวอักษรมีส่วนท้ายครบ
- เลือกแถวว่างล้างอาการ/คะแนน/บันทึกเดิม ไม่มี placeholder; กรณีไม่มีประวัติแยกจาก error และกดลองใหม่กลับมาอ่านได้

ผลตรวจเป็นการเทียบ source และตัวอย่างจากฐานจริง ไม่ใช่การเปิด Windows เทียบภาพสดทุกผู้ป่วย ภาพหน้าจอทั้งหมดเป็นข้อมูลสมมติ ไม่มีการเขียนข้อมูลธุรกิจหรือ commit/push
