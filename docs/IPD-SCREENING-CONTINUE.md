# Screening — ยารอ Screen และส่งจัดยา (Continue รอจัด)

วันที่ตรวจ 18 ตุลาคม 2026 อ้างอิง Windows `Screenning/ucScreenning.vb` กิ่ง `btnContinue` ใน `Showward` (~297), `ShowPrescriptionHeader` (~545), `ShowPrescriptiondetail` (~1043), `clsPrescription.getgroupWard/getPresHeader`, `clspackagemaster.getForgenorder` และ `ClsUsers.getRoom`

สถานะต่อยอด: เพิ่ม [Continue จัดแล้ว](IPD-SCREENING-CONTINUE-FINISHED.md) แล้ว รายงานผลด้านล่างเป็นหลักฐานของเฟส Continue รอจัด

## การใช้งานและขอบเขต

เมนู ห้องยา IPD → Screening → **ยารอ Screen และส่งจัดยา** ใช้ `mode=continue-wait` ภายในกรอบเดิม วอร์ดซ้าย → ใบสั่งยาบน → รายการยาล่าง และตัวเลือกห้องยาจริงทุกห้องจาก `ms_room` แบบเดียวกับ Stat เริ่มด้วยห้อง login แต่เปลี่ยนห้องใน Screening ได้โดยไม่เปลี่ยน session ห้องหลัก

เลือกวันที่ ค้น AN/HN/เลขใบแบบตรงกันข้ามทุกวอร์ดในห้องที่เลือก เลือกวอร์ด/ใบเพื่อดูข้อมูล คงรอบที่ backend คำนวณระหว่างเลือก เปลี่ยนห้อง/โหมด/วันที่/ค้นหาแล้วซ่อนรายการเดิมและยกเลิกคำขอเก่า แยกโหลด/ไม่มีรายการ/ผิดพลาดพร้อมลองใหม่

ตารางแสดงค่าจริงที่บันทึก: ยา ขนาด จำนวน หน่วย ความถี่ เวลา วิธีใช้ ข้อความ/หมายเหตุ วอร์ด เตียง แพทย์ ผู้บันทึก และสถานะต่าง ๆ รวม Off/Hold และค่าศูนย์ ดับเบิลคลิกใบเปิด patient view ด้วย AN และวอร์ดปัจจุบันที่ backend ตรวจ กลับมาคงห้อง/โหมด/วันที่/รอบ/คำค้น/วอร์ดของใบ/เลขใบเดิม

ปุ่ม Screen/ส่งจัด/ยกเลิก/พิมพ์/ส่งเครื่องยังปิด และ server ไม่เปิด mutation หรือ hardware route ชื่อโหมดหมายถึงคิวที่รอดำเนินการ ไม่สั่งส่งจัดยาเมื่อเปิดดู ไม่ใช้ MySQL เพราะเส้นทางนี้ในต้นฉบับอ่าน MSSQL

## เงื่อนไขตาม Windows

| ระดับ | เงื่อนไข |
| --- | --- |
| วอร์ด | `genorderdatetime IS NULL`, `ISNULL(frequencycode,'') NOT IN ('S','E','STAT')`, `ordertype <> '1'`, ห้องยาจริงและช่วงรอบ; นับ distinct ใบ ไม่บังคับ active ward ในยอดวอร์ด |
| หัวใบ | เงื่อนไขเดียวกัน พร้อมวอร์ดที่เลือกและ `ms_ward.wardstatus='Y'` |
| ยา | gen ว่าง และ non-Stat ของเลขใบ/ช่วงรอบ; เว็บเพิ่มห้อง/วอร์ด/non-home/active ward และ HN/AN จากหัวใบที่ server อ่านเพื่อป้องกันปนข้ามบริบท |

**ความถี่ null หรือว่างอยู่ในกลุ่มนี้ตาม ISNULL ของต้นฉบับ** ไม่บังคับ `prioritycode LIKE '%C%'` ไม่ยก exclusion `%C%` ของ Stat จัดแล้วมาใช้ และไม่กรอง Off/Hold ทิ้ง

ห้องยาตรวจจาก `ms_room` ฝั่ง server และกรอง `fromlocationname = roomname+'['+roomcode+']'` ด้วย SQL parameter ไม่มี HN override จาก client หรือ room name ที่ browser กำหนดเอง

ใช้รอบ 08:00 ตาม [Stat](IPD-SCREENING-STAT.md): ก่อน 08:00 ของกรุงเทพฯ ถอยวันที่เลือกหนึ่งวัน รวมวันย้อนหลัง ยอดวอร์ดถึงวันถัดไป 07:59:00 แต่หัวใบ/ยาถึง 07:59:59 คงความต่างตามต้นฉบับ ส่ง `workdate` ที่คำนวณแล้วไปตารางลูกเพื่อไม่เปลี่ยนรอบกลางทาง

รายละเอียดเป็นแถว `prescription` ที่บันทึกจริงเช่นเดียวกับ Stat ที่ทำก่อนหน้า ไม่เรียกส่วนแตกซอง/สร้างรายการสำหรับเครื่องหรือพิมพ์ จึงไม่อ้างว่าจำนวนแถว/จำนวนต่อซองเท่าตาราง native หลังแตกซอง แสดงปริมาณและข้อความเดิมโดยไม่คำนวณขนาดยาใหม่

## โครงสร้างและ API

ใช้ GET `/api/ipd/screening/options`, `/wards`, `/prescriptions` และ `/prescriptions/:prescriptionno` เดิม เพิ่ม enum `continue-wait` ที่ frontend/backend พร้อมให้ patient return ยอมรับโหมดนี้ คง Stat สองโหมดและปิดโหมดที่ยังไม่ทำ

พารามิเตอร์หลัก `mode`, `roomCode`, `orderdate`, `search`, `workdate`; ตารางลูกเพิ่ม `wardCode` รายละเอียดยาใช้เลขใบจาก URL และตรวจตัวตนจากหัวใบ ไม่รับ query SQL จาก browser ใช้ MSSQL pool ร่วมและอ่าน master ใน query ไม่ทำ HTTP/SQL ต่อแถวยา ไม่ได้เพิ่ม cache ที่ทำให้คิวเก่าถูกใช้แทนการโหลดใหม่

## ผลตรวจ

- **90/90 backend tests ผ่าน**, frontend build และ ESLint ไฟล์ที่เปลี่ยนผ่าน ครอบคลุมโหมดไม่ปน Stat, ห้อง/รอบ/ค้นหาครบทุกระดับ, auth, ข้ามห้อง/วอร์ด/ใบ, ความถี่ null, Off และ 0, แยก empty/503/404, ปิด writes/hardware และกลับจาก patient view
- เทียบฐานจริงกับ manual SQL ของ Windows: ยอด distinct ใบรายวอร์ด **27 วอร์ดตรงกัน**; สุ่ม **3 วอร์ด รวม 9 แถวหัวใบ** และรายละเอียดหนึ่งใบต่อวอร์ดรวม **9 แถวยา** เทียบ key/field หัวใบและ itemindex/รหัสยา/ชื่อ/ขนาด/จำนวน/ความถี่/วัน Off/Hold/ส่งจัด ตรงกัน ไม่บันทึก HN/AN/เลขใบ/ชื่อหรือข้อมูลยาเฉพาะผู้ป่วยลงเอกสารหรือ log
- ทดสอบ regression ฐานจริงของ Stat รอจัด/จัดแล้วซ้ำหลังเพิ่มเงื่อนไข mode แล้ว ทั้งยอดวอร์ด หัวใบ และค่ารายละเอียดยาตัวอย่างยังตรงกัน
- หลัง restart API ทดสอบบัญชีที่ผู้ใช้ให้: Continue 001 ตอบ 200 (27 วอร์ด), ห้อง 002 ตอบ 200 (18 วอร์ด), หัวใบ/รายละเอียดตอบ 200 และรายการตัวอย่างทั้งหมด gen ว่าง/non-Stat/non-home ค้นเลขใบกลับเฉพาะวอร์ดที่ถูกต้อง
- ตัวอย่างเวลารอบนี้ วอร์ด **360 ms**, หัวใบ **148 ms**, รายละเอียดยา **227 ms** เป็นการวัดเฉพาะครั้ง ไม่รับรองทุกช่วงหรือทุกห้อง
- Browser ข้อมูลสมมติ: เปิดปุ่ม Continue ในโครงเดิม เลือกห้อง 001/002 เปลี่ยนวันแล้วใช้รอบใหม่ ค้นใบข้ามวอร์ด/ไม่พบ สลับห้องล้างใบ/ยาเดิม แสดง Hold/Off/0/ความถี่ว่าง และเปิดผู้ป่วย/กลับคงโหมด/ห้อง/วัน/ใบผ่าน ปุ่ม Screen/พิมพ์ตรวจว่า disabled ภาพยืนยันใช้ข้อมูลสมมติทั้งหมด

ยังต้องตรวจรับข้อมูลจริงครบทุกห้องและรูปแบบ master/ข้อความที่หลากหลาย งานแตกแถวเวลาระดับซองยังมีขอบเขตเดียวกับ Stat ส่วน Continue จัดแล้ว/All/Take-home/Robot/ภาพใบสั่งยาเป็นงานถัดไป
