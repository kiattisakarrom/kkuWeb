# Med Transfer viewer — 20 ตุลาคม 2026

เพิ่ม `/ipd/med-transfer` จากเมนูห้องยา IPD → Med Tranfer โดยคงเมนู/ส่วนหัว/ท้ายและโครงสองส่วนเดิม อ้างอิง `frmMain.MedtranferToolStripMenuItem_Click`, `Medtransfer/ucMedtransfer`, `ucWaitMedtransfer`, `ucMedComplete`, Designer และ `Medtransfer/class/clstr_prescription_pharmacy.vb` ในซอร์ส Windows ที่ผู้ใช้ให้มา ไม่รวม Report Med Transfer ที่เป็นอีกเมนู

## ทำแล้ว

- สองหน้า: **บรรจุยาเข้ารถเข็น** (ค่าเริ่มต้น) และ **สถานะบรรจุยาเข้ารถเข็น** ใช้ปุ่ม/ตำแหน่งแบบเดิมและสีเขียวเลือกหน้าตาม Windows เมื่อสลับหน้าเริ่มตัวกรองและการเลือกใหม่ตาม native
- หน้าแรกใช้ฟอร์มผู้ป่วยด้านซ้าย ตารางยาด้านขวา: ตำแหน่งยา / รหัสยา / ชื่อยา / จำนวน / หน่วยขาย / วิธีใช้ / ความถี่ / เวลา รวม 8 คอลัมน์ตาม Designer มีเลื่อนแนวนอนเมื่อจอแคบ
- เปลี่ยนช่องสแกนรถเข็นเป็นตัวเลือกจริงจาก `ms_cart` และช่องรับยาเป็นการระบุเลขใบแล้วกดดูข้อมูล รองรับเลขใบธรรมดาหรือ AN|เลขใบเดิมเพื่ออ่านเท่านั้น ไม่เชื่อมอุปกรณ์ ไม่สแกนยืนยันรับยา
- ช่องยืนยันรับยาและปุ่มยืนยันปิดใช้งาน ปุ่มยกเลิกล้างเฉพาะฟอร์มในเว็บ ไม่มี UPDATE medtransferdatetime/medtransferuserid/cartname และไม่มีการพิมพ์หรือส่งเครื่อง
- ฟอร์มแสดง HN/AN/ชื่อ/วันเกิด/อายุ/หอ/เตียง/สิทธิ์/แพ้ยาตามแหล่งข้อมูลของหน้านี้ ไม่ดึง demographic ชุดอื่นจาก Medication Profile มาทับ
- หน้าสถานะมีตารางหอ 2 คอลัมน์: หอผู้ป่วย / จำนวน; หัวใบ 6 คอลัมน์: ใบสั่งยา / ประเภทใบสั่งยา / HN / AN / ชื่อ - นามสกุล / สถานะ ซ่อนรหัสหอ/หอ/เตียงตาม native มีตัวเลือกยังไม่บรรจุยา (ค่าเริ่มต้น) และบรรจุยาแล้ว
- หน้าสถานะคลิกหอเพื่ออ่านหัวใบ ไม่มีการเปิดรายละเอียดจาก double-click เพราะ `ucMedComplete` ต้นฉบับไม่มี event นี้ ไม่เพิ่มการส่งงานหรือสร้างการบรรจุใหม่
- ทางเข้าจาก IPD / Screening / Quick Order / Check Out ใช้หน้าใหม่นี้ เส้นทางเดิม `/medtranfer/*` และ `/medtransfer` ใช้งานได้ และลิงก์เดิม `/medtranfer/statedoseintocart` เข้าแท็บสถานะ

## เงื่อนไขข้อมูลตรงกับ Windows

- **ทั้งหมดของหน้านี้ใช้ MSSQL** รวม ADR ผ่าน `ucNurseMain.showadr` → `clsShowdata.showDataPatientADR` ไม่พบกิ่ง MySQL ใน entry/control/class ที่ใช้งาน จึงไม่มีการเพิ่มการเชื่อมต่อ MySQL ที่ต้นฉบับไม่ได้ใช้ และไม่ได้เชื่อมต่อหรือทดสอบ MySQL จริง
- รถเข็นตรวจจากชื่อใน `ms_cart` ตาม native ไม่บังคับให้ใบยาเป็นวอร์ดเดียวกับรถเข็น เพราะต้นฉบับไม่ได้ใช้ ward ของรถเข็นกรอง ShowData
- หน้าอ่านใบยาใช้ prescriptionno และ `voiddatetime IS NULL` ไม่มีตัวกรองวัน/ห้องยา/ordertype/medtransfer รอบปัจจุบัน เก็บหนึ่งแถวต่อข้อมูลซองตามต้นฉบับ **ไม่ SUM/รวมยาซ้ำ** เรียง shelfname แล้วใช้ seq/barcode ตัดสินเมื่อ shelf เดียวกัน
- ตรวจทุกซองของเลขใบก่อนอ่าน: ถ้ามี `medtransferdatetime` แล้วแม้เพียงบางแถว (รวม Off) แจ้ง “ใบสั่งยานี้ได้ทำการบรรจุยาเข้ารถเข็นแล้ว” และไม่โหลด Preview ตาม native ถ้ายังมี `checkoutdatetime IS NULL` แจ้งเตือนตาม native แต่ยังอ่านรายการที่ไม่ Off ได้ ไม่ทำ Checkout ให้อัตโนมัติ
- จำนวน NULL/ว่างเป็น 0 ตาม Windows Convert.ToDouble ข้อมูลจำนวนที่อ่านเป็นเลขฐานสิบไม่ได้ไม่ถูกแทนด้วย 0 เงียบ ๆ; วิธีใช้/ความถี่/เวลาใช้รหัสที่บันทึก ไม่เปลี่ยนเป็นคำอธิบาย master
- ชื่อ/วันเกิด/หออ่าน snapshot จาก packagemaster; สิทธิ์ใช้ rightnameTH จาก patient/right; **เตียงแสดง “-” ตาม ShowData แม้ซองจะมี bedcode** สิทธิ์ว่างแสดง “-” ตาม native
- ADR แสดงชื่อ generic หรือกลุ่มยา คั่นด้วย comma และไม่ซ้ำชื่อกลุ่มที่เรียงติดกันตาม `ucNurseMain.showadr`; ไม่ใช้ข้อความแจ้งเตือนแพ้ยาแบบหน้า Profile หรือเพิ่ม popup ADR ที่ native entry นี้ไม่ได้เรียก
- เมื่อไม่พบวันเกิด เว็บเว้นวันเกิด/อายุ ไม่จำลองบั๊ก native ที่ใช้วันปัจจุบันเป็นวันเกิด; เมื่อไม่มี HN ไม่ query ADR ของ HN ว่าง และไม่แสดงผลยืนยันว่าไม่แพ้ยา
- หน้าสถานะอ่าน `packagemaster` ทุกหอ/ทุกห้องยา รวม inactive ward, ยากลับบ้าน, Off/Hold, ที่ยังไม่ Checkout และที่ join prescription ไม่เจอ ตาม native **ไม่ใช้เงื่อนไข Screening หรือ Checkout มาแทน**
- รอบหน้าสถานะก่อน 08:00 เป็นวันก่อน 08:00 ถึงวันนี้ 07:59:00 หลัง 08:00 เป็นวันนี้ 08:00 ถึงวันถัดไป 07:59:00 ไม่มี date picker ตาม Windows; API รองรับวันที่/รอบที่ผ่านการตรวจสอบเพื่อคงบริบทขณะเลือกหอ
- ยอดหอคือ COUNT(DISTINCT prescriptionno); หัวใบแยกกลุ่มถึงค่า medtransferdatetime จริง จึงมีเลขใบซ้ำหลายเวลาหรือประเภท และจำนวนหัวใบอาจมากกว่ายอดใบไม่ซ้ำของหอได้

## การอ่านและข้อจำกัด

- API ทุกเส้นทางต้องมี session IPD แบบอ่านอย่างเดียว ใช้ parameter binding เท่านั้น ห้าม client ส่ง HN/AN/SQL/medtransferdatetime มากำหนดบริบท ADR ใช้ HN ที่ resolve จากซองเท่านั้น
- ถ้าเลขใบเดียวมี HN/AN หลายราย ปฏิเสธ Preview และแจ้งตรวจสอบเลขใบ แทนการผสมรายการและ demographic ต่างผู้ป่วย
- แยก error ออกจาก empty ล้างข้อมูลเดิมเมื่อเปลี่ยนใบ/รถเข็น/สถานะ และไม่มีการคงข้อมูลผู้ป่วยเก่าใต้ผลที่โหลดไม่สำเร็จ
- โหลดรถเข็นครั้งเดียวในหน้า ไม่โหลดซ้ำทุกครั้งที่ค้นใบ; ยอดหอเป็น query รวม ไม่ query ทีละหอ; เลือกหอครั้งแรกไม่ทำให้โหลดรายชื่อหอใหม่เพียงเพื่อ pin รอบ
- SQL ไม่ได้แก้ตาราง/index หรือข้อมูลโรงพยาบาล กิ่ง lookup มี batch รถเข็น/eligibility/ซอง แล้วอ่าน ADR รวมตาม HN หนึ่งครั้ง ไม่มี SQL ต่อรายการยา

- เทียบ visible/order/HeaderText จาก Windows Designer โดยตรง: **8/2/6 คอลัมน์ตรงครบ**
- ชุดทดสอบทั้งหมด **193 กรณีผ่าน** รวม 8 กรณีใหม่: รอบก่อน/หลัง 08:00/วันอธิกสุรทิน/รอบคงที่, SQL ไม่เพิ่มเงื่อนไขผิดหน้า, ซองซ้ำ/0/สิทธิ์/เตียง, guard/แยกผู้ป่วย, ADR native, parameter scope, คอลัมน์/รูปแบบเลขใบ และ API authentication/validation/empty/error/ห้าม writes ใช้ DB stub ไม่เปิด MySQL

- Browser ใช้ component จริงกับ adapter สมมติ: ทางเข้าจากเมนู Check Out, ค่าเริ่มต้น/รถเข็น/เลขใบธรรมดาและ AN|เลขใบ/เตือน Checkout/บรรจุแล้ว/empty/error/retry/ล้างฟอร์ม/วันเกิดไม่มีข้อมูล/สองสถานะ/เลือกหอโดยไม่โหลดหอซ้ำ/ประเภท 1/ประเภท NULL/หัวใบหลายเวลา ผ่าน ไม่พบ console error และจำนวนคำขอเขียนข้อมูลเป็น 0
- Production build และ ESLint เฉพาะไฟล์ที่แก้ผ่าน ภาพใช้ข้อมูลสมมติทั้งหมด ไม่ได้เปิด Windows เทียบภาพสดทุกสถานะ ไม่เรียก MySQL หรือ hospital API ไม่มี commit/push ลบ fixture/probe ชั่วคราวหลังตรวจ
