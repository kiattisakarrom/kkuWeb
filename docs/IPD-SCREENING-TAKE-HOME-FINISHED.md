# Screening — ยากลับบ้านจัดแล้ว (ดูข้อมูล)

ตรวจ 18 ตุลาคม 2026 เทียบ `ucScreenningMain.btnTakeHomeFinished_Click`, `ucScreenTakeHome.vb`/Designer, `clsPrescription.getgroupWard/getPresHeader` และ `clspackagemaster.getForgenorder`

## หน้าจอและข้อมูล

เปิดปุ่ม **ยากลับบ้านจัดแล้ว** (`mode=take-home-finished`) ในโครง Screening เดิม ใช้สามตาราง: วอร์ด → หัวใบ → แถวยาที่บันทึก เริ่ม **ทุกห้องยา** เพื่อแสดงทุกหอที่มีรายการเหมือน Windows ยังเลือกกรองห้องจริงจาก `ms_room`, วัน และค้น AN/HN/เลขใบข้ามวอร์ดได้ ไม่เปลี่ยนห้อง IPD ของ session — ดู [ผลแก้หอแสดงไม่ครบล่าสุด](IPD-TAKE-HOME-ALL-WARDS.md)

ใช้ `ordertype='1'` และ **genorderdatetime IS NOT NULL** ทุกระดับ แยกจากโหมดรอจัดที่ใช้ IS NULL ไม่ใช้คิว Stat/Continue แทน แสดงสถานะ “Screen แล้ว” และวันที่ gen ตาม native หัวใบพื้นเขียว (ใบที่เลือกพื้นฟ้า) คำว่าจัดแล้วในเมนูอิงสถานะ gen ของ Windows ไม่ใช้ยืนยันว่าผู้ป่วยรับหรือบริหารยาแล้ว

| ระดับ | เงื่อนไขตาม native นอกเหนือจาก type/gen | ปลายช่วงหลัง/ตรง 08:00 |
|---|---|---|
| วอร์ด | non-Stat: ISNULL(frequencycode,'') NOT IN S/E/STAT; ไม่ตัด Off/Hold หรือ inactive ward; นับ distinct เลขใบ | วันถัดไป 07:59:00 |
| หัวใบ | วอร์ดที่เลือกต้อง active; ไม่ตัด Stat/Off/Hold; group ตามวันสร้าง/เลขใบ/HN/AN/ชื่อ/วอร์ด/เตียง/type/ห้อง/วัน gen | วันเดียวกัน 23:59:00 |
| แถวยา | non-Stat และ voiddatetime IS NULL; ไม่ตัด Hold; ผูกใบ/ห้อง/วอร์ด/HN/AN ที่ตรวจบน server | วันถัดไป 07:59:59 |

ทุกระดับเริ่มวันที่เลือก 08:00 ก่อน 08:00 กรุงเทพฯ ถอยวันเริ่มหนึ่งวัน และจบวันที่เลือก 07:59:00 สำหรับยอด/หัวใบ หรือ 07:59:59 สำหรับยา ใช้ helper เดียวกับยากลับบ้านรอจัดที่มี `wardEnd/headerEnd/end` แยกกัน ส่ง workdate จาก server ให้คำขอลูกเพื่อ pin รอบ หน้าจอแสดงช่วงหัวใบเพิ่มเติม ไม่เปลี่ยนเป็นช่วงของ Stat/Continue

ยอดวอร์ดจึงอาจต่างจากจำนวนแถวหัวใบตาม source และหัวใบที่มีแต่ Stat/ยา Off อาจไม่มีแถวยาผ่านเงื่อนไข API ส่งหัวใบพร้อม items=[] ให้แสดงว่างได้ ไม่แจ้งเป็นใบหายหรือฐานข้อมูลล้มเหลว

## ขอบเขต viewer

- เลือกใบแล้ว recheck หัวใบใน mode/ห้อง/วัน/วอร์ดที่เลือกก่อนอ่านยา ใช้ HN/AN จากหัวใบ ปฏิเสธเมื่อเลขใบมีหลายตัวตน ไม่รับ HN/AN override
- ค่าเริ่มต้นทุกห้องไม่กรอง fromlocationname เหมือน native เมื่อเลือกห้องเฉพาะจึงเทียบ fromlocationname กับชื่อและรหัสจาก master แบบ exact ทุกระดับ
- แสดง dose/qty/หน่วย/วิธีใช้/ความถี่/เวลาและข้อความ/varymeal-varymealtime, Hold, print/send flags และเวลาส่งจัดที่บันทึก คงศูนย์และ null ตามข้อมูล ไม่จำลองจำนวนซอง JVM หรือแถวพิมพ์ รายละเอียดข้อแตกต่างเหมือน [ยากลับบ้านรอจัด](IPD-SCREENING-TAKE-HOME-WAIT.md)
- เปิดผู้ป่วยจาก AN/วอร์ดปัจจุบันที่ server ตรวจ และกลับคง mode/ห้อง/วัน/คำค้น/วอร์ดของใบ/เลขใบ/รอบ สลับรอจัด/จัดแล้วหรือเปลี่ยนตัวกรองล้าง selection/detail เก่า ยกเลิกคำขอค้าง
- ดูข้อมูลอย่างเดียว ไม่มีการจัด/ส่งเครื่อง/ยกเลิก/พิมพ์/Reprint หรือเปลี่ยนสถานะผ่าน mount, click, double-click ปุ่มเขียนยังปิดไว้
- ใช้ MSSQL `prescription`/master ตาม flow นี้ ไม่มี MySQL endpoint เพิ่มและไม่มีข้อมูลจำลองทดแทนข้อมูลจริงในหน้าใช้งาน

API GET `/api/ipd/screening/wards`, `/prescriptions`, `/prescriptions/:prescriptionno` ตรวจ JWT, ห้องจริงหรือ all, วัน/รอบ/คำค้น และ ward ที่จำเป็น รองรับ room=all เป็นค่าเริ่มต้น แต่ไม่รับ status/type ของ Screen All ทุก query ใช้ parameters และ pool ร่วม โหมดรอจัด/จัดแล้วใช้ SQL ชุดเดียวกันแต่มีเงื่อนไข mode/gen แยกชัดเจน
