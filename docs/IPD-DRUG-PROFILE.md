# Drug Profile แบบอ่าน — ปรับเทียบคอลัมน์ 19 ตุลาคม 2026

คงกรอบรายละเอียดผู้ป่วย เมนูและตัวกรองเดิม ปรับเฉพาะ Drug Profile ให้อ้างอิง `Dispense/frmDrugprofilectx.vb`, `.Designer.vb` และ `Dispense/cls/clsdrugprofilectx.vb` ไม่มีการสร้าง แก้ไข จ่ายยา หรือสั่งฮาร์ดแวร์

## คอลัมน์และแถวตาม Windows

- คอลัมน์ที่มองเห็น: **ลำดับ, ชื่อยา, เวลา, วันที่ 7 ช่อง** รูปแบบ `dd/MM/yyyy` เริ่มจากวันที่เริ่มค้นหา แม้ช่วงค้นหาสั้นหรือยาวกว่า 7 วัน
- ซ่อนรหัสยาและ timecode ตาม Designer: `deorderitemcode.Visible = False`, `dftimecode.Visible = False`; `GridViewStyleShowlist` ที่ตั้งให้ visible ไม่ได้ถูกเรียก
- ชื่อยาใช้ `orderitemname`, เวลาใช้ `frequencyTimedesc`; เก็บ `orderitemcode` และ `frequencyTime` ใน API ตาม query เดิม
- `showdrugprofile` เติมข้อความว่างทั้ง 7 ช่องวันที่ เว็บจึงเว้นว่างเช่นกัน ไม่มีจำนวน/หน่วย/Off/Hold หรือเครื่องหมายขีดมาเติมในช่องเหล่านี้
- ไม่เพิ่มคอลัมน์ใบสั่งยา วิธีใช้ แพทย์ สถานะ หรือ timestamp ที่ Windows ไม่แสดง และไม่ทำสี Off/Hold ซึ่ง `ApplyFormatting` ต้นฉบับไม่มีโค้ดทำงาน
- `CellPainting` ใน Windows แสดงชื่อยาซ้ำติดกันเฉพาะแถวแรก เว็บซ่อนเฉพาะข้อความชื่อซ้ำติดกันด้วยกฎเดียวกัน ยังเก็บลำดับ เวลา และจำนวนแถวครบ รวมแถวซ้ำทุก field
- แสดงทุกแถวของช่วงค้นหา ไม่แบ่งหรือกรองแถวตามสัปดาห์ ค่า `dpWeek` เก่าถูกละเลย และลบออกเมื่อกดค้นหาใหม่
- ช่วงที่ปลายปี 9999 หัววันที่เกินขอบเขตเว้นว่างเพื่อไม่สร้างวันซ้ำ/วันที่ผิด แต่ยังคง 7 ช่อง

## การอ่านข้อมูล

`GET /api/ipd/patients/:an/drug-profile?wardCode=...&orderdate=...&from=YYYY-MM-DD&to=YYYY-MM-DD`

ใช้ **MSSQL** `packagemasterctx` ตาม `Showprofileorderitem` เลือก 4 field ข้างต้น กรอง `an` และ `takedate BETWEEN` รวมวันเริ่มและสิ้นสุด ไม่มี GROUP BY, DISTINCT, ตัวกรองสถานะ หรือ ORDER BY เพิ่มจาก Windows ฐานข้อมูลจึงไม่ได้รับประกันลำดับแถวหากไม่มี ORDER BY เช่นเดียวกับต้นฉบับ

คง HN ที่ backend resolve เพิ่มเป็นเงื่อนไขตรวจเจ้าของ admission และคง JWT/current AN/ward validation ไม่รับ HN override ใช้ SQL parameters ตรวจวันที่จริง 1753–9999 และวันเริ่มไม่เกินสิ้นสุด

หนึ่ง query ต่อการค้นหา ลด field ที่อ่าน/ส่งจากเดิม ไม่มี query ต่อแถว ไม่มีการเปลี่ยน schema/index ไม่มี MySQL ในเส้นทางนี้ ข้อกำหนด [MySQL ภายในโรงพยาบาล](DATABASE-CONNECTIVITY.md) ยังใช้กับส่วนอื่น

คงฟอร์มวันเริ่ม/สิ้นสุด ปุ่มค้นหา โหลดใหม่ และสถานะกำลังโหลด/ผิดพลาด/ไม่มีรายการ เริ่มจากวันหน้าผู้ป่วยถึงอีก 6 วันตามเว็บเดิม การเพิ่มจำนวนรายวันที่เคยทำในเวอร์ชันก่อนถูกนำออกเพื่อให้ตรงกับ source Windows

## ผลตรวจรอบนี้

- ชุดทดสอบ backend 138 กรณีผ่าน รวม auth/scopes/ช่วงวันที่/ข้อผิดพลาดเดิม และปรับกรณีทดสอบ Drug Profile เป็นหัววันที่ 7 ช่อง ข้ามเดือน/ปี/leap day ชื่อซ้ำติดกัน ค่าว่าง และแถวที่อยู่นอก 7 วันแรก
- Frontend production build และ ESLint ไฟล์ที่แก้ผ่าน
- Browser ใช้ component และ hook จริงกับ API fixture ข้อมูลสมมติ: แสดง 5 แถวในช่วง 10 วันแม้ URL มี `dpWeek=1`; แถววันที่ 9/10 ไม่ถูกตัด ชื่อซ้ำและช่องวันที่ว่างครบ
- เปลี่ยนเป็นช่วง 1 วัน: เหลือ 2 แถวแต่ยังมีหัววันที่ 7 ช่อง; ช่วงกลับด้านถูกปฏิเสธ; ไม่มีรายการแสดง 0; ฐานผิดพลาดแสดงข้อความ error และยอดเป็นขีด ไม่แสดงเป็นไม่มีรายการ; เปลี่ยนช่วงกลับมาโหลดได้
- การอ่าน MSSQL จริงรอบนี้จบด้วย `ETIMEOUT` จึงยังไม่รับรอง parity กรณีมีรายการจริงกับ Windows ที่กำลังเปิดใช้งาน หลักฐานรอบนี้เป็นการเทียบ source และทดสอบหน้าจอด้วยข้อมูลสมมติ

ผลตรวจ schema/ข้อมูลว่างจริงจากรอบก่อนยังเป็นหลักฐานแยกต่างหาก: `takedate` เป็น SQL `date` เคยอ่านช่วงที่ไม่มีรายการสำเร็จ แต่ยังต้องเทียบตัวอย่างจริงที่มีข้อมูลเมื่อ MSSQL ตอบกลับได้
